# 3D描画（src/components/3d）

- `SaunaScene` のDOM `data-*` 属性に初回ロード時間、描画数、初期180フレームの間隔を記録する。Reactの毎フレーム更新は行わず、DOM属性も値が変わったときだけ書き込む。
- GLB読み込み後の材質拡張（葉・ノイズ色・画像ランプ・林のカード）と影・水形状の非表示は `modelMaterials.ts` の `prepareModel()`、解放は `disposeTree()`。
- 水は元GLBの閉じた水形状を非表示にし、`waterEffects.ts` の境界付き水面・波紋・注水に置き換える。元の水は透明（透過1・IOR 1.333）なので、水面はタイルに色を足さず、Fresnel反射（F0=0.02）でトーンマッピングしない空の色（`scene.background` を共有）だけを重ねる。水面は影を投射しない（内壁まで暗くなるため）。動きを減らす設定では波紋・注水の時間更新を止める。最適化は未完了。
- 昼／夕暮れ／自動は `lighting.ts` で管理。元Cyclesに合わせて霧はなく、空は元画像の表示色の単色（昼 `#4f616c`・夕暮れ `#283d54`）、カメラの描画距離は250m（地面は原点から100m）。`sui-lighting-mode` に保存し、3Dモデルを再ロードせずに反映する。自動は各周回でサウナ=昼、水風呂=中間、外気浴=夕暮れ。ステージ変更時は暗転中に適用し、手動変更は補間する。動きを減らす設定では即時適用。
- トーンマッピングは元blendと同じAgX（look None）。three内蔵の `AgXToneMapping` はBlender 4.xのAgX（E-Gamut・57³ LUT）と別の曲線で、同じ線形入力を平均約4 L*明るく表示するため、`agx.ts` がAgX関数を差し替える（行列・対数・32点の曲線・行列・2.4乗・行列。定数は `scripts/fit_blender_agx.py` でBlenderのOCIOに当てはめ、表示値の誤差平均0.001）。露出はBlenderの昼0.15・ブルーアワー0.55段を `2^EV` で使う。日光（向きは両シーン共通、強さは昼3.2・夕暮れ0.045の青。元の日光は光沢に不可視なので、`lights_fragment_begin` の平行光源ループで鏡面反射を戻して拡散だけにする）、寝椅子上のスポット光（元の `V9 lounge patch of sunlight`、950W円盤→軸上 `950/π` cd、夕暮れは0）、ブルーアワーの暖色灯5灯（`V10 lounge dusk fill` 42W・`V10 path grazing light 1/4/7` 各8W・`V10 specimen uplight` 35W、軸上 `P/π` cd・寝椅子上とモミジ下の2灯に影あり・昼は0）、サウナ室の面光源6灯（下記）は元blendの値。スポット光はすべて元の円盤光源の代わりで、90度の円錐とpenumbra 1のまま `lights_pars_begin` の減衰を smoothstep から線形へ差し替え、正確な余弦配光にする（`SPOT_COSINE`）。半球光はない。空・ブラウザで描かない面光源（Sky softbox・Sunlit courtyard・行灯など）・全光源の間接光は、元blendから焼き込んだ照度プローブ（下記 `irradiance.ts`）で与え、合わせ込みの係数はない。照明の確認はCycles同視点との比較（`scripts/cycles_tone_stats.py`、CIELABの明暗分布と彩度）で行う。夕暮れは06に加え、`scripts/blender_bluehour_reference.py` のブルーアワー参照画像（02〜05・07）とも比較する。照明を変えたら全周撮影の後にこのスクリプトで比較し、進捗記録へ値を残す。ブラウザで再現しないノイズ→ランプの基本色（漆喰・リネン・樹皮・砂利）は書き出し時にノイズ平均0.5のランプ色の単色にする（`procedural_flat_color`）。
- サウナ室の照明は `interiorLights.ts`。元の6灯（ベンチ下2・天井・壁・蒸気の逆光・背もたれ）を `RectAreaLight`（円盤は等面積の正方形、壁の灯は室内に出る帯だけ）で放射輝度 `P/(π·A)` にし、影がない分を光源ごとの見え率（02の視点でCycles直接光÷Web直接光）で掛ける。元の光源は光沢に映らないため拡散成分だけを、受光面の地平線で切り取った厳密な形状係数で計算する（LTCテーブルは読み込まない）。`lights_fragment_begin` を差し替え、室内の箱（ガラス面まで）の外では6灯を評価しない。同じ箱の判定で照度プローブの室内グリッドを選ぶ。Three.js更新時は `interiorLights.test.ts`・`agx.test.ts` と全周撮影で確認する。
- 間接光は `irradiance.ts`。`scripts/bake_irradiance_probes.py` が元blendの昼・ブルーアワーをCyclesで焼き込んだL2球面調和（SH）の照度プローブ（`public/models/irradiance.json`・`irradiance.bin`、float16）を、室内（0.5m・室内の箱の中の画素だけ）・中庭（1m）・外周（3m、中庭グリッドの端1.5mで混合）の3グリッドのRGBA半精度3Dテクスチャ（three の LightProbeGrid と同じ詰め方・余白付き）にし、`lights_pars_begin`・`lights_fragment_begin` に画素ごとの評価を足す。three の LightProbeGrid は物体ごとに1グリッドを選ぶが、モデルは材質ごとに結合されて室内と中庭にまたがるため使わない。昼夕は `suiIrradianceEvening` で係数を混ぜる。プローブには空・ブラウザで描かない面光源の直接光・全光源の間接光が入り、ブラウザで描く光源（日光・V9・室内6灯・夕暮れの暖色灯5灯）の直接光は入らない。GLBの `MeshStandardMaterial` に `SUI_IRRADIANCE` を定義し、uniformは全材質で共有する。読み込みはGLBと並行し、形式の不一致は3Dの読み込み失敗として扱う。Three.js更新時は `irradiance.test.ts` と全周撮影で確認する。`data-irradiance-probes`・`data-irradiance-materials` に数を記録する。
- 3D画質は `quality.ts` の軽量／標準／高精細。`sui-quality` に保存し既定は標準。DPR上限は1／1.5／2、日光・V9スポット光・夕暮れの寝椅子上とモミジ下の照明の影は無効／1024／2048px。夕暮れの暖色灯5灯は全画素のシェーダーに加わるため、軽量では非表示にする（ライト数の変更はシェーダー再コンパイルを伴うので、画質変更時だけ切り替える）。モデルを保持したまま反映し、画質変更時は180フレームの計測をリセットする。
- 影を描くのは日光・V9スポット光・`V10 lounge dusk fill`・`V10 specimen uplight`（室内の面光源・通路の暖色灯3灯は影なし）。Cyclesのガラスは直接光を通さないため、ガラスは影を投射する（受けない）。両面材質の裏面は反転した法線で陰影付けされるため、`softShadows.ts` が `shadowmap_vertex` で影の法線オフセット（normalBias）を頂点ごとに視点側へ反転する（下向きの遠景地形が自分の影に入っていた）。水・蒸気は影を投射しない。影を描く4灯は動かないため、影解像度の変更時だけシャドウマップを更新する（昼夕の補間中も再描画しない）。軽量切り替え・シーン解放時に4灯の影のGPUリソースを解放する。これはベイクではない。
- 影のぼけは `softShadows.ts` のPCSS。three 0.186の `shadowmap_pars_fragment` のBasicShadowMap分岐を差し替え（レンダラーはBasicShadowMap）、遮蔽物との深度差×係数kで半影幅を決める。kは `shadow.radius` で渡し、日光は角直径0.085rad（`directionalPenumbra`）、V9は直径1.25m、夕暮れの寝椅子灯は直径2m・モミジ灯は直径0.6m（`spotPenumbra`）から計算する。日光の影の範囲は±30m（範囲外は影がつかない）。Three.js更新時は `softShadows.test.ts` と全周撮影で確認する。
- `SaunaScene` は描画数・三角形数・テクスチャ数・ジオメトリ数もDOM属性へ記録。描画数は最新フレームの値なので、照明補間中の影パスを含む値と、安定後の値を区別する。
- 蒸気の座標更新は `steam.ts`。動きを減らす設定では全軸を固定し、濃淡と6秒の表示時間は維持する。`scene-viewport.e2e.ts` は390×844の操作・キーボード見回し・844×390とのリサイズ・同一canvas保持を検証。Chromeの画面サイズとメディア設定のエミュレーションであり、モバイル実機の検証ではない。
- 見回しは `lookControls.ts`。終了は操作開始時のpointerIdに一致する場合だけ処理し、別の指の終了・キャンセル・キャプチャ喪失で中断しない。`scene-touch.e2e.ts` はChromeのCDPタッチ入力でスワイプ、2本目の指を離した後の操作継続、キャンセル後の再操作、タップでのUI復帰・ステージ一巡・2D復帰を検証する。モバイル実機やSafariの検証ではない。
- 林のカードは `leafCluster.ts`。20枚の菱形の葉のマスクを決定的に生成し（カードの半分を覆う）、アルファテストの被覆率を保つよう各ミップを自前で補正、`alphaToCoverage` で描く。マスクは枚数ごとに1枚を共有し、材質とともに解放する。`data-leaf-cluster-materials` に対象材質数を記録する。
- 葉は `foliage.ts`。名前が leaf／foliage／fern の `MeshStandardMaterial`（落ち葉 `leaves`・苔・樹皮は対象外）を両面にするだけで、裏面へ光を透過させない。元の葉はTranslucentもTransmissionもなくSubsurface Weight 0〜0.08で、Cyclesで背面から照らすと正面の0.1%未満しか返さない（以前の0.6倍の透過は元データに根拠がなく、林・草を明るく鮮やかにしていた）。視点側の面は照度プローブが照らす。`data-foliage-materials` に対象材質数を記録する。
- 地面の苔・シダの色は `noiseColor.ts`。`export_web_glb.py` が元材質のワールド／オブジェクト座標fBmノイズ→線形カラーランプの設定を材質 `extras.suiNoiseColor` に記録し、BlenderのPerlin（Jenkinsハッシュ）とfBmのGLSL移植で画素ごとに評価する。画素より細かいオクターブは平均へフェード。バンプは省略。Three.jsの `common`・`project_vertex`・`color_fragment` チャンクに依存。移植は `noise-color.e2e.ts` がBlender基準値（`scripts/blender_noise_reference.py` → `e2e/fixtures/blender-noise.json`）と比較する。名前による苔・シダの単色上書きはBase Colorが接続された材質だけ。
- 石・布・木材の色は `imageRamp.ts`。`export_web_glb.py` の `base_color_image_ramp()` が「画像→RGBのBW化→線形ランプ × Object Info Randomのランプ（→一定色へ混合）」を材質 `extras.suiImageRamp` に記録し、結合前のオブジェクトごとの乱数を色属性 `SuiObjectRandom`→`COLOR_0` で渡す（名前seedの一様乱数でCyclesの値ではない）。濡れ跡のノイズは省略。輝度係数はBlenderのOCIO設定の `luma`。Three.jsの `common`・`map_fragment`・`color_fragment` チャンクに依存。`data-image-ramp-materials` に対象材質数を記録する。書き出しはUVの最下位ビットが実行ごとに揺らぐため、GLBのハッシュは再実行で変わる。
- `SaunaScene` 内で `meshoptimizer/decoder` をGLTFLoaderへ渡す。WASMは3Dの遅延JS内に含まれ、CDNや別のデコーダーURLへ依存しない。圧縮ストリームの破損時も2Dを継続し、手動再試行できることを `scene-lifecycle.e2e.ts` で検証する。圧縮は転送量を減らすもので、描画三角形数やGPUメモリは減らさない。
