# 3D描画（src/components/3d）

- `SaunaScene` のDOM `data-*` 属性に初回ロード時間、描画数、初期180フレームの間隔（`frameMetrics.ts`）を記録する。シーンの取得（`sauna.scene.json`・GLB・プローブ）は `sceneAssets.ts`。Reactの毎フレーム更新は行わず、DOM属性も値が変わったときだけ書き込む。
- GLB読み込み後の材質拡張（葉・ノイズ色・画像ランプ・林のカード）と影・水形状の非表示は `modelMaterials.ts` の `prepareModel()`、解放は `disposeTree()`。
- 水は元GLBの閉じた水形状を非表示にし、`waterEffects.ts` の境界付き水面・波紋・注水に置き換える。元の水は透明（透過1・IOR 1.333）なので、水面はタイルに色を足さず、Fresnel反射（F0=0.02）で映り込みだけを重ねる：平面反射（下記 `planarReflection.ts`）があればその鏡像、なければ反射プローブ（下記 `reflection.ts`、粗さ0.018）。水面の高さはシーン定義の0.765m（元の水形状の上面の平均）。法線は元の水形状の波を当てはめた式（注水口中心の同心円波＋平面波、R² 0.986、`WAVES`）の解析的な勾配で、毛管重力波の位相速度で外へ進める（動きを減らす設定では元の形のまま）。元材質のバンプ（傾き約0.001）は水面の描画では省略し、水の底面の部分反射の経路だけに使う（下記 `waterBottom.ts`）。水面は影を投射しない（内壁まで暗くなるため）。水面下（`interiorLights.ts` の `WATER_BOX`、タイルと下の石板まで含むよう水形状より広い）には日光・スポット光を直接当てない（`lighting.ts` の `DRY_ONLY`。床のV9・寝椅子灯の鏡面だけは `waterBottom.ts` が足す）：元の日光は透過レイに不可視で影レイは水面で止まり、V9・夕暮れの暖色灯は屈折経路だけで届き、その光は水中プローブに入っている。動きを減らす設定では波紋・注水の時間更新を止める。最適化は未完了。
- 水越しの像は `refraction.ts`。水面を平面（シーン定義の水面の高さ）とみなし、`WATER_BOX` のxz内で水面より下の頂点を、カメラごとにスネルの法則（IOR 1.333、二分法16回）で解いた像（点の真上、見かけの深さ `b·cosθ1/(n·cosθ2)`）へ `project_vertex` の後で持ち上げる。照明・プローブ・影は真の位置のまま（影のパスは別の深度材質）。水中に0.3mより長い辺を持つメッシュは読み込み時に水面と0.1m格子の平面で分割する（共有辺を同じ点で切るので割れない、`sliceUnderwater`）。水中の三角形を持つ材質だけに `SUI_REFRACTION`（値は水面の高さ）を定義する。水越しの面の色には元の水の透過色と体積吸収（屈折経路長、頂点で計算して補間）を `opaque_fragment` の後で掛ける。屈折は平面のままで波による揺らぎはない。`data-refraction-materials`・`data-refraction-triangles` に数を記録する。
- 水の側面の全反射も `refraction.ts`（`addSideImages()`）。元の水形状（`WATER_VOLUME`、側面・底はフラット、外は空気）を平らな水面で屈折した視線は |d.y|≥0.66 なので底では全反射せず、側面では各軸1回まで全反射する。水中の三角形だけ（属性バッファを共有しインデックスだけ新規）を側面4面・角4つで鏡映した8つの複製を、鏡映した点の像の位置へ同じ頂点屈折で描く。照明・プローブ・影は真の位置のままで、視線方向だけ鏡映する（`SUI_SIDE_IMAGE`、1回の鏡映は巻き方向が逆なので `SUI_SIDE_FLIPPED` で面の向きと法線を戻す）。全水中フラグメントは `clipping_planes_fragment` の先頭で画素の視線を波の法線（`waterEffects.ts` の `WAVE_NORMAL`、時刻は水面と共有）で屈折させて箱を追い、全反射した側面の組と違う像・全反射した側面の裏の点を `discard` する（`keepsImage`／`sidePath`／`trueWeight` がTSの参照実装）。像の位置は平らな水面のまま。最初に当たる側面では必ず反射する経路とし、透過する視線（入射角41.4〜48.6°）はFresnel反射率Rで部分反射させる：その側面の裏5cm以内（`SIDE_WALL_LAYER`、内壁は6mm裏の1層だけ）の面を重み1−Rのアルファで像の上にブレンドし、それより奥は捨てる。2面目は全反射か透過の二値。複製はレイヤー2（水面の鏡像パスに写らない）・影なし。判定は各複製の子の深度だけのメッシュ（`renderOrder` 1、同じ頂点シェーダで断片は判定だけの短いプログラム、手前の縁石で深度により捨てる）が行い、複製（`renderOrder` 1.5、`SUI_SIDE_TESTED` で判定と `discard` を省く）は `EqualDepth`・深度書き込みなしで残った画素だけを塗る。複製自身で捨てるより水風呂が0.97倍になった（捨てる断片も床のシェーダのレジスタで起動すること、`discard` がAppleの隠面除去を止めることが理由と考えられるが、切り分けていない。`docs/3d-qa/side-image-depth/`）。内壁は像の後に描く必要があるため、裏の層に角を持つ水中の三角形だけを属性共有の別メッシュ（`renderOrder` 2、ブレンドする材質の複製）へ移す。元メッシュごと後回しにすると床のタイルの下を深度で早期に捨てられず、GPU時間が水風呂で+25%前後になった。`material.clone()` は `onBeforeCompile`・`customProgramCacheKey` を引き継がないため、複製には両方を元に委ねる形で設定する（キーがないとコースティクスの有無など別材質のプログラムを取り違える）。`update(camera)` がカメラが水面下・水面が視野外・カメラがその側面の外側（屈折しても水平方向を保つので反射しない）の複製を隠す。`data-side-image-meshes`・`data-side-image-triangles`・`data-side-images-shown` に数を記録する。
- 水面の鏡像は `planarReflection.ts`。水面の高さで鏡映したカメラ（x反転で回転に戻す）から、近クリップ面を水面に置き換えた斜め投影（Lengyel法）で水面より上だけを半精度ターゲット（4倍MSAA、線形）へ描く。視錐台は水面の画面上の範囲＋余白0.08（NDC）に切り抜き、ターゲットの左下の同じ画素密度の部分に描く（`suiMirrorLimit` でサンプルを制限）。カメラ行列・解像度・呼び出し側の状態（照明の昼夕、画質）が同じフレームは描き直さない（映り込む注水の動きは視点が止まっている間は止まる）。蒸気はストーブ脇の室内にあり鏡像に写らないため、レイヤー1に置いて主カメラだけが描く（ロウリュ中に毎フレーム鏡像を描き直さない）。水面が視野外・カメラが水面以下・軽量画質・HDR出力なしの端末では描かず、水面は反射プローブを使う。軽量ではターゲットを解放する。鏡像のカメラだけがレイヤー3（`MIRROR_LAYER`）も描く。水面は鏡像を、反射方向に0.6m進んだ点の投影位置で参照し、波で像をずらす。`data-mirror-calls`・`data-mirror-triangles`（最後に描いた鏡像パスの値）・`data-mirror-size` を記録する。
- 光沢にだけ見える面光源は `glossyLights.ts`。元blendでカメラに不可視・光沢に可視の面光源13灯（`V7 water reflection soft strip`・V9・夕暮れの暖色灯・V8・デッキ端など、すべてspread 180°）を元の形・位置・向きの発光面（円盤は面積を保つ32角形、表は光が出る側）として1メッシュにまとめ、放射輝度 `P·color/(π·A)` の昼・ブルーアワーの値を頂点に持たせて「1−昼の重み」で混ぜる（夜はブルーアワーと同じ出力）。レイヤー3（`MIRROR_LAYER`）に置き、水面の鏡像にだけ写す（主カメラ・影のパスには写らない）。水面はブラウザの光源を受けず、鏡像があるときは反射プローブも使わないため、これがないとV7の帯・V9・寝椅子灯の形が水面に出ない。鏡像がない端末では従来どおりプローブだけ。
- 水の底面の部分反射は `waterBottom.ts`。元の水形状の底面（y=0.215）はタイルより1.3cm上で間は空気のため、床はその水→空気の境界越しに見える。床（水の箱のxz＋裏の内壁の足元5cm、底面より下）を描く材質に `SUI_WATER_BOTTOM` を定義し、`opaque_fragment` の水越しの色（`refraction.ts` の `VIEW_TINT`）の前で `(1−R)·透過色·床 + R·上へ反射した放射輝度` にする。視線は `refraction.ts` が屈折させた `suiWetView`（鏡映像では鏡映した方向）。反射した視線は側面で反射し（全反射／Fresnel、残りは壁へ抜ける）、水面で波の法線について屈折して出て、反射プローブ（粗さ0.018）と、透過レイに見える光沢専用の面光源（V9・`V10 lounge dusk fill`、元の形と交差、縁石の上面1.035mより低く側面を越える光線は届かない）を見る。`V7 water reflection soft strip` は元blendで透過レイに不可視なので含めず、プローブが含むそのぼけた分はプール中央上から見たL2係数（`sourceSH`）を引く。水面で下へ反射する分は床の色で代用。タイル自身の光沢による光源のぼけた像は省略（反射プローブだけ）。床にはV9・`V10 lounge dusk fill` の鏡面だけを足す（`suiWetSpecular`、`lighting.ts` のスポット光ループで `DRY_ONLY` の代わりに呼ぶ）：床は水の底面の下の空気層にあり、平らな水面なら光は空気中の向きのまま届き、視線は底面で屈折して出る（平行な2面）。光の経路に (1−R)²・透過色2回・吸収を掛け、円盤の大きさは GGX の α'²=α²+0.25(r/d)² で広げる（円盤上の積分と±10%以内）。元blendではこの経路が間接光クランプ10とロシアンルーレットで大きく削られる（水なしの0.138倍、クランプ100で1.09倍）ため、標本値を `WET_SAMPLE_WEIGHT` から見積もってV9を0.17倍にする（寝椅子灯はクランプに掛からない）。`scripts/diagnose_water_floor_highlight.py` で測る。影は屈折した経路が水面を出る点で引く：水中の床の頂点だけ `shadowmap_vertex` のスポット光の影座標を、`spotLightMatrix` から求めた光源へ向かう空気中の向きのまま空気層・水を通って水面に出た点（`wetExitRun`）に置き換え、出口が水の箱の外なら届かない（`suiWetSpecular`）。床のハイライトには、灯りから遠い側のx・zの側面で反射して届く経路も足す（`suiWetImage`、TS参照は `wetImage`）：床の点を側面で鏡映した像から灯りへの屈折経路の空気中の向きをNewton法4回で解き（像は灯りから遠く直線の向きでは上を向きすぎる）、側面より先に水面を出る・箱の外で出る・その先で縁石より低く箱を出る経路は届かない。色は像の点の `getSpotLightInfo` に側面のFresnel反射率（多くは全反射）を掛け、向きを折り返す。影マップは引かない（ループ内で灯り×軸ごとにPCSSを展開すると対象外のサウナまで約1割遅くなり、この視点では値もほぼ1だった）。スポット光のループでは灯りの番号だけを記録し、ループの後で消灯中でない灯りについて1回だけ計算する。夕暮れの斑の手前半分（真っすぐ見た床）は、Cyclesでは側面に映った寝椅子灯だけで光沢を得ており、これがないとタイル光沢が0だった（`docs/3d-qa/water-gloss-capture/`、水風呂のGPU時間約+5%）。水中の判定は法線オフセット前の位置で行う（オフセット1.5cmでタイル上面が底面より上に出る）。床からの直線の影では奥の縁石が寝椅子灯を隠し、斑の中のハイライトの85%が消えていた（Cyclesでは斑の光の約2割がこのタイル自身の光沢で、目地が透け中央が明るい。`docs/3d-qa/water-bottom-gloss/`）。この経路（水面への入射・底面での反射・水面からの出射）には元材質のバンプ（`waterEffects.ts` の `WATER_BUMP`・`WATER_BUMP_GLSL`：Object座標のノイズFac、Scale 55・Detail 2、Distance 0.0006・Strength 0.08をBlenderのBumpノードと同じ式で、高さの勾配は水平面上の0.4mmの前進差分、画素より細かいオクターブは `sui_fbm` の足跡で弱める）を波の法線に重ねる。バンプの評価（ノイズ3回×3か所）は重いので、まずバンプなしで追い、底面の法線を4方向へ `BUMP_REACH`（0.006）傾けた安い追跡のどれかで見える灯りが変わる画素（灯りの縁・縁石・側面で経路が変わる境目の近く）だけ、灯りの項をバンプ付きで追い直す（プローブの項はバンプなしのまま）。傾きは小さい（実効値0.0013、Cyclesの法線パスと一致）が、数m先の灯りへ向かう視線を振るため、寝椅子灯・V9の像の縁がCyclesと同じくほつれる（バンプを外したCyclesは縁が滑らか。最も効くのは傾きの2倍で振れる底面の反射）。ほつれの位相はCyclesと画素単位では一致しない（水面の高さを平面で近似し、波が動く）。水越しの床の像と鏡映像の入射はバンプなしのまま。`FBM_GLSL` は `SUI_FBM` で多重定義を防ぐ。`scripts/diagnose_water_bump.py`・`summarize_water_bump.py`、記録は `docs/3d-qa/water-bottom-bump/`。`bottomExit`／`upwardExit`／`clearsRim`／`lightCoverage` がTSの参照実装（バンプなし）。`data-water-bottom-materials` に数を記録する。4本の傾けた追跡はDPR 1.5の水風呂で約1msかかるが、これはコードの存在による費用で、保守的な事前判定で追跡する画素を減らしても下がらなかった（`docs/3d-qa/tilt-cost/`）。床のハイライトの6か所の `suiWetSpecular` を1つのループの1回の呼び出しにまとめると、水風呂で1.01〜1.02倍（展開できない上限では1.10〜1.13倍）遅かった（`docs/3d-qa/wet-single-call/`）。GLSLの構造体には三項演算子を使わない（WebGLでコンパイルに失敗し、その材質が描かれなくなる）。
- 水中の疑似コースティクスは `caustics.ts`。元の `V10 | submerged light` 2材質の発光強度（Voronoiの辺距離×ノイズ×水面下の箱）を、BlenderのハッシュとVoronoi・ノイズの色のGLSL移植で画素ごとに評価し `emissivemap_fragment` の後に足す（書き出しは接続された発光強度を落とす）。Perlin fBmは `noiseColor.ts` の `FBM_GLSL` を共用し、既に定義済みなら重ねない。移植は `caustics.e2e.ts` がBlender基準値（`scripts/blender_caustic_reference.py` → `e2e/fixtures/blender-caustic.json`）と照合する。`data-caustic-materials` に数を記録する。模様は静的なので、届き得るVoronoiセル（箱・歪み・両隣を含む19×21×11）の特徴点は `causticCells()` がGPUと同じJenkinsハッシュでCPU計算した3Dテクスチャ（`SUI_CAUSTIC_CELLS`）から読む（水風呂のDPR 1.5で約2.5ms短縮、`docs/3d-qa/caustic-cells/`）。`caustics.e2e.ts` はハッシュ版との完全一致も検査する。範囲外のハッシュへの分岐は置かない（実行されないコードも費用になる）。1周目のハッシュを配列に残す案はレジスタ圧迫で遅かった。歪み・濃淡のPerlinの格子ハッシュを同じテクスチャ（RGBA32UI、8角の勾配番号を32bitに詰める）から読む案は、水風呂で約0.2msしか減らず不採用（`docs/3d-qa/noise-lattice/`）。水底の材質はテクスチャユニットに空きがない（16）。箱を広げるときは `CAUSTIC_BOX` も直す。
- 昼／夕暮れ／夜／自動は `lighting.ts` で管理。時間帯は1つの値 t（0=昼 `SUI • Daylight`、1=ブルーアワー、2=夜 `SUI • Night`）で、隣り合う2シーンだけを混ぜる（`sceneWeights`）。夜のシーン（`scripts/build_night_scene.py`）はブルーアワーの複製で、日光を同じ向きの月（0.1・淡い青・角直径0.0093rad）に、空の補助光（Sky softbox・Sunlit courtyard）を弱い青に変えただけなので、ブラウザで描く暖色灯5灯・光沢専用の面光源・V9（0）はブルーアワーと同じ値を「1−昼の重み」で使い、夜の重みで変わるのはプローブ・空・日光（月）・露出だけ。元Cyclesに合わせて霧はなく、空は下記 `sky.ts`、カメラの描画距離は250m（地面は原点から100m）。`sui-lighting-mode` に保存し、3Dモデルを再ロードせずに反映する。自動は入室からの実時間で進み、0〜12分は昼、12〜15分で夕暮れへ、27分まで夕暮れ、27〜30分で夜へ移り、以後は夜のまま（`timeOfDay`、`AUTO_SECONDS_PER_SCENE`・`AUTO_TRANSITION_SECONDS`）。昼と夕暮れの中間は昼の日光の影と夕暮れの灯・2組のプローブを同時に描くため最も重く（標準画質のGPU時間でサウナ昼38ms・中間68ms・夕50ms）、各シーンを保持して中間を3分に限る。ステージには依存しない。入室時刻は `useSaunaSession` の `enteredAt`（`Date.now()`）で、2D／3Dの切り替えや再マウント後も同じ時間帯から続く（未指定ならシーンのマウント時刻）。タブが裏にある間も時計は進み、戻ると補間で追いつく。時刻は毎フレーム動くので、鏡像の再描画キーは時間帯を0.002刻み（移り変わり中の約0.36秒）に丸める。ステージ変更時は暗転中に即時適用し、手動変更は補間する（昼↔夜は夕暮れを経由する）。現在の値は `data-time-of-day`。動きを減らす設定では即時適用。
- 深度だけのプリパスは `depthPrepass.ts`。フレームのGPU時間はほぼすべて画素の計算で、材質ごとに結合したメッシュは手前からの並べ替えが効かず、サウナでは1画素あたり約4.7回計算していた（ANGLE MetalではAppleのHSRも効いていなかった）。不透明な面のメッシュに、形状を共有する深度だけの子メッシュ（`colorWrite: false`・元の面の向き・polygonOffset 1,1、`PREPASS_LAYER` 4）を加え、`hdrOutput.ts` がそのレイヤーだけを先に描いてから深度を消さずに通常の描画を重ねる。子なので変換・表示は元に従う。対象外は半透明・合成・`ShaderMaterial`・既定以外のレイヤー・インスタンス等（`takesPrepassDepth`）。林のカード（アルファマップ＋アルファテスト＋alpha-to-coverage、`cutoutOf`。`map`・頂点色・alphaHash・屈折を持つ材質は対象外）は、照明パスのalpha-to-coverageが全サンプルを覆う画素（`leafCluster.ts` の `suiLeafCoverage` が1）だけ深度を書く材質を材質ごとに作る：照明パスが一部のサンプルしか覆わない縁で深度を書くと、奥の面のそのサンプルが欠ける。水中の `SUI_REFRACTION` 材質は `refraction.ts` の `refractedDepthMaterial`（頂点段にだけ定義を入れて同じ屈折位置に描き、照明パスが `discard` し得る「水の箱の中・水面下・水の体積の外」では1mm広げて深度を書かない）を使う。庭も読み込み後に加える。共有する形状は `disposeTree` が1回だけ解放する。画像は変更前と全画素一致、GPU時間はサウナ約−5割・外気浴−4〜6割・水風呂−2割（`docs/3d-qa/depth-prepass/`）、水中の材質を加えてさらに水風呂約−3割・サウナ−2〜5割（`docs/3d-qa/underwater-prepass/`）。林のカードを加えて水風呂の夜0.43倍・夕暮れ約14ms（`docs/3d-qa/woodland-cards/`、マスクと合わせた値）。鏡像パスには入れていない。`data-prepass-meshes` に数を記録する。新しい不透明な材質の頂点段で位置を変えるときは、プリパスの対象から外すか同じ位置を出す深度材質にする（ずれると通常の描画が深度で欠ける）。
- 影の半解像度マスクは `shadowMask.ts`。夕暮れ・夜のGPU時間の約75〜85%がPCSSで、費用は画素数×参照回数に比例した（`docs/3d-qa/light-shadow-cost/`）。不透明で影を受ける面（`takesPrepassDepth` かつ `MeshStandardMaterial`）に、形状を共有する子メッシュ（`SHADOW_MASK_LAYER` 5、`lights: true` の `ShaderMaterial`）を加え、描画バッファの半分の解像度のfloatターゲットへ、深度プリパスの子を先に描いてから日光＋影付きスポット光6灯の影の係数を評価する（光に背を向けた面は頂点法線で−0.25未満のとき省略）。係数は8bitずつ3つを1チャンネルに詰め（2²⁴未満でfloat32に正確。復元は `round`、+0.5は2²⁴−1を2²⁴に丸めて全灯が0になった）、残る2枠に頂点法線（八面体符号化）、アルファにビュー深度を書く（影を落とす灯は7灯まで、超えれば `#error`）。元の材質には `SUI_SHADOW_MASK` を定義し、`lights_fragment_begin` の先頭で近傍4テクセルのうち深度（許容は深度の0.2%＋画面上の深度勾配×1.25テクセル）と法線（内積0.9以上）が自分の面に合うものを双線形で補間する。合うものがない画素（輪郭・溝・半解像度より細い部分）は影マップを1回だけ引く硬い影（`suiHardShadow`）にする：深度が最も近いテクセルを使うと、天井の板の溝に隣の板の明るさが漏れ、法線を見ないと溝の側面が深度の許容を通った。本描画では `getShadow`・`suiSunShadow` をこの1回参照に `#define` で置き換え、PCSSの関数は呼ばれず消える：実行されない分岐でもPCSSが本描画のシェーダに残るだけで、影を評価するのと同じだけ遅かった。threeはカメラのレイヤーにある光源だけを集めるので、光源にもマスクのレイヤーを足す（同じ光源・同じ順で影の番号が揃う）。静的な影マップは更新が必要になった後の最初の描画で、そのカメラのレイヤーの物体から描かれるため、マスクのレイヤーだけで描くと投射物のない影マップになる：更新が必要なフレーム（読み込み・画質変更）はマスクの前に元のレイヤーで一度描く（その間はマスク自身を読まない）。水面の鏡像パスは `createPlanarReflection` の `beforeDraw` で、鏡像のカメラ・描画範囲の大きさのマスクを別のターゲットに描く。水中の材質（`SUI_REFRACTION`）のマスク材質は同じ定義で頂点を屈折像へ動かし（影はビュー深度とも真の位置のまま）、`SUI_WATER_BOTTOM` があれば底面のスポット光の影座標も屈折経路の出口へ移す。本描画が捨て得る領域（`refraction.ts` の `mayDiscardGlsl`、深度プリパスと共有）では書かない。側面の像と側面の奥の壁のコピー（どちらも水面下で、日光・スポット光は `DRY_ONLY` により底面の光沢にしか使われない）は `SUI_HARD_SHADOW` を定義し、マスクなしでPCSSを1回参照に置き換える。HDR出力のない端末・軽量画質（影なし）では使わない。林のカードのマスク材質（`SUI_CUTOUT`）は照明パスが葉を残す画素（`alpha ≥ alphaTest`）だけ書く。半透明は従来どおりPCSSを自分で評価する。画像は半影の粒の並びと輪郭の画素だけが変わる（`docs/3d-qa/shadow-mask/`）。`data-shadow-mask-meshes` に数を記録する。
- 描画は `hdrOutput.ts` で4倍MSAAの半精度レンダーターゲットへ線形のまま描き、全画面パスで一度だけトーンマッピングする（Cyclesと同じく、ガラス・水・蒸気の合成を線形で行う。three 0.186の `outputBufferType` は `renderer.dispose()` で解放されないため自前）。最終パスはアルファを1にする（canvasは `alpha: true` で、葉の縁などシーンのアルファが1未満の画素でページの背景が透けていた。サウナ昼の既定視点で約1800画素、2026-10-03修正）。`EXT_color_buffer_float` がない端末は従来どおり材質ごとにトーンマッピングする。canvasは全画面パスを受けるだけなので、`createRenderer()` が先にWebGL2コンテキストを `antialias: false, depth: false` で作り、`EXT_color_buffer_float` があればそれをthreeに渡す（canvasの4倍MSAA＋深度、1280×800で約31MiBを持たない）。ない端末はそのコンテキストを失わせて従来どおり `antialias: true` で作る。シーンの後始末は `renderer.dispose()` の後に `forceContextLoss()` で、旧コンテキストの描画バッファ・three内部のテクスチャをGCを待たずに解放する（`docs/3d-qa/gpu-memory/`）。描画数・三角形数の計測値は全画面パス・深度だけのプリパスを含まない。空（`sky.ts`）も線形の放射輝度で描き、同じパスでトーンマッピングする。
- 空は `sky.ts`。元blendのWorld（`scripts/build_sky_world.py`）は、拡散反射を経ていない経路（カメラ・光沢・透過）にだけ空（天頂→地平のグラデーション・グロー・曲面に貼ったFBMの雲・Voronoiの星・昼だけ日光の円盤）を見せ、拡散反射の後は元の単色のままにしている。このため照度プローブは元のまま（単色の空）、反射プローブは空を含み（円盤は除く）、ブラウザは背景だけを描く。空の明るさは、上向きの面への照度が焼き込んだ中庭の平均照度と一致するよう `build_sky_world.py` が倍率を決める。ノードを1つずつGLSLに移植し（パラメータは同スクリプトが書く `sky.json`、Blender軸。視線をglTF→Blender軸へ変換）、Perlin fBmは `noiseColor.ts`、ハッシュは `caustics.ts` の `BLENDER_HASH_GLSL` を共用する。画素より細かい雲のオクターブは平均へフェードし、星と円盤は画素内の光束を保つ（`sui_sky_star`・`sui_sky_disk`）。単位球のメッシュを視点の回転だけで遠クリップ面（`z = w`）に描き、深度を書かず `renderOrder` を大きくして他の不透明物の後に空いた画素だけを塗る（斜め投影の鏡像パスでも欠けない）。日光の円盤は元blendで光沢の経路に見えないため、鏡像のカメラ（`MIRROR_LAYER`）では `suiSkyDisk` を0にする。夜の空は月の方向のかすかな暈・月光に縁を照らされた雲・ブルーアワーの2倍の星・月の円盤（0.1W/m²を角直径0.0093radで割った放射輝度）。重みのある空だけを評価して混ぜる（常に2つまで）。移植は `sky.e2e.ts` がCyclesのパノラマ（`scripts/blender_sky_reference.py` → `e2e/fixtures/blender-sky.json`）と照合する。雲は動かない（Cyclesと同じ静止画。動かすと鏡像を毎フレーム描き直す必要がある）。
- トーンマッピングは元blendと同じAgX（look None）。three内蔵の `AgXToneMapping` はBlender 4.xのAgX（E-Gamut・57³ LUT）と別の曲線で、同じ線形入力を平均約4 L*明るく表示するため、`agx.ts` がAgX関数を差し替える（行列・対数・32点の曲線・行列・2.4乗・行列。定数は `scripts/fit_blender_agx.py` でBlenderのOCIOに当てはめ、表示値の誤差平均0.001）。露出はBlenderの昼0.15・ブルーアワー0.55・夜0.9段を重みで平均して `2^EV` で使う。日光（向きは全シーン共通、強さは昼3.2・夕暮れ0.045の青・夜は月の0.1の淡い青。色×強さを重みで混ぜる。元の日光は光沢に不可視なので、`lights_fragment_begin` の平行光源ループで鏡面反射を戻して拡散だけにする）、寝椅子上のスポット光（元の `V9 lounge patch of sunlight`、950W円盤→軸上 `950/π` cd、夕暮れは0）、ブルーアワーの暖色灯5灯（`V10 lounge dusk fill` 42W・`V10 path grazing light 1/4/7` 各8W・`V10 specimen uplight` 35W、軸上 `P/π` cd・5灯すべてに影あり・昼は0）、サウナ室の面光源6灯（下記）は元blendの値。スポット光はすべて元の円盤光源の代わりで、90度の円錐とpenumbra 1のまま `lights_pars_begin` の減衰を smoothstep から線形へ差し替え、正確な余弦配光にする（`SPOT_COSINE`）。半球光はない。空・ブラウザで描かない面光源（Sky softbox・Sunlit courtyard・行灯など）・全光源の間接光は、元blendから焼き込んだ照度プローブ（下記 `irradiance.ts`）で与え、合わせ込みの係数はない。照明の確認はCycles同視点との比較（`scripts/cycles_tone_stats.py`、CIELABの明暗分布と彩度）で行う。夕暮れは06に加え、`scripts/blender_bluehour_reference.py` のブルーアワー参照画像（02〜05・07）とも比較する。夜は元のレンダーがないため、同スクリプトを `-S "SUI • Night"` で実行した参照画像（01〜05・07、`blender/renders/web-night/`）と比較する。照明を変えたら全周撮影の後にこのスクリプトで比較し、進捗記録へ値を残す。ブラウザで再現しないノイズ→ランプの基本色（漆喰・リネン・樹皮・砂利）は書き出し時にノイズ平均0.5のランプ色の単色にする（`procedural_flat_color`）。
- サウナ室の照明は `interiorLights.ts`。元の6灯（ベンチ下2・天井・壁・蒸気の逆光・背もたれ）を `RectAreaLight`（円盤は等面積の正方形、壁の灯は室内に出る帯だけ）で放射輝度 `P/(π·A)` にし、影がない分を光源ごとの見え率（02の視点でCycles直接光÷Web直接光）で掛ける。元の光源は光沢に映らないため拡散成分だけを、受光面の地平線で切り取った厳密な形状係数で計算する（LTCテーブルは読み込まない）。`lights_fragment_begin` を差し替え、室内の箱（ガラス面まで）の外では6灯を評価しない。同じ箱の判定で照度プローブの室内グリッドを選ぶ。Three.js更新時は `interiorLights.test.ts`・`agx.test.ts` と全周撮影で確認する。
- 間接光は `irradiance.ts`。`scripts/bake_irradiance_probes.py` が元blendの昼・ブルーアワーをCyclesで焼き込んだL2球面調和（SH）の照度プローブ（`public/models/irradiance.json`・`irradiance.bin`、float16）を、室内（0.5m・室内の箱の中の画素だけ）・中庭（1m）・外周（3m、中庭グリッドの端1.5mで混合）・水中（約0.5m・`WATER_BOX` の画素だけ）の4グリッドのRGBA半精度3Dテクスチャ（three の LightProbeGrid と同じ詰め方・余白付き）にし、`lights_pars_begin`・`lights_fragment_begin` に画素ごとの評価を足す。three の LightProbeGrid は物体ごとに1グリッドを選ぶが、モデルは材質ごとに結合されて室内と中庭にまたがるため使わない。プローブは面から法線方向に半間隔ずらして読むが、水中グリッドだけはずらさない（プローブはすべて有効で、下の層はタイルと水の底面の間の空気層 y=0.2085m にあり、床は自分の高さの照度を読む）。水中グリッドの照度はパノラマでなく、タイルと同じアルベドの拡散球の照度で焼く（元blendの間接光クランプ・Filter Glossyが水面越しのV9をタイルの拡散反射では削るため。`docs/3d-qa/water-floor-irradiance/`）。時間帯は `suiIrradianceEvening`（1−昼の重み）と `suiIrradianceNight`（夜の重み）で3シーンの係数を混ぜる（重みのあるシーンだけ評価）。プローブには空・ブラウザで描かない面光源の直接光・全光源の間接光が入り、ブラウザで描く光源（日光・V9・室内6灯・夕暮れの暖色灯5灯）の直接光は入らない。GLBの `MeshStandardMaterial` に `SUI_IRRADIANCE` を定義し、uniformは全材質で共有する。照度と反射（下記）はグリッドごとに1枚のテクスチャ（照度の昼・夕・夜→反射の昼・夕・夜の42サブボリューム、`createProbeTextures`。中庭で奥行き1134層、WebGL2の3Dテクスチャ上限2048以内）にまとめる：フラグメントシェーダーのテクスチャユニットは16で、影マップ7枚と材質の画像が大半を使うため、別テクスチャを増やすと画像付きの材質がコンパイルに失敗して消える。読み込みはGLBと並行し、形式の不一致は3Dの読み込み失敗として扱う。Three.js更新時は `irradiance.test.ts` と全周撮影で確認する。`data-irradiance-probes`・`data-irradiance-materials` に数を記録する。
- 環境の鏡面反射は `reflection.ts`。`bake_irradiance_probes.py --reflection` が照度プローブと同じグリッドに、光沢レイに見えるもの（空・面・光沢に可視でブラウザがハイライトを描かない光源。日光・Sky softbox・Sunlit courtyard・行灯・室内6灯は元から光沢に不可視、V9・夕暮れの暖色灯5灯はブラウザが描く）の放射輝度をL2 SHで焼き込む（`public/models/reflection.json`・`reflection.bin`、グリッドは照度と一致必須で、照度と同じテクスチャの後半を使う）。粗さごとに帯域1・2をGGXと同じ幅のvMF（Λl≈exp(−l(l+1)α²/4)）で減衰し、threeの支配方向で評価して `lights_fragment_begin` の `radiance` に足す（Fresnelはthreeのsplit-sum）。照度プローブの材質（`SUI_IRRADIANCE`）に `SUI_REFLECTION` を定義する。L2なので鏡像は出ず、ガラス・水はぼけた映り込みになる。`data-reflection-materials` に数を記録する。
- ガラスは `glass.ts`。書き出しのガラス（12%不透明の拡散面）を元材質の厚さ18mmの透過ガラス（IOR 1.45・色で1回だけ着色）として描き直す：元のメッシュが透過率 `T=(1−F)²t/(1−F²t)` を乗算合成で掛け（影は従来どおり投射）、同じ形状の子メッシュがその直後（同じ深度・後のid）に反射率 `R=F+F·T` × 反射プローブを加算する。Fは誘電体の厳密なFresnel。Cyclesで元材質の板を測った値（垂直T=0.812/0.896/0.887・R=0.062、75°でT=0.525・R=0.373）に0.01以内で一致する（`glass.test.ts`）。プローブはカメラ側で参照し、室内から見るときは室内グリッドを使う。屈折のずれ・粗さ0.055は省略。`data-glass-meshes` に数を記録する。
- 見回し中の時間方向の蓄積は `temporalAA.ts`。各ステージのカメラは回転だけなので、前のフレームの画素は奥行きなしの射影変換（遠クリップ面の点、`reprojectionMatrix`）で今のフレームへ正確に写る。`hdrOutput.ts` がMSAAを解決した線形HDRの画像を半精度の履歴2枚と交互に混ぜ（履歴0.9、`c/(1+max)` で圧縮したYCoCg）、その結果をトーンマッピングする。履歴は今の画素と上下左右の5点（十字）の平均±標準偏差の箱に、今の画素を必ず含めて制限する（含めないと静止画がぼけに収束した。3×3の9点は残差を1〜2%多く減らすがパスの費用が約1.6倍）。履歴はCatmull-Rom（双線形5回）、画素中心では `texelFetch`、今のフレームは `texelFetch` で読む。サブピクセルのずらしはしないので、静止画は1フレームの画像そのもの：履歴が半精度の丸めの範囲で今の値と同じ画素（混ぜても0.1倍の差が丸めで消えて止まる、最大約5段）は今の値をそのまま出し、`?temporal=off` とほぼ全画素一致する。カメラ位置・描画バッファの大きさが変わるか、1フレームに0.25rad（`JUMP_ANGLE`。指のスワイプ約0.07radでも履歴は効く）を超えて回るか、矢印キーを押すと（`attachLookControls` の `onJump`）履歴を捨てる（ステージ変更・Cycles視点の差し替え・矢印キーの見回し・撮影のための視点の飛びの直後も次のフレームから同じ画像）。60フレーム（`STILL_FRAMES`）続けて止まると履歴は収束しているので、パスを省いて履歴を捨てる（すぐ省くと、ゆっくりしたドラッグで混ぜた像と1フレームの像が交互に出てちらつく）。見回し中の葉のちらつき（面の残差）は約0.55倍、費用は見回し中だけでDPR 1.5で約0.1〜0.4ms（十字にした後、`docs/3d-qa/temporal-aa/`）。サブピクセルのずらしはさらに減らすが静止画もやわらかくするため採らなかった。軽量画質・HDR出力のない端末では使わず、`?temporal=off` で無効（`data-temporal`）。
- 3D画質は `quality.ts` の軽量／標準／高精細。`sui-quality` に保存し既定は標準。DPR上限は1／1.5／2、日光・V9スポット光・夕暮れの暖色灯5灯の影は無効／1024／2048px。夕暮れの暖色灯5灯は全画素のシェーダーに加わるため、軽量では非表示にする（ライト数の変更はシェーダー再コンパイルを伴うので、画質変更時だけ切り替える）。水面の鏡像の解像度は描画バッファの0／0.5／1倍。モデルを保持したまま反映し、画質変更時は180フレームの計測をリセットする。描画中のシーンの画質変更は、`lighting.withQuality()` で一時的に新しい画質の光源・影の数にして `hdrOutput.ts` の `compile()` だけを行い、旧画質のまま描き続けてプログラムのリンク完了後に適用する（`data-quality` は適用した画質。連続した変更は最後の選択だけ、破棄後は適用しない）。threeはプログラムを初めて描くときにドライバーを同期で待つため、従来は軽量への切り替えで約0.4〜0.5秒止まった（`docs/3d-qa/quality-stall/`）。threeの `compileAsync` は材質の現在のプログラムを待つが、間の描画が旧画質のプログラムへ戻すため、`compile()` はコンパイルしたプログラム自体の `isReady()` を待つ。光源に依存しない材質は描画時に影の有無を比べず、コンパイルしたプログラムを旧画質の描画で使ってしまうため、`needsUpdate` で選び直させる。読み込み時も最初の描画の前にシーン全体を同じ `compile()` で準備する（待つ間に画質が変われば準備し直す）。従来は最初の描画で41プログラムを1つずつ同期で待ち、約0.78秒のLong Taskになっていた（`docs/3d-qa/load-compile/`）。何も描いていないコンテキストの並列コンパイルは、別のページがWebGLを描いている間4〜30秒以上終わらないことがあったため、読み込み時の待ちは1秒まで（`compile()` の `within`）で、残りは最初の描画で同期で待つ。画面外ターゲットのクリア・`flush()` では進まなかった。`KHR_parallel_shader_compile` がないブラウザでは、threeが各プログラムを作成直後に準備完了とみなすので `compile()` は待たずに終わり、最初の描画・画質変更後の最初の描画で従来どおり同期で待つ（止まりはするが終わらない待ちはない）。
- 動的解像度は `dynamicResolution.ts`。1秒ごとの平均フレーム間隔が60fpsの予算の1.1倍を超えるとDPRを0.25ずつ画質の上限の6割（1未満にしない）まで下げ、予算内が10秒続くと1段上げて試す。上げてすぐ遅くなれば次の試行までの待ちを倍にする（上限160秒）。下げた後の最初の窓が予算の1.04倍以内か下げる前の9割未満でなければ段を戻し、段下げを10秒（効かないたびに倍、上限160秒）保留する（30fps上限・CPU律速で画質だけ落とさないため）。250ms超の間隔と切り替え直後（画質の変更で上限へ戻した直後も）の1窓は数えない（描画先の再確保・影の作り直しの引っかかりで意味なく段を下げていた）。画質の変更で上限へ戻し、ステージの変更で待ち・保留を戻す。DPR1の画面では何もしない。`?resolution=fixed` で無効（`data-resolution`）。DPRが変わると180フレームの計測をリセットする（`data-pixel-ratio`）。記録は `docs/3d-qa/dynamic-resolution/`。
- 静止中の描画は `frameRate.ts` で30fpsに間引く（無風扇のノートPCで発熱していた。画面はほぼ眺めるだけだが、水・蒸気・時間帯が動くため毎フレーム全体を描いていた）。前回の描画から `IDLE_MS − SLACK_MS`（約27ms）経ったフレームだけ描くので、60Hzでは1つおき・120Hzでは4つに1つ。カメラの位置・向きが変わったフレーム（見回し・ステージの視点）から1秒（`HOLD_MS`、TAAの履歴が落ち着くまで）とロウリュの蒸気の6秒は表示のフレームごとに描く。間引き中は動的解像度の窓を数えない（`pause()`。30fpsはGPUの遅さではない）。180フレームの計測は描いたフレームの間隔。`?frameRate=full` で無効（`data-frame-rate`）。フレーム時間・rAFを操作する検証や撮影はこれを付ける。`frame-rate.e2e.ts` が静止・見回し・ロウリュの描画の割合を確かめる。
- 影を描くのは日光・V9スポット光・`V10 lounge dusk fill`・`V10 specimen uplight`・通路の暖色灯3灯（室内の面光源は影なし）。Cyclesのガラスは直接光を通さないため、ガラスは影を投射する（受けない）。両面材質の裏面は反転した法線で陰影付けされるため、`softShadows.ts` が `shadowmap_vertex` で影の法線オフセット（normalBias）を頂点ごとに視点側へ反転する（下向きの遠景地形が自分の影に入っていた）。水・蒸気は影を投射しない。影を描く7灯は動かないため、影解像度の変更時だけシャドウマップを更新する（昼夕の補間中も再描画しない）。軽量切り替え・シーン解放時に7灯の影のGPUリソースを解放する。threeの影マップは色付きのレンダーターゲット＋深度テクスチャで、シェーダは深度だけを読むため、`narrowShadowColor()` がターゲットの代入時（確保の前）に色をR8にする（2048²で1灯16→4MiB。threeは最初の影の描画で影の種類の変更としてターゲットを必ず作り直すので、事前に渡せない）。これはベイクではない。
- 影のぼけは `softShadows.ts` のPCSS。three 0.186の `shadowmap_pars_fragment` のBasicShadowMap分岐を差し替え（レンダラーはBasicShadowMap）、遮蔽物との深度差×係数kで半影幅を決める。kは `shadow.radius` で渡し、日光は角直径0.085rad（`directionalPenumbra`、夜の月は0.0093radへ重みで補間）、V9は直径1.25m、夕暮れの寝椅子灯は直径2m・モミジ灯は直径0.6m・通路灯3灯は直径0.28m（`spotPenumbra`）から計算する。日光の影の範囲は±30m（範囲外は影がつかない）。標本数は16+24だが、日光だけは色×強度の最大成分が `SUN_LITE_BELOW`（0.09）未満のとき4+6（`SUN_LITE_SAMPLES`）にする（`suiSunShadow`。uniform由来の値の分岐なので再コンパイルなし。夕暮れの日光0.045のみが該当し、昼夕の補間の終わり約2%で切り替わる。夜の月0.1は見える鋭い影なので16+24のまま（以前の0.1だと月が境界上に来るため0.09にした）、夕→夜の補間ではt≈1.82で戻る。画像差はΔE>2の画素0%・夕暮れのGPU時間を削減、`docs/3d-qa/shadow-per-light/`）。暖色灯の半減は粒が見えるため不採用。一律に16+24を8+12にすると夕暮れのGPU時間は約3〜4割減るが、日なたの面の粒が目で分かるほど増えるため不採用（`docs/3d-qa/shadow-samples/`）。光に背を向けた画素（標準材質でclearcoatなし、`dot( geometryNormal, L ) <= 0`）は `lights_fragment_begin` の分岐で影を評価しない（`SUI_SHADOW_FACING`。直接光が `saturate( dot )` に比例するため画像は不変）。受け側平面の微分は分岐内では未定義になるため、分岐の前に `suiShadowSlope()` で取る（`docs/3d-qa/shadow-facing/`）。日なたの粒は葉・パーゴラの格子の本物の半影の標本ばらつきで、自己遮蔽の不具合ではない。Three.js更新時は `softShadows.test.ts` と全周撮影で確認する。
- `SaunaScene` は描画数・三角形数・テクスチャ数・ジオメトリ数もDOM属性へ記録。描画数は最新フレームの値なので、照明補間中の影パスを含む値と、安定後の値を区別する。
- ロウリュの蒸気は `steam.ts`（`createSteam()` が点群・6秒の表示・濃淡を持つ。作成直後は表示のままにしてシーンのコンパイルに含める）。動きを減らす設定では全軸を固定し、濃淡と6秒の表示時間は維持する。`scene-viewport.e2e.ts` は390×844の操作・キーボード見回し・844×390とのリサイズ・同一canvas保持を検証。Chromeの画面サイズとメディア設定のエミュレーションであり、モバイル実機の検証ではない。
- 見回しは `lookControls.ts`。終了は操作開始時のpointerIdに一致する場合だけ処理し、別の指の終了・キャンセル・キャプチャ喪失で中断しない。`scene-touch.e2e.ts` はChromeのCDPタッチ入力でスワイプ、2本目の指を離した後の操作継続、キャンセル後の再操作、タップでのUI復帰・ステージ一巡・2D復帰を検証する。モバイル実機やSafariの検証ではない。
- 林のカードは `leafCluster.ts`。20枚の菱形の葉のマスクを決定的に生成し（カードの半分を覆う）、アルファテストの被覆率を保つよう各ミップを自前で補正、`alphaToCoverage` で描く。被覆は `suiLeafCoverage`（`alphatest_fragment` の置き換え、深度プリパス・影マスクの複製も同じ関数）で、1画素が1→2テクセルを覆うにつれ閾値0.5の遷移の半幅を `fwidth` から `LEAF_FAR_RAMP`（0.2）へ広げる。葉が1画素前後になる遠景で画素ごとの点滅を抑える（見回し中のちらつきの約半分がカードだった）。ミップの平均被覆をそのまま渡すと、重なったカードが同じサンプルを覆って冠が透け、広げすぎ（0.35以上）も透ける（`docs/3d-qa/leaf-shimmer/`）。マスクは枚数ごとに1枚を共有し、材質とともに解放する。`data-leaf-cluster-materials` に対象材質数を記録する。
- 葉は `foliage.ts`。名前が leaf／foliage／fern の `MeshStandardMaterial`（落ち葉 `leaves`・苔・樹皮は対象外）を両面にするだけで、裏面へ光を透過させない。元の葉はTranslucentもTransmissionもなくSubsurface Weight 0〜0.08で、Cyclesで背面から照らすと正面の0.1%未満しか返さない（以前の0.6倍の透過は元データに根拠がなく、林・草を明るく鮮やかにしていた）。視点側の面は照度プローブが照らす。`data-foliage-materials` に対象材質数を記録する。
- 地面の苔・シダの色は `noiseColor.ts`。`export_web_glb.py` が元材質のワールド／オブジェクト座標fBmノイズ→線形カラーランプの設定を材質 `extras.suiNoiseColor` に記録し、BlenderのPerlin（Jenkinsハッシュ）とfBmのGLSL移植で画素ごとに評価する。画素より細かいオクターブは平均へフェード。バンプは省略。Three.jsの `common`・`project_vertex`・`color_fragment` チャンクに依存。移植は `noise-color.e2e.ts` がBlender基準値（`scripts/blender_noise_reference.py` → `e2e/fixtures/blender-noise.json`）と比較する。名前による苔・シダの単色上書きはBase Colorが接続された材質だけ。
- 石・布・木材の色は `imageRamp.ts`。`export_web_glb.py` の `base_color_image_ramp()` が「画像→RGBのBW化→線形ランプ × Object Info Randomのランプ（→一定色へ混合）」を材質 `extras.suiImageRamp` に記録し、結合前のオブジェクトごとの乱数を色属性 `SuiObjectRandom`→`COLOR_0` で渡す（名前seedの一様乱数でCyclesの値ではない）。濡れ跡のノイズは省略。輝度係数はBlenderのOCIO設定の `luma`。Three.jsの `common`・`map_fragment`・`color_fragment` チャンクに依存。`data-image-ramp-materials` に対象材質数を記録する。書き出しはUVの最下位ビットが実行ごとに揺らぐため、GLBのハッシュは再実行で変わる。
- 庭の木々（`sauna-garden.glb`、`scripts/compress_web_glb.mjs` の `GARDEN`）は準備完了（`onReady`・30秒期限の解除）の後に取得する。本体と同じ `prepare`（材質拡張・プローブ等、材質数の `data-*` は合計）を通し、`hdrOutput.ts` の `compile()`（HDRターゲットを設定して `compileAsync`）の後にシーンへ加え、`lighting.refreshShadows()` で静的影を描き直し、鏡像の状態（`mirrorState`）を変えて描き直させる。水中の三角形があれば失敗扱い（側面の像を作らない）。庭の失敗は3Dを止めない。`data-garden`（loading／ready／failed）・`data-garden-ms` を記録し、`onGardenLoading` で `SceneMode` に読み込み中を伝える（refで保持し、変わってもシーンを作り直さない）。描画数・資源数・画像を見るブラウザテストは `data-garden="ready"` を待つ。
- `SaunaScene` 内で `meshoptimizer/decoder` をGLTFLoaderへ渡す。WASMは3Dの遅延JS内に含まれ、CDNや別のデコーダーURLへ依存しない。圧縮ストリームの破損時も2Dを継続し、手動再試行できることを `scene-lifecycle.e2e.ts` で検証する。圧縮は転送量を減らすもので、描画三角形数やGPUメモリは減らさない。
