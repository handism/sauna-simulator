# GLB書き出し・シーン定義（scripts）

- 体験用視点と水面位置の正本は `scripts/web_scene.py`。水面の高さ0.765mは元の `V4 rippled spring water volume` の上面の平均。`python3 scripts/web_scene.py` でシーン定義だけ再生成できる。GLB再出力時も同じ関数を呼ぶ。
- 葉の書き出しは `export_web_glb.py` の `sample_whole_leaves()`。接続成分を葉として名前をseedに選ぶ。近景V11 maple 3体とV7 mapleは全枚数を元の5裂の輪郭・水平の向き・元の面のスムーズ設定のまま残す（元形状は1枚10三角形）。V6林の葉（`V6 clustered tree leaves`、1本約4,000枚）は元の葉20枚につき1枚の切り抜きカード（元の葉の面積を保つ長方形、UVは4隅・90度単位の回転）へ置換する。カードは複製した専用材質（名前末尾 ` card`）を使い、その `extras.suiLeafCluster` に枚数を記録する（同じ色材質を使う `V8 selective low grass` にはカードUVがないため共有しない）。`Fine canopy leaves` とその複製は各480枚を間引かず2三角形の平面へ変換する。それ以外は1オブジェクト175枚を上限に、元の位置・向き・広がりを近似した2三角形の平面へ変換する（V5/V6の葉は元から菱形）。建物のDecimateとは分離。中庭外の距離による除外はしない（該当する表示対象は林・植栽帯の木だけで、Cyclesの視点に写る）。奥の植栽帯のモミジは菱形のまま。
- 樹皮（`Tree bark`）のカーブは書き出し時にメッシュ化する（断面分割1、UV削除）。元blendで `hide_render` の `V5 overhead canopy bough` は、見上げ可能なWeb用に限り復元する。V5頭上キャノピーの葉は間引かず全960枚。`Limestone terrace paver` はデッキ材と上面が一致するため書き出し時に3mm持ち上げる。
- V6の枕は両極に未接続の重複頂点があるため、Web書き出し時に距離1e-6で結合してから簡略化する。対象は `V6 compressed linen pillow` のみ。結合後と簡略化後の閉じた形状を検査し、`export-report.json` の `pillow_topology` に記録する。元blendは保存しない。
- 壁の施設名・案内・温度計は、書き出し時に描画対象の `FONT` を元の輪郭・厚み・配置・材質のままメッシュへ変換する。文字は小物の除外・Decimateの対象外。`export-report.json` の `text_meshes` に本文・フォント・三角形数を記録する。ブラウザ用フォントや文字画像は追加しない。
- GLBは書き出し末尾の `scripts/compress_web_glb.mjs` で可逆の `EXT_meshopt_compression` に圧縮する（meshoptimizer 1.1.1、bitstream v0、頂点はATTRIBUTES、インデックスは順序を完全保持するINDICES、フィルターなし）。すべての圧縮領域を復号し、元のバイト列と一致することを出力前に検査する。材質extras・画像・ノード変換は維持し、量子化は採用しない。`docs/3d-export/` の `compression-report.json` と `export-report.json`（配信物に含めない）に圧縮前後のハッシュと容量を記録。書き出しにはNode.jsと `bun install` が必要。
- 元のレンダーでブルーアワーは06（カメラ01）だけ。夕暮れの照明比較用に `scripts/blender_bluehour_reference.py`（`-S "SUI • Blue hour"` で起動）がカメラ02〜05・07をブルーアワーで描き、`blender/renders/web-bluehour/`（Git管理外）へ出力する。50%解像度・128サンプル・デノイズの参照用で、完成画像ではない。`cycles_tone_stats.py` はこれがあれば夕暮れの撮影と比較し、元の7枚とは別に集計する。元blendは保存しない。
- 材質の粗さが画像・ノイズで接続されている場合（デッキ・木材・石材・リネン・濡れ跡）、`scalar_samples()` で平均値を `roughnessFactor` にする（画像は全画素の輝度をランプに通した平均、ノイズは平均0.5の値）。未対応ノードは例外。`export-report.json` の `roughness_mean` に記録する。Specular IOR Levelは元の値を残し、0.5以外はBlenderの書き出しで `KHR_materials_specular`（係数2倍）になる。three.jsではその材質が `MeshPhysicalMaterial` になる。
- `src/components/3d/agx.ts` の定数は `scripts/fit_blender_agx.py` で作る。Blenderで `-b --python scripts/fit_blender_agx.py -- <出力.npz>` と実行すると同梱OCIO（Linear Rec.709→sRGB、AgX）で20万色の参照値を書き出し、通常の `python3 scripts/fit_blender_agx.py <出力.npz>`（NumPy・SciPy）で当てはめて定数と検証誤差を表示する。参照値はGit管理外に置く。
- 照度プローブは `scripts/bake_irradiance_probes.py`（`-b blender/scene/SUI_Retreat.blend --python-exit-code 1 --python scripts/bake_irradiance_probes.py`、Metal GPUで約40〜60分）。昼・ブルーアワーの各プローブ位置で64×32の正距円筒パノラマ（64サンプル、元のバウンス数・クランプ）を描き、glTF軸のL2 SHにして `public/models/irradiance.json`・`irradiance.bin` と `docs/3d-export/irradiance-report.json` を出力する。元の光源はすべてカメラから見えないので、ブラウザで描かない光源だけ焼き込み中にカメラから見えるようにする。形状内のプローブは全材質に足したBackfacingのAOV（コンポジターでアルファへ）で判定し、近傍から埋める。水材質は裏面を囲いとして扱わず（AOV 0）、水中は専用の `water` グリッドが担う。中庭・外周の水中・室内のプローブは外側から埋める（水中の暗い値が周囲のデッキへ漏れないように）。下向きの大きな地形（`V10 woodland floor extension`）は焼き込み中だけ法線を反転する。視点の方向はCycles自身に描かせて較正する。`--out <dir>` で別出力、`--quick` で間隔2倍、`--grids water` で指定グリッドだけを焼いて他は配信中のファイル（同じ入力・同じ配置）から引き継ぐ（反射も同様、各約80秒）、`--probe-test N [--probe-grid G --probe-start I]` で速度と値だけ確認。1枚ごとにimageデータブロックを作る・材質を上書きする・CPUデバイスを併用すると1点数秒に遅くなる。元blendは保存しない。
- `--reflection` を付けると同じグリッドに反射プローブを焼き込む（`public/models/reflection.json`・`reflection.bin`・`docs/3d-export/reflection-report.json`）。各光源のカメラ可視性を元の光沢可視性にし（ブラウザがハイライトを描くV9・夕暮れの暖色灯5灯は除く）、ワールドも光沢可視性に合わせる。約0.35〜0.5秒/点。
- `bake_irradiance_probes.py --surface-samples <JSON> --out <診断先>` は配信プローブを更新せず、面の位置・単位法線（glTF軸）で昼夕の入射拡散光を診断する。例は `docs/3d-qa/probe-sampling/surface-points.json`。128×64・128サンプルのパノラマを面から2cm／5cmで描き、全方向の余弦積分・同地点L2 SH・既存グリッド補間（法線オフセット0／0.5格子）を `surface-sampling.json` に保存する。元blendとfixture・プローブのハッシュ対応を確認する。反射／quick／probe-testとの併用は禁止。`probe_sampling.py` がCPU上のグリッド補間を担当し、`python3 -m unittest discover -s scripts -p 'test_probe_sampling.py'` で定数光・線形場・境界・参照位置・室内選択を検証する。点の診断であり画面全体の品質指標ではない。2cm／5cmの差と裏面の比率も確認し、遮蔽を一律の減光係数に置き換えない。
- `diagnose_probe_visibility.py --out <診断先>` はBlenderから実行し、面近傍fixtureの補間元・重み・符号付き照度と、面から2cm／5cmで各隅への形状遮蔽を診断する（`--samples <JSON>` でfixture指定可）。出力は `visibility.json` のみ。ガラス・葉も遮る幾何判定で、可視性による再正規化は製品未採用。小さい残存重みの増幅に注意。`check_probe_visibility.py` は入力blendなし・`--factory-startup` でレイの終端・非表示の除外・全遮蔽時などを検証する。
- `diagnose_probe_depth.py --out <診断先>`（Blender）は面近傍fixtureの補間元ごとに、測定点方向へcos^50ローブ64本のレイを飛ばし、距離の平均・二乗平均（2cm・5cm・半格子の参照点）を `depth.json` に出す。`compare_probe_weights.py <depth.json>`（通常のpython3）がChebyshev・裏面の重み・正則化εの候補を面近傍測定と比べる。`survey_probe_enclosure.py --out <診断先>` は全プローブの空き距離（約14分）、`refill_enclosed_probes.py <enclosure.json>` は閉じ込められたプローブの埋め直し候補を評価し、`--write` で作業用コピーへ書き出す（`public/models` は拒否）。いずれも不採用の診断で、記録は `docs/3d-qa/probe-depth/`。面近傍2cmの参照は薄い葉で誤判定し、プローブ値の埋め直しは下の床へ光を漏らす。`fill_invalid` はベイクと共用で `probe_sampling.py` にある。Blenderの `first_hit`／ローブ／全球方向は `check_probe_visibility.py` で検査する。
- `sample_room_floor.py --out <fixture.json> [--spacing 0.25]`（Blender）はサウナ床 `Sauna floor` をセル中心の格子で下向きレイにより拾い、`--surface-samples` 用のfixtureを作る。`summarize_floor_irradiance.py <surface-sampling.json> --out <dir>`（通常のpython3・NumPy・PIL）が裏面0.25以上の点（閉じた形状内）を除き、グリッド／測定の比・領域（東の壁際・ストーブ周り・その他の壁際・開けた床）ごとの比・一律係数・0.5m床マップのホールドアウト評価と分布図を出す。記録は `docs/3d-qa/floor-irradiance/`。床マップは不採用（0.5mでは改善しない）。
- `blender_caustic_reference.py`（Blender、元blend）は水中の `V10 | submerged light` 材質の発光強度に繋がるノードをGeometry Nodesへそのまま複製し、128点で強度とVoronoi・ノイズの中間値を評価して `e2e/fixtures/blender-caustic.json` に書く（2材質が同じ発光であることを検査）。元blendは保存しない。
- `fit_water_waves.py` は元の水面の波を `src/components/3d/waterEffects.ts` の `WAVES` に当てはめる。Blenderで `-b blender/scene/SUI_Retreat.blend --python-exit-code 1 --python scripts/fit_water_waves.py -- <heights.npz>`（1cm格子の下向きレイで上面の高さを取る。元blendは保存しない）、次に通常の `python3 scripts/fit_water_waves.py <heights.npz>`（NumPy・SciPy）で注水口中心の同心円波＋平面波を最小二乗で当てはめ、glTF軸の係数・R²・残差を表示する。npzはGit管理外。
