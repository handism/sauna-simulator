# 初回描画の分割を製品へ組み込む設計

作成日：2026-10-06。状態：設計完了、実装・採用は未完了。

対象は本体と庭の初回描画。根拠は [時間予算付きの診断](3d-qa/compile-batches/README.md#キャッシュがある2回目の読み込みと時間予算2026-10-06) と現行ソース。診断の数値は製品実装の性能保証にしない。既定2D、明示的な3D選択、同じセッション・AudioContext、失敗時の2D継続を維持する。

## 1. 現行実装から分かった変更点

- `SaunaScene` の `setView()` はカメラ設定と実描画・空間音響更新を同時に行う。温め中に呼ぶと部分画像や準備途中の音響位置を公開するので、視点設定と表示確定を分離する。
- `ActiveScene` の `loading` はcanvasを隠さない。`.scene-3d-layer .sauna-3d-canvas` は常にポインタ操作を受ける。ロード表示だけでは途中画像を隠せない。
- `applyQualityRef` は準備完了前なら即座に画質を変える。非同期の材質分割中には描画先・光の数が変わるため、そのまま併用できない。
- 本体の準備完了後に庭を取得する。庭の温めで `material.visible` を操作すると、通常ループとステージ変更による描画が同じシーンを使う。描画処理を一つの所有者に限定する必要がある。
- 鏡像は視点・サイズ・状態をキーに再利用する。材質の表示切替はキーに含まれない。温め中と最後の完全描画には明示的な無効化が必要。
- 深度プリパスと影マスクは別材質のコピーを持つ。元材質を隠すだけではコピーも隠れるとは限らない。復旧後の全体描画で影・マスク・TAAを更新する。

## 2. 処理の責務と状態

`SaunaScene` がモデル・レンダラー・設定・終了処理を所有し、温め用ヘルパーへ描画コールバックと中止判定を渡す。ヘルパーはReact、通信、音響、ロード状態を操作しない。

| 状態 | 描画の所有者 | 利用者に見せる景色 | 次の処理 |
| --- | --- | --- | --- |
| 本体取得・解析 | なし | 2D | 材質加工・設定スナップショット |
| 本体コンパイル・温め | 温め処理 | 2D | 設定一致を確認、全体描画 |
| 本体表示確定 | 通常描画 | 完全な3D | `onReady()`、庭を取得 |
| 庭取得・解析 | 通常描画 | 本体3D | 通常ループの境界で温めを開始 |
| 庭コンパイル・温め | 温め処理 | 直前の完全な3D画像 | 設定一致を確認、全体描画 |
| 庭表示確定 | 通常描画 | 庭を含む完全な3D | `garden=ready` |
| 終了・失敗 | なし | 2D | 待ちを解除、遅着を破棄、解放 |

温め中は通常ループ・`setView()`・画質変更の完了コールバックから直接描画しない。ロウリュ通知は本体の準備前は消費せず、庭の準備中は既存の蒸気を通常どおり時間で終了させる。過去の通知を後から再生しない。

## 3. 材質の分割と時間予算

1. 全材質を元の表示状態でコンパイルする。シーンの光・影・描画先はその処理の設定で固定する。
2. プログラムと材質のブレンド・書き込み状態でグループ化する。元々非表示の材質は変更しない。
3. 重い材質を隠した鏡像・主描画を別ステップで準備し、その後1グループずつ鏡像・主描画を準備する。
4. 各描画の完了を確認し、直前にブラウザへ処理を返してから50ms以上ならrAF＋20msで処理を返す。各ステップ前と非同期待ち後に終了・設定変更を確認する。
5. `finally` で各材質の元の `visible` を復元する。グループ完了の記録は両パス終了後だけ確定する。

50msは処理を返す判断の予算であり、1回の同期GL呼び出しの上限ではない。診断でも約0.4秒の停止が残る。初回リンク情報の先行取得とフェンス待ちは採用しない。

`renderer.properties.get(material).currentProgram` とプログラムのshaderハンドルは内部構造に依存する。前記録の「公開APIだけ」という説明は、GLの描画抑止が不要という意味では成立するが、安定した公開インターフェースだけで完結するとは扱わない。参照を小さなアダプターに閉じ込め、Three.js 0.186.0の更新時に再検証する。欠けた情報を温め済みと判断しない。

6万字の閾値は今のシェーダーでの診断上の分類。材質名や文字数だけを永久的な性能判定にしない。最初の試作では診断と同じ分類を使い、通常描画で新しい重い状態が残らないことを計測する。

## 4. 部分画像を見せない

本体は準備完了までhostを視覚的にも入力対象としても無効にする。レイアウト寸法は維持し、完全描画・有効世代・期限内を確認した後で `data-load-ms` と `onReady()` を公開する。2Dの蒸気・オーロラを隠す既存の境界もこの時点に保つ。

庭は本体表示済みなので、hostを隠す方式では2Dへ一瞬戻る。採用案は **温めの描画を内部ターゲットに限定し、表示canvasへ出力しない**。通常ループを一時停止し、直前の完全画像を保持する。HDRの `output.render()` は最後に画面へAgX出力するため、温め専用のパスが必要。温めでTAA履歴を更新せず、完了時にリセットする。庭の新しい材質がない画面出力プログラムは本体準備時に温める。

ここは次の試作で検証する条件：通常出力と同じ形式・MSAAのパイプラインが準備されること、処理を返してもcanvasが空白にならないこと、庭温め中のリサイズでも途中画像が出ないこと。非HDRの直接canvas描画は同じ構成を使えない。代替ターゲットによる効果と画素一致を確認するまでは、非HDRで新方式を有効にせず従来の準備を維持する。canvasの `preserveDrawingBuffer` や全体のMSAA設定は変更しない。

## 5. 設定変更と期限

最新の希望設定と実際に準備している設定を別に持つ。設定スナップショットは画質・ステージ・時間帯モード・入室時刻・描画寸法を含む。変更ごとに要求世代を増やし、同時に二つの温め処理を走らせない。

- 本体の温め中：変更を記録し、次のステップ境界で復元して最新設定を準備する。GLBとプローブは再取得しない。旧世代から `onReady()` を呼ばない。
- 庭の温め中：旧設定の部分描画を中止・復元し、最新の完全な本体画像を先に描いてから庭の温めを再開する。新画質の初回使用も発生するので、この経路の停止時間も採用前に測る。
- 自動時間帯：毎フレームの連続値で世代を増やさない。準備中は時刻を固定し、表示確定直前に入室時刻から再計算する。光の数を変える画質変更は別世代にする。
- 見回し：本体準備中は入力を受けない。庭準備中はカメラへの直接変更を保留し、表示確定時にステージに合った視点へ整合させる。準備前からのドラッグはキャンセルし、解除後は新しい操作を受ける。
- リサイズ：ResizeObserverから温め中のターゲットを直接再確保しない。新寸法を記録して境界で反映する。

本体の絶対期限は `ActiveScene` の開始から30秒。JavaScript取得、コンパイル、温め、設定変更を含み、再準備で延ばさない。タイマーだけでなく表示確定前にも経過時間を検査する。同期GL処理を途中で割り込んで中断することはできない。

庭は本体の30秒期限の対象へ戻さない。庭のコンパイル・温め開始から30秒を別の作業期限とし、期限切れは庭だけ失敗、本体を継続する。取得に長くかかっても本体表示を停止しない。庭の作業期限も設定変更で延ばさない。

2D切替・解除・コンテキスト喪失・本体失敗は終端。rAF／タイマーの予約を解除して待ちも完了させ、以後GLを呼ばない。遅着GLBは解放する。`fail()` とcleanupは同じ中止経路を使い、音響を `null` に戻す。復元はレンダラーを解放する前に行う。既存の手動2D→3D再試行とimport拒否時の再読み込み案内を維持する。

## 6. 完全描画への復旧

成功・中止・例外のすべてで、材質の表示、カメラのlayers、override材質、描画先、clear状態、影マスクuniformを復元する。パス内で例外が起きても戻せるよう、鏡像・影マスクの状態変更も `try/finally` で守る。

表示確定は、最新の設定と視点・時間帯を適用 → 全材質復元 → 静的影の再更新 → 鏡像の強制更新 → TAAリセット → 完全描画 → 世代・終了・期限の再確認 → 状態公開、の順に行う。温め中のサンプルをフレーム時間計測や動的解像度の窓へ入れない。庭失敗時はモデルとそのコピー材質の所有関係を確認し、部分追加を取り除いて本体の影・鏡像を再生成する。

サウナの視点だけで全パイプラインが温まるとは前提にしない。水風呂・外気浴から3Dへ切り替えた場合も同じ処理へ入れる。姿勢ごとに実際に描かなかったグループを無条件に温め済みへ登録しない。ステージをまたぐ温めが必要かは次の計測で決める。

## 7. 実装と検証の順序

1. 一時ビルドで内部ターゲットへの温めを試す。通常→候補→候補→通常で、サウナ／水風呂／外気浴から3Dを開始し、庭温め中の完全画像保持と重い状態の初出を記録する。非HDRは別条件。
2. 同じ試作で3画質×昼夕夜の入口を確認する。変更なしの条件で通常描画との差と再撮影差を分ける。rAF・タイマーの最長間隔、ロード時間、本体／庭の時間、初回／同一プロセス内2回目を別に測る。
3. 条件が成立したら、中止可能なスケジューラー、設定世代、状態復元、出力パスを製品実装へ移す。単体テストは予約解除・待ちの完了・元々非表示の材質・例外・旧世代の完了拒否を検査する。
4. 本番ビルドのブラウザ回帰へ、温め中の2D切替／コンテキスト喪失／30秒期限／設定の連続変更／ステージ変更／リサイズを追加する。旧世代からreadyが公開されないことと同じセッションが続くことを確認する。
5. 通常回帰・遅い通信・全周静止画・動く時間帯と見回し・リソース安定性を確認して採否を決める。ChromeとPlaywright WebKitの結果をSafari実機やモバイルの保証にしない。

次の作業は1の試作。製品採用を決める前に、表示を保持したままの庭の温めと、水風呂・外気浴から開始した際のパイプライン網羅を確かめる。

## 8. 試作で確認した不足と設計への反映

2026-10-06に [内部ターゲットの試作](3d-qa/compile-batches/README.md#内部ターゲットでの温めと開始ステージ2026-10-06) を実施。開始視点だけを温める方法では、後のステージで初めて描かれる重い状態が残る。したがって、材質を列挙してステップを終えたことを、その材質のすべての描画先・視点の準備完了とは扱わない。

次の試作はサウナ・水風呂・外気浴の複数視点での温め。準備用のカメラ移動は音響と表示へ公開せず、最後に最新の希望ステージへ戻す。庭も鏡像が見える視点で準備する。各入口で、その後のステージ移動に新しい重い状態が残らないことと、追加の読み込み時間を別に測る。今回の撮影待ちを含む時間は性能比較に使わない。

庭の内部描画中のリサイズ、非HDR、画質・時間帯変更、中止競合、全周・動く時間帯・見回し、実機は未検証。製品の採用はこれらの検証と実装後の回帰まで保留する。
