# 自動の時間帯を入室からの実時間で進める（2026-09-29）

自動モードで3周目の入室時に夜から夕暮れへ戻る問題を受け、周回ではなく入室からの実時間で昼→夕暮れ→夜と進めるようにした（利用者の判断）。

## 仕様

- 0〜12分は昼、12〜15分で夕暮れへ、15〜27分は夕暮れ、27〜30分で夜へ、以後は夜のまま（`lighting.ts` の `timeOfDay`）。ステージには依存しない。
- 入室時刻は `useSaunaSession` の `enteredAt`（`Date.now()`）。2D／3Dの切り替えや3Dの再生成後も同じ時間帯から続く。タブが裏にある間も進み、戻ると既存の補間（時定数1.4秒）で追いつく。
- 手動の昼／夕暮れ／夜はこれまでどおり時計より優先する。
- 移り変わり中は時刻が毎フレーム動くため、水面の鏡像の再描画キーは時間帯を0.002刻みに丸める（約0.36秒ごと）。

## 保持を入れた理由（費用）

最初は「0〜15分で昼→夕暮れ、15〜30分で夕暮れ→夜」を一定の速さで進めたが、昼と夕暮れの中間は昼の日光の影（16＋24標本）・夕暮れの暖色灯・2組の照度プローブを同時に描くため最も重い。一時的な計測（標準画質・1280×800・DPR1、既定視点、各4秒を順・逆、[blend-cost.json](blend-cost.json)）：

| ステージ | 昼 | 中間 t=0.25 / 0.5 | 夕暮れ | 夕夜の中間 t=1.5 | 夜 |
| --- | ---: | ---: | ---: | ---: | ---: |
| サウナ | 37.8ms | 68.0 / 68.3ms | 50.2ms | 52.5ms | 56.5ms |
| 水風呂 | 32.1ms | 56.6 / 56.3ms | 43.6ms | 45.7ms | 48.4ms |

入室直後の15分がずっとこの状態になり、`scene-lifecycle.e2e.ts`（180フレームを15秒以内）が失敗し、`scene-touch.e2e.ts` も時刻の変化で画素一致が崩れた（どちらもHEADでは成功）。各シーンを12分保持して中間を3分に限る形に変えた。変更前の自動でも水風呂（t=0.5）は同じ中間の状態だった。中間の描画そのものを軽くする変更はしていない。

## 確認

- `e2e/auto-lighting.visual.ts`：検証ブラウザ内で `Date.now` だけを指定の値に止め、入室から0・12・13.5・15・27・28.5・30・45分の `data-time-of-day`（0/0/0.5/1/1/1.5/2/2）を検査し、3ステージ×8方位を撮影（192枚、`rendererCaptureStyle` でDOM演出を除く）。ステージ変更で時刻が変わらないこと、2D→3Dの再生成後も1.5のまま、手動の昼が優先されることも検査する。96.8秒、ページ／コンソールエラー0件。
- 一覧（ローカル画像）：`sauna.jpg`・`water.jpg`・`totonou.jpg`。13.5分（昼と夕暮れの中間）、28.5分（夕暮れと夜の中間）とも空・壁・水の色が両端の間にあり、帯や破綻は見られない。全標本は [samples.json](samples.json)。
- 水風呂で夕暮れ・夜に水面へ出るクリーム色の平たい斑は、手動の夕暮れでも、DOMを除いた撮影でも、HEADのビルドでも出る（HEADと画素単位で同一）。今回の変更とは無関係の既存の問題として残す（原因は未調査）。
- 撮影は動作抑制ありの静止画で、通常速度で移り変わる様子の動画確認はしていない。
