# 継続利用テストの初回確保を揃える（2026-09-27）

対象は `e2e/scene-stability.soak.ts`。製品の描画・配信モデルは変更しない。

## 再現した失敗

変更前（`2805a61`）のテストは約22秒で `sauna/low` の形状数不一致で失敗した。
初めて水風呂へ移ると形状数が118から126へ増え、サウナへ戻っても126を保持する。
テクスチャは14で一定、未処理ページエラーは0。今回は以前記録された15秒の計測期限切れとは別の失敗。
[変更前の全標本](before.json)。

Three.jsの `WebGLGeometries.get()` は初めて描画した形状を登録・計数する。
`refraction.ts` の側面像は視点ごとに可視性が変わるため、初回入室時と全ステージを表示した後の数は比較できない。

全ステージを表示するだけの試作でも、3D再生成後に126から125になり失敗した。
最初のレンダラーは標準画質で起動しており、軽量画質で再生成したものとは異なり、
水面の鏡像専用の光源メッシュ（`glossyLights.ts`）も登録している。

## 修正

各周回と3D再生成後に高画質で水風呂→外気浴→サウナを表示し、指定画質へ戻す。
これにより初回の描画履歴を揃えてから蒸気を表示・終了し、リソース数を比較する。
同じステージ／画質のテクスチャ数・形状数の厳密な一致、180フレームの計測期限15秒、
全体420秒の期限は維持する。継続時間は実時間5分以上、最低6周回（3画質×昼夕）。
準備の一巡では `setView()` がステージ更新と同期して描画することを確認し、180フレームの
計測は比較用標本でのみ待つ。準備でも計測した試作は4周で約403秒かかり、全体の期限を超えた。

## 中断した実行

重複計測を除いた実行は5周を約241秒で完了し、6周目の外気浴まで28標本でリソース数が一致した。
その後、最後の標本（286.9秒）から終了（779.9秒）まで約493秒の空白が生じ、420秒の期限を超えた。
原因は確定していないため、この実行を5分継続検証の成功とは扱わない。
[中断した実行の全標本](interrupted.json)。再実行はmacOSの `caffeinate -i` を付けてアイドルスリープを防ぐ。
