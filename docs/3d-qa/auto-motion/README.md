# 自動照明の実時間録画（2026-09-29）

自動照明を実際の3分間で動かし、時刻の記録と見回しを含む動画を残す検証。製品コード・配信モデル・照明設定は変更していない。

## 方法

- Chrome／macOS headless、1280×800・DPR1、標準画質、動作抑制なし。庭の読み込み完了後に開始。
- 水風呂は昼→夕暮れ（入室12〜15分）、外気浴は夕暮れ→夜（27〜30分）。入室からの待ち時間だけを省くため、検証ブラウザの `Date.now` にオフセットを一度だけ加える。その後はDate.now・rAF・タイマー・水のアニメーションがすべて実時間で進む。
- 各195秒（3分＋終点15秒）を観察。50〜70秒と110〜130秒にはマウスを約10Hzで左右へ動かし、視点を約±0.5rad振って元に戻す。それ以外は固定視点。画面上の既存演出は残す。
- 約1秒ごとに照明値・ステージ・資源数などのDOM属性と、実際の壁時計・単調時計を採取。照明値の単調増加、目標からの差0.025未満、時計の差250ms未満、標本間隔5秒未満、終点への到達を検査する。同じcanvasが残ること、最後に2Dへ戻れること、ページ／コンソールエラーなしも検査。
- Playwrightの動画には準備と終了操作も含む。WebMを全デコードし、H.264のMP4へ等速変換して再度全デコード。動画全体から等間隔で12フレームを抽出する。一覧の秒数は動画先頭からの時刻で、検証区間の時計とは別。

## 再実行

```sh
bunx playwright install ffmpeg # 初回だけ必要
bun run test:browser:motion --reporter=json > /tmp/sauna-auto-motion.json
python3 scripts/summarize_auto_motion.py /tmp/sauna-auto-motion.json docs/3d-qa/auto-motion
```

集計は失敗・skip・flaky・条件の不足／重複・撮影後の入力変更・条件間の入力不一致を拒否する。通常のブラウザ回帰・静止画撮影・継続利用とは別のconfigで、動画の符号化負荷も分ける。

## 判定の範囲

録画中は符号化の負荷が加わる。25fpsなどの動画の符号化レートはアプリの描画fpsではなく、重複フレームもあり得る。DOMのフレーム時間は開始後180フレームだけの既存計測なので、この区間全体の速度として使わない。資源数は観測値であり、全ステージのウォームアップを含む継続利用のリーク検証ではない。

抽出フレームの目視は連続再生によるちらつき・鏡像の段差の知覚的な合否とは区別する。高画質、サウナ視点、手動切り替えの6秒程度の補間、端末実機、実聴は今回の対象外。
