# 自動照明の実時間録画（2026-09-29）

自動照明を実際の3分間で動かし、時刻の記録と見回しを含む動画を残す検証。製品コード・配信モデル・照明設定は変更していない。

## 方法

- Chrome／macOS headless、1280×800・DPR1、標準画質、動作抑制なし。庭の読み込み完了後に開始。
- 水風呂は昼→夕暮れ（入室12〜15分）、外気浴は夕暮れ→夜（27〜30分）。入室からの待ち時間だけを省くため、検証ブラウザの `Date.now` にオフセットを一度だけ加える。その後はDate.now・rAF・タイマー・水のアニメーションがすべて実時間で進む。
- 各195秒（3分＋終点15秒）を観察。50〜70秒と110〜130秒にはマウスを約10Hzで左右へ動かし、視点を約±0.5rad振って元に戻す。それ以外は固定視点。画面上の既存演出は残す。
- 約1秒ごとに照明値・ステージ・資源数などのDOM属性と、実際の壁時計・単調時計を採取。照明値の単調増加、目標からの差0.025未満、時計の差250ms未満、標本間隔5秒未満、終点への到達を検査する。同じcanvasが残ること、最後に2Dへ戻れること、ページ／コンソールエラーなしも検査。
- Playwrightの動画には準備と終了操作も含む。WebMを全デコードし、H.264のMP4へ等速変換して再度全デコード。動画全体から等間隔で12フレームを抽出する。一覧の秒数は動画先頭からの時刻で、検証区間の時計とは別。

## 再実行

```sh
bunx playwright install ffmpeg # 初回だけ必要
bun run test:browser:motion --reporter=json > /tmp/sauna-auto-motion.json
python3 scripts/summarize_auto_motion.py /tmp/sauna-auto-motion.json docs/3d-qa/auto-motion
```

集計は失敗・skip・flaky・条件の不足／重複・撮影後の入力変更・条件間の入力不一致を拒否する。通常のブラウザ回帰・静止画撮影・継続利用とは別のconfigで、動画の符号化負荷も分ける。

## 判定の範囲

録画中は符号化の負荷が加わる。25fpsなどの動画の符号化レートはアプリの描画fpsではなく、重複フレームもあり得る。DOMのフレーム時間は開始後180フレームだけの既存計測なので、この区間全体の速度として使わない。資源数は観測値であり、全ステージのウォームアップを含む継続利用のリーク検証ではない。

抽出フレームの目視は連続再生によるちらつき・鏡像の段差の知覚的な合否とは区別する。高画質、サウナ視点、手動切り替えの6秒程度の補間、端末実機、実聴は今回の対象外。

## 追記：全フレームの段差・ちらつき解析（2026-09-29）

連続再生での確認の代わりに、同じWebM 2本（`summary.json` のハッシュと一致を検査）の全フレーム（5,019／5,049枚）を320×200の輝度で解析した。`python3 scripts/analyze_auto_motion_frames.py docs/3d-qa/auto-motion` → [frames.json](frames.json)（追跡）と `frames-highpass.png`（ローカル）。人が目で連続再生して見る知覚的な確認ではない。

比べる区間は、照明が変わる区間（観察1〜179秒。見回しの前1秒・後3秒を除く、計130秒）と、照明が止まった終点保持（181〜194秒、13秒）。保持区間との比較は符号化後の画像差の診断に限り、段差・ちらつき不存在の合否には使わない。

| | 水風呂・昼→夕暮れ | 外気浴・夕暮れ→夜 |
| --- | --- | --- |
| 変化なしのフレーム | 811 | 3,073 |
| 前フレームとの差（平均絶対、8bit）の中央値／p99／最大：変化区間 | 0.558 / 1.448 / 2.481 | 0.021 / 0.497 / 1.224 |
| 同：保持区間 | 0.562 / 1.748 / 2.323 | 0.000 / 0.305 / 0.637 |
| キーフレーム前後の差の最大（変化／保持） | 3.485 / 2.556 | 2.187 / 1.929 |
| 画素ごとの時間方向の高周波（平均）：変化／保持 | 0.454 / 0.422 | 0.118 / 0.250 |
| 端点平均差÷500の記述統計（p99／最大。個別更新の上限ではない） | 0.156 / 0.176 | 0.202 / 0.228 |
| 下半分の平均の2.5〜3.1Hz帯（鏡像の更新周期）の強さ（他の帯域比） | 0.537 | 0.716 |

- **最大差の一部はキーフレーム付近に出た。** 静止区間で差が最大の6フレームは、両方の動画ともWebMのキーフレーム（5.12秒ごと）と一致した。キーフレームを除いた変化区間の最大（外気浴76.52秒の1.224）も、画面全体に一様な符号化ノイズ（最大11段階、局所的な形なし）だった。移り変わりの途中で画面が跳ぶ段差は見つからなかった。
- **端点差÷500は個別更新の上限ではない（2026-10-10訂正）。** 変化区間の両端の各1秒平均の差を500で割った記述統計は最大0.18（水風呂）／0.23（外気浴）段階。途中の変化は打ち消し合えるため、1回の鏡像更新をこの値で上限評価できない。2.5〜3.1Hz帯の突出もこの記録では見出していないが、感度・符号化・波の混在があり、段差不存在の根拠にはしない。無劣化PNGのABBA比較と高画質8動画の追加診断は[後続記録](../motion-flicker-20261009/README.md)。
- **局所の高域差を保持区間と比較した。** 20×20画素のブロックで、変化区間の高周波が保持区間の2倍を超え、しかも0.3を超えたブロックは、水風呂の上端の2つだけだった（0.41対0.19・0.42対0.17、空のグラデーションの符号化ノイズ程度）。外気浴は0。水風呂で高周波が大きいのは水際・縁の線と水面で、どちらの区間にも同じように出る（波で動く屈折像）。
- 水風呂の下半分の平均には約1〜1.4Hzの揺れ（振幅約0.7段階）がある。これは保持区間にも同じく出るので、照明ではなく水の波のアニメーション由来。周波数が描画速度とともにずれるため、波（2.1Hz・2.9Hz）の描画間隔による見かけの周波数と見られる（未検証）。
- 変化なしのフレームは、水風呂では描画の遅れ（録画中は約54ms/フレーム）で同じ画が続いたもの。外気浴では動くものがなく、1フレームの照明の変化が8bitの1段階に満たないためと見られる。外気浴の保持区間は変化したフレームが少なく（高周波の標本は2組）、保持区間の高周波は比較に使えない。

**判定の範囲**：数値は符号化後の変化を表す。段差・ちらつき不存在の判定ではない。ただし実際に人が通して見て違和感がないかは、この解析では判定していない。録画はVP8の符号化後の画で、25fpsの時刻に標本化されている。符号化ノイズより小さい変化と、1フレーム未満の変化はこの解析では見えない。
