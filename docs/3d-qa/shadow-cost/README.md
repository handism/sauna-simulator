# 夕暮れの影の描画費用（2026-09-28）

[継続利用検証](../soak-timing/README.md)で、高画質の夕暮れが60fps目標に届かなかったため、影のぼかし（PCSS）の費用を切り分けた。製品の描画・配信モデル・画質設定は変更していない。

## 計測器の修正

既存の `scene-gpu-time.gpu.ts` はすべての `requestAnimationFrame` コールバックをGPUクエリで囲んでいた。UIのアニメーションもコールバックを登録するので、描画が軽い条件ではWebGL描画のない標本が分位点を下げる。初回の硬い影・昼の外気浴では8秒に734コールバックあり、描画フレーム数と一致しなかった。

共通の `e2e/gpu-timer.ts` に移し、取得したWebGL2コンテキストの `drawArrays` / `drawElements` / 各Instanced版の呼び出しを数えて、描画のないクエリを破棄する。ブラウザテストで8回のコールバックのうち4回だけ描画し、標本が正確に4件になることを確認する。変更は検証側のみ。

初回の6条件と通常条件の追試は最終比較から除外した（前者の最初の通常条件はコード検査とも一部重なった）。修正後に全条件を単独で再実行した。過去のGPU時間と今回の値は直接比較しない。継続利用テストの180フレーム計測はアプリ内の別の計測器なので、この不具合の修正対象ではない。

## 条件

- macOS、headless Chrome、1280×800、DPR1、localhost、本番ビルド。バージョン・ハッシュは `results.json`。
- 高画質、動作抑制、庭の追加完了後、蒸気なし、3ステージの既定視点×昼夕。UIは表示。DPR1なので高画質の上限2倍には達しない。
- `shaderSource` を検証ブラウザ内で差し替え、通常のPCSS（遮蔽物探索16＋フィルター24）／半分（8＋12）／硬い影（1参照）を比較する。光源・影マップ・形状・描画数は同じ。硬い影は早期returnでPCSSを使わない。
- 通常→半分→硬い影、その逆の順序で実行。各条件で3秒安定待ち、4秒測定、1秒クエリ回収待ち。10・50・90百分位を保存。拡張がなければskipし、成功とは扱わない。
- アニメーションコールバック内の描画パス全体のGPU時間。影マップと水面の鏡像は静止時に再利用されるため、主に主パス内の影の参照費用を比較している。光源ごとの時間やCPU時間を直接分解するものではない。

## 結果

修正版のブラウザ検証 **7件成功、skip・自動再試行なし**（Chrome 154.0.8037.57、全体344.5秒）。ページ・コンソールのエラー0件。各条件で21個のシェーダーが対象となり、描画数・三角形数は全方式で一致した（サウナ117／646,308、水風呂108／634,142、外気浴82／538,654）。全測定値・検証状態・入力ハッシュは [results.json](results.json)。

同じ順序の通常条件と比べ、標本数半減で夕暮れのGPU時間は **32.7〜40.2%減**。硬い影では昼夕の差も大幅に縮む。画素ごとのPCSS評価が大きな費用であり、影マップを毎フレーム描き直していることが主因ではないと判断した。まず標本数削減の画質を検証する。ただし通常と候補は同時測定ではなく、実行間変動やシェーダーコンパイラの最適化の影響を含むため、影の各処理の時間を足し引きで厳密に分離した値ではない。

半分でも夕暮れは25.43〜43.25msで、GPU描画だけで16.7msを超える。60fps達成や画質維持は確認できていない。初回に見られた通常条件の大きな変動（夕サウナ67→105ms）は最終実行では再現しなかった。原因は特定しておらず、空コールバックの除外だけで安定したとは断定しない。

型検査、35ファイル198単体テスト、Lint、整形、本番ビルド、差分検査成功。3Dチャンク721.37KBの既存警告は継続。製品変更がないため、通常のブラウザ回帰・全周画像・継続利用・帯域制限・Python検証は再実行していない。

## 次の試作と採用条件

1. PCSSの標本数を8＋12へ減らす候補を先に画像で検証する。光源・半影幅・影マップの大きさは固定する。標本配置が変わるため、性能だけで採用しない。
2. Cycles同視点・水風呂ステージ視点・全周の昼夕で通常版と比較し、壁・床の粒状感、葉の影、接触影、水面の鏡像を確認する。定量差と目視所見を残す。見回し中のちらつきも静止画とは別に確認する。
3. 画質を保てる候補だけ、通常／候補を短い間隔で交互に測る。夕暮れの3ステージでGPU時間が繰り返し改善し、通常のブラウザ回帰・継続利用を通ることを採用条件にする。

半減だけで16.7ms以下になるとは限らない。画質差が大きい場合は、光が寄与しない画素の影計算を省く方法や静的な影の焼き込みを別に試す。硬い影をそのまま採用する計画ではない。

## 再実行

```sh

```
