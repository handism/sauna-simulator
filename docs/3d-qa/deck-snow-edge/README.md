# デッキの雪の縁を板ごとに（2026-10-27）

冬の外気浴の正面で、開けたデッキ（屋根の端 z 0.74 より外、〜2.84）の雪が、全部の板を横切る滑らかな波線の縁を持つ一様な白い帯に見えていた。雪ではなく、デッキの上に塗った白い形に見えた。

## 原因

`winterSnow.ts` の開けたデッキの雪は、外縁へ向けて増える値に2つのノイズ（約0.45m・数m周期）を足し、幅0.08のsmoothstepで切っていた（[2026-10-13](../winter-ground/README.md)）。縁は板の向き・継ぎ目と無関係な一続きの曲線で、雪は縁まで同じ厚みの白だった。

## 変更

- 板（世界Z方向、`DECK_BOARDS`：x −0.145 から20cm間隔・幅19cm、外端 z 2.844。本体GLBの `outdoor ash`・`locally damp ash` の頂点から読んだ）ごとに、外端からの雪の奥行きを0.45〜1.05mの範囲で決める（`DECK_SNOW.reach`）。隣の板と独立に決めると鍵盤のような段に見えたため、板をまたいで変わるノイズ（2.2枚周期）と板ごとの乱数を6:4で混ぜる。数m周期の吹きだまりの値で±0.15mずらす。
- 各板の上の縁は、板を横切る方向に細かいノイズ（約7cm・2.5cm周期、深さ12cm）でほつれさせ、最後の6cm（`DECK_SNOW.thin`）で被覆を0から1へ上げる。
- 雪の層の厚み2cm（`DECK_SNOW.depth`）を被覆に掛けて雪の高さ（バンプ）に足し、縁に光の当たる段を付ける。
- 縁が屋根の下・歩く中ほどへ入らないことは単体テストで検査する（最も深い所でも外端から約1.3m以内）。

## 確認

`graphic-fixes.visual.ts`（1280×800・DPR1・標準・固定解像度）の37視点を直前のビルドと比べた。変わったのは冬の4視点（外気浴の正面・左・右、サウナの正面。8階調超の画素は0.5〜1.1%）だけで、ほかの33視点は全画素一致。外気浴・サウナの冬で、縁が板ごとに少しずつずれた雪になり、波線の帯は見えなくなった。

型検査・単体テスト510件・Lint・整形・ビルドが成功。ブラウザ回帰は80件中79件が成功した。残り1件（`frame-rate.e2e.ts` の静止時の間引き）は、軽量への画質切り替えが5秒以内に適用されず失敗した（夏の視点）。単独で3回繰り返すと3回とも成功したため、全件実行中のシェーダーのコンパイル待ちの揺らぎと見ているが、雪のシェーダーが伸びた影響を切り分けてはいない。

## 範囲

静止画の目視で、夕夜の冬・高画質・見回し中・実機は見ていない。描画費用は測っていない（雪のシェーダーに板ごとのノイズ3回分を足した。冬以外も同じプログラムを通るが、`suiOpenDeck` はy<0.5の面だけで計算する）。足跡・雪かきの跡・板の継ぎ目に残る雪はない。
