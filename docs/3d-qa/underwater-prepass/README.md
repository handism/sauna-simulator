# 水中の材質の深度プリパス（2026-09-30、採用）

[深度だけのプリパス](../depth-prepass/README.md)の残件の先頭。水越しに見える面（`SUI_REFRACTION` を定義した材質）は、頂点を屈折した像の位置へ動かし、側面の奥では `discard` するため対象外だった。水風呂の画面の多くを占め、水風呂ステージの残りの時間の大半と見込んでいた。これをプリパスに入れ、**画像を変えずに**水風呂で約3割、サウナで2〜5割GPU時間を減らした。

## 変更

`refraction.ts` の `refractedDepthMaterial(level, side)`：深度だけの `MeshBasicMaterial` の頂点シェーダにだけ `#define SUI_REFRACTION` を加え、照明パスと同じ `project_vertex`（屈折の二分法）で像の位置に描く。断片側の `SUI_REFRACTION` の処理（側面の像の判定・色の減衰）は照明用シェーダの変数を使うため、断片シェーダには定義しない。

照明パスが真の面の断片を捨てるのは、水の箱（`WATER_BOX`）の中で水面より下、かつ元の水の体積（`WATER_VOLUME`）の外にある面（側面の奥の壁。反射率1または壁の層より奥で捨てる）だけ。深度材質はその領域では深度を書かない（1mm広げて丸め誤差を避ける。カメラ・視線の条件は見ず、照明パスが捨て得る範囲を包む）。ここは照明パスが従来どおり描く。プリパスの深度が照明パスで実際に書かれる深度の部分集合になるので、見える面は変わらない。側面の像（レイヤー2）・側面の奥の壁の合成メッシュ（`CustomBlending`）は従来どおり対象外。

`depthPrepass.ts` は `SUI_REFRACTION` を除外する条件を外し、面の向きと水面の高さごとに深度材質を共有する。プリパスのメッシュは78→82。

## 結果

条件：Chrome 154.0.8037.58／ANGLE Metal（Apple M1 Max）、headless、`e2e/frame-cost.gpu.ts`、標準画質・1200×800・DPR1・動作抑制・庭の準備完了後、3ステージ既定視点×昼夕夜。

60fps（16.7ms）に届く条件は増えていない（前回からの外気浴昼のみ。サウナ昼の最良値は17.2ms）。水風呂は昼でもなお36〜39ms。

### 1画素あたりの計算回数

加算合成を強制した照明パスの平均（`overdraw` 添付、[cost.json](cost.json) `overdraw`）：サウナ2.40→2.25、水風呂2.40→2.10（3回以上の画素46%→36%）、外気浴1.18→1.06。残りはガラス・水面・葉など合成やアルファテストの面で、プリパスの対象外。

### 画像

`scene-survey`（216枚）・`cycles-compare`（18枚）・`stage-compare`（12枚）を変更前後で2回ずつ撮り、さらにCycles視点・水風呂ステージを3回ずつ追加した（[cost.json](cost.json) `imageRuns`）。

- 読み込みごとに画像が変わる：変更前の2回の間でもCycles視点9枚・全周のサウナ24枚・外気浴30枚・水風呂ステージ3枚が異なる（床やデッキの孤立したJPEGブロック、最大39レベル）。[既知](../../../e2e/CLAUDE.md)の読み込み間の差。1組の比較では変更の差と区別できない。
- サウナ・外気浴の全周144枚と水風呂ステージ12枚は、変更後のどの撮影も変更前の撮影のどれかと**全画素一致**。
- Cycles視点・水風呂ステージは順序を交互にして各5回撮った。Cycles視点の変化は1回のページ読み込みで撮る視点のまとまり（01・04・05と02・03・07）ごとに起きる。01・04・05の変化は変更前（2回目）と変更後（3回目）の両方に出た。02・03・07は10回中、変更後1回目だけが異なり、変更後の他の4回は変更前と全画素一致した。その差は段・デッキ・床タイルに散る孤立ブロック（03昼で最大30レベル・1,858画素）で、水や水中の面ではない。同じ読み込み間の差と判断した（`imageRuns` の `afterNotInBefore` にはこの9枚が残る）。
- 水風呂ステージは3枚（見出し2）が読み込みごとに2通りに変わり、変更前後とも同じ2通りだけが出た。
- 全周の水風呂72枚は `.cooling-glow` の脈動で毎回異なり比較できない（水中の面は `stage-compare` とCycles視点03で確認）。

## 残件

- 夕暮れ・夜は暖色灯5灯・月の影（PCSS）の計算がなお重い。1画素1回に近づいたので、光源ごとの費用を測り直す。
- 水面（合成）・ガラス・葉は対象外。水風呂の残りの内訳は未測定。
- 他の端末（Windowsの外付け・内蔵GPU、モバイル）での効果は未測定。

## 再実行

```sh
# 変更前はHEADのworktree（node_modulesをリンク）で同じテストを交互に
FRAME_COST_VARIANTS=product bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "frame cost" --reporter=json > after-1.json
bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "per pixel" --reporter=json > overdraw-after.json
bunx playwright test --config playwright.visual.config.ts e2e/scene-survey.visual.ts e2e/cycles-compare.visual.ts e2e/stage-compare.visual.ts
python3 scripts/summarize_frame_cost.py --out docs/3d-qa/underwater-prepass/cost.json \
  --runs standard before=before-1.json,... after=after-1.json,... \
  --images <変更前の撮影> <変更後の撮影> \
  --image-runs before=<撮影1>,<撮影2>,... after=<撮影1>,<撮影2>,... \
  --overdraw overdraw-before.json overdraw-after.json
```
