# GPUタイマーの誇張と、繰り返し描画のフレーム間隔による費用（2026-10-01、計測方法）

[林のカード](../woodland-cards/README.md)の残件「DPR 1.5・高画質のGPU時間」を測る途中で、**ANGLE Metalの `EXT_disjoint_timer_query_webgl2` は、表示間隔（16.7ms）に収まらないフレームで実際のフレーム間隔の約1.8倍を返す**ことが分かった。収まるフレームでは間隔が16.7msに張り付いて差が見えない。そこで1回のrAFで同じフレームをN回描いてGPUを律速にし、フレーム間隔÷Nを1フレームの費用とした。この方法で林のカードの変更を3条件で測り直すと、**記録の「水風呂の夜 0.43倍」は実際には0.83倍**（16.0〜16.4→13.5〜13.8ms）だった。標準画質・DPR 1で全ステージが60fpsに収まるという結論は変わらない。

## 何が起きていたか

条件：Chrome／ANGLE Metal（Apple M1 Max）、headless、`e2e/frame-cost.gpu.ts`（`warmup,product`）、1200×800・動作抑制。

1. **タイマー値がフレーム間隔を超える。** 標準画質・DPR 1.5の6組（林のカードの変更前後を交互）で、水風呂の夜はタイマー42ms、4秒間に描いたフレームは173枚（間隔23ms）だった。GPUがフレームを順に処理するならタイマーは間隔を超えられない。GPU律速の視点ではタイマー÷間隔は1.8〜1.85でそろう（前のフレームを待つ時間も区間に入ると考えられる）。

   | 標準・DPR 1.5（6組の中央値） | タイマー 変更前→後 | フレーム間隔 変更前→後 |
   | --- | ---: | ---: |
   | サウナ 夕暮れ | 31.8 → 15.9 | 17.5 → 16.7 |
   | サウナ 夜 | 33.8 → 17.2 | 18.5 → 16.7 |
   | 水風呂 夜 | 48.9 → 42.2 | 26.7 → 23.1 |
   | 外気浴 夜 | 19.0 → 14.2 | 16.7 → 16.7 |

   変更前の費用がちょうど予算を少し超えていたサウナの夕暮れ・夜では、タイマーが0.50倍を示したが、間隔は予算の上限で止まり、実際の差は分からない。
2. **繰り返すとフレーム間隔÷Nはそろう。** 同じビルド（林のカード後）・標準・DPR 1で、各rAFのコールバックをN回呼んだ（2回目以降は同じ時刻で何も進めず、次のフレームも予約しない）。4秒間のフレーム数から求めた1回あたりの費用は、サウナ夕暮れ 2回10.8・3回10.6ms、水風呂昼 11.6・10.9ms、水風呂夕暮れ 13.2・12.9ms。タイマーは1回13.4→2回42→3回103ms（水風呂昼）と回数に比例しない。
3. **DVFS（GPUのクロック低下）ではない。** 当初は軽いフレームでクロックが下がって12〜14msに張り付くと考えたが、それなら繰り返しで2倍未満に増えるはずで、実際は逆だった。`trivial`（画素シェーダを定数）は2.2〜3.7msで、下限が張り付いているわけでもない。

過去の記録（[深度プリパス](../depth-prepass/README.md)以降のGPU時間）のうち、変更前か変更後が予算をまたぐ視点の比は誇張されている可能性が高い。とくに[林のカード](../woodland-cards/README.md)の水風呂（夕暮れの16ms／30msの二峰性、夜の0.43倍）は、実費用が16ms前後で予算の境目にあったことで説明できる。両方とも予算を大きく超える視点（例：DPR 1の初期の測定の多く）では、タイマーの比と間隔の比は一致した（下の表の「タイマー比」）。

## 変更

- `e2e/gpu-timer.ts`：`timeFrames(repeat)`。`repeat` > 1 は描画したコールバックをその回数呼ぶ。描画したコールバックの時刻を `suiFrameAt` に残す。既定の1は従来どおり（他の `*.gpu.ts` は変更なし）。
- `e2e/frame-cost.gpu.ts`：`FRAME_COST_DPR`（デバイスピクセル比。画質の上限が優先：標準1.5・高画質2）、`FRAME_COST_REPEAT`。各視点に `intervalMs`（フレーム間隔÷repeatの10/50/90百分位と平均）を記録する。個々の間隔は表示間隔の倍数（5.56＝16.7/3、11.1、16.7…）に量子化されるため、**平均を費用とする**。不正な値は例外にする（zshの `set -- $c` が分割されず `"1 1"` が渡り、NaN・0で走った回があった）。
- `scripts/summarize_frame_cost.py`：`--runs` に `beforeIntervalMs`／`afterIntervalMs`／`medianIntervalRatio` を追加。DPR・repeatの混在を拒否する。

## 林のカードの変更の測り直し

HEAD~1（変更前）のworktreeとHEADを交互に4組。値は [cost.json](cost.json) の `comparisons`（`standard-1-3`＝標準・DPR 1・3回、`standard-1.5-2`、`high-2-2`）。1フレームの費用（ms、4組の範囲）。

| | 標準・DPR 1（3回） | 比 | 標準・DPR 1.5（2回） | 比 | 高画質・DPR 2（2回） | 比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| サウナ 昼 | 8.5 → 8.0 | 0.95 | 13.3 → 12.3 | 0.92 | 19.8 → 18.4 | 0.93 |
| サウナ 夕暮れ | 11.9 → 10.6 | 0.89 | 17.6 → 15.4 | 0.87 | 25.6 → 21.3 | 0.83 |
| サウナ 夜 | 12.4 → 11.4 | 0.91 | 18.4 → 16.1 | 0.88 | 26.7 → 22.0 | 0.83 |
| 水風呂 昼 | 12.1 → 11.1 | 0.92 | 19.7 → 18.3 | 0.93 | 29.4 → 27.4 | 0.94 |
| 水風呂 夕暮れ | 15.3 → 13.1 | 0.86 | 23.9 → 21.3 | 0.89 | 35.8 → 32.4 | 0.90 |
| 水風呂 夜 | 16.2 → 13.6 | 0.83 | 25.3 → 21.8 | 0.87 | 37.1 → 32.9 | 0.89 |
| 外気浴 昼 | 6.5 → ≤5.6 | ≤0.85 | 10.3 → 8.6 | 0.84 | 15.1 → 13.1 | 0.87 |
| 外気浴 夕暮れ | 10.2 → 7.6 | 0.74 | 15.2 → 12.2 | 0.81 | 22.0 → 17.9 | 0.82 |
| 外気浴 夜 | 11.3 → 8.1 | 0.72 | 16.2 → 12.9 | 0.80 | 23.3 → 18.5 | 0.80 |

- 4組の範囲は各条件で±2%以内に収まり、変更前後は重ならない。タイマー比も同じ値になった（GPU律速のため）。例外は外気浴の昼・DPR 1で、変更後は3回描いても60fps（16.7/3＝5.56ms）に張り付き、タイマー比は0.39だった。費用は5.56ms以下としか言えない。
- **この機械の60fps（16.7ms）**：標準・DPR 1は変更後の全視点が13.6ms以下。標準画質の上限のDPR 1.5（Retinaの通常表示）では水風呂が18〜22msで届かず、サウナの夜が16.1msでぎりぎり。高画質・DPR 2は外気浴の昼以外は届かない。
- 変更後の1フレームの費用はDPR 1→1.5（画素2.25倍）で1.45〜1.65倍で、画素数に比例しない部分がある（内訳は未確認）。

## 残件

- 過去の変更（深度プリパス・影マスク・水中の材質）を繰り返し描画で測り直すかは未判断。比の向きは変わらないが、予算をまたぐ視点の大きさは誇張されている。
- 他の `*.gpu.ts`（`scene-gpu-time`・`shadow-cost`・`sun-shadow`）は従来のタイマーのまま。同じ注意が必要。
- 繰り返しの2回目以降は鏡像・マスクのパスも描き直すが、静的な影マップは描き直さない。影マップの更新を伴うフレームの費用は含まない。
- 他の端末（Windows・モバイル）、見回し中の粒、継続利用は未確認。

## 再実行

```sh
bun run build   # 変更前はHEADのworktree（node_modulesをリンク、e2eの2ファイルをコピー）でも
# bash で（zsh は "$c" を分割しない）。変更前と変更後を順序を入れ替えながら交互に
FRAME_COST_DPR=1 FRAME_COST_REPEAT=3 FRAME_COST_VARIANTS=warmup,product \
  bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "frame cost" --reporter=json > after-1.json
python3 scripts/summarize_frame_cost.py --out docs/3d-qa/frame-interval/cost.json \
  --runs standard-1-3 before=before-1.json,... after=after-1.json,... --runs standard-1.5-2 ... --runs high-2-2 ...
```

## 検証

型検査、Lint、整形、Python（`test_summarize_frame_cost.py` 10件、3件追加）、GPU計測：DPR 1.5・2の交互6組×2条件（従来のタイマー）、DPR 1・1.5の切り分け各1回、繰り返し1〜3回の5条件、繰り返しの交互4組×3条件。製品コードの変更はなく、単体テスト・ブラウザ回帰・撮影・継続利用は再実行していない。
