# PCSSの標本数を半分にする候補の画質（2026-09-28）

[影の描画費用](../shadow-cost/README.md)で、PCSSの標本数を16＋24→8＋12にすると夕暮れのGPU時間が約33〜40%減ることが分かった。採用条件の2番目（画像と見回し時のちらつき）を検証した。**結論：採用しない。** 製品の定数（`softShadows.ts` の `BLOCKER_SAMPLES`／`FILTER_SAMPLES`）は変更していない。

## 方法

### 1. 多標本の基準との比較（高画質）

`e2e/shadow-samples.visual.ts` が、検証ブラウザ内だけでシェーダーを差し替え（`e2e/shadow-variants.ts`。`shadow-cost.gpu.ts` と共通）、同じ操作で次の4回を撮る：基準（64＋96標本、収束した同じカーネルの代わり）、通常（16＋24）、半分（8＋12）、通常の再撮影。

- 高画質（影マップ2048px）、1280×800、DPR1、動作抑制、庭の準備完了後、画面演出を除いたPNG。
- 3ステージの既定視点×昼夕。各条件で既定視点と、そこから1pxずつ8回ドラッグした視点（1px＝0.004rad）の9枚。
- `python3 scripts/compare_shadow_samples.py sweep <report.json> <出力先>` が、各方式の基準とのCIELAB差（ΔE76）を既定視点で集計し（静止）、同じ視点列での誤差のフレーム間の変化（ちらつき）を集計する。PCSSの標本円盤の回転は画面座標（`gl_FragCoord`）で決まるため、見回すと影の粒が景色に対して流れる。基準自身の残る粒は全方式に共通。

### 2. 既存の撮影での前後比較（標準画質）

HEADのworktree（通常）→定数だけ8＋12にした作業ツリー→HEADの再撮影の順に `bun run test:browser:visual` を実行し、全周144視点・Cycles同視点・水風呂ステージ視点を同名で比べた（`compare_shadow_samples.py pairs`）。全値は [image-comparison.json](image-comparison.json)。

## 結果

撮影は決定的だった：同じ方式の再撮影はどちらの方法でも差0（全周の水風呂は `.cooling-glow` の脈動で差が出るため除く）。定数を戻したビルドで1を再実行し、全値が一致した。

### 目視

切り抜き（左から基準・通常・半分、2倍の最近傍拡大。誤差の最も大きい320×200の区画）：

- [昼のサウナ](crop-sauna-day.jpg)：日の当たる漆喰壁全体に、通常でも細かい粒があり、半分では粗く濃い斑点になる。
- [昼の外気浴](crop-totonou-day.jpg)：寝椅子の側面の布に、半分では網目状の暗い点が出る。
- [夕の外気浴](crop-totonou-evening.jpg)：パーゴラの梁の暗い面に、半分でわずかな斑点。

標準画質の全周・Cycles同視点では、昼の外気浴・庭の視点で変化が大きい（外気浴 昼：平均ΔE 0.98、ΔE>2が平均15.6%・最大32.3%、Cycles同視点 昼：平均0.86、ΔE>2が平均14.2%）。日なたの石の床・デッキの粒が格子状の模様に変わる。夕暮れは平均ΔE 0.02〜0.33と小さいが、ΔE>2の画素は外気浴で平均2.7%、Cycles同視点で3.6%。

## 判断

半分の標本数では、日なたの面に出る影の粒（部分的な自己遮蔽の揺らぎ）が目で分かるほど強まり、見回し時の変化も増える。費用が問題の夕暮れでは差は小さいが、標本数はシェーダーで昼夕共通であり、昼の劣化は許容しない。

副次的な所見：**通常（16＋24）でも、基準に比べて日なたの壁・床に粒がある**（昼のサウナでΔE>2が1.1%）。遮蔽物がないはずの面で遮蔽物探索が一部の標本で当たっていると考えられる（原因は未特定）。

次の候補（画像を変えない、または改善する方向）：

1. 光が寄与しない画素の影計算を省く。three 0.186は `directLight.visible`（スポット光の円錐外・色0）なら `getShadow` を呼ばない条件式だが、`getShadow` 内で `dFdx` を使うため、実際に分岐で省かれているかは未確認。光源ごとの費用を分けて測る。
2. 日なたの粒の原因（遮蔽物探索の半径・傾きのバイアス）を調べる。粒が減れば標本数を減らす余地が出る。

## 限界

- 基準（64＋96）も収束値ではない。同じ標本配置の系列なので、方式間の相対比較に使う。
- ちらつきは1pxずつのドラッグ8回の静止フレーム列で、実際の表示フレームレートや人の知覚の評価ではない。
- この機械（macOS、headless Chrome 154.0.8037.57）のみ。モバイル実機は未検証。

## 再実行

```sh
bun run test:browser:visual e2e/shadow-samples.visual.ts --reporter=json > /tmp/sauna-shadow-samples.json
python3 scripts/compare_shadow_samples.py sweep /tmp/sauna-shadow-samples.json /tmp/shadow-samples
```

`sweep.json` の切り抜きはPNG名で記録され、ここにはそのうち3枚をJPEGで置いた。前後比較は、HEADのworktreeと候補の作業ツリーで `bun run test:browser:visual` を順に実行してから `compare_shadow_samples.py pairs <前> <後> <前の再撮影> <出力.json>` を使う。GPU費用の再確認（`shadow-cost.gpu.ts`、共通化後）は7件成功したが、逆順の通常条件で夕サウナ67→105msの大きな変動が再び出た（前回の初回と同じ現象、原因未特定）。
