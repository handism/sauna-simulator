# 動的解像度（2026-10-02、採用）

DPR 1.5の水風呂の夕暮れ・夜（約18〜19ms）は、画像を変えない工夫でも経路を外す案でも60fpsに届かなかった
（[path-cuts](../path-cuts/README.md)）。利用者と相談し、フレームが予算を超え続けるときだけ画素数を下げることにした。

## 仕組み（`src/components/3d/dynamicResolution.ts`）

- 1秒ごとの窓で平均フレーム間隔を見る。60fpsの予算（16.67ms）の1.1倍（18.3ms）を超えた窓でDPRを0.25下げる。
  下限は画質の上限の6割で、1未満にはしない（標準 1.5→1.25→1、高画質 2→1.75→1.5→1.25、DPR1の画面では何もしない）。
- 表示間隔に張り付いたフレームでは余裕が分からないので、上げは試行：予算の1.04倍以内の窓が10秒続いたら1段上げ、
  上げてから4秒以内に遅い窓が出たら次の試行までの待ちを倍にする（上限160秒）。切り替えのたびに描画先を作り直すため、往復を避ける。
- 下げた段は効いたときだけ残す（2026-10-02追加）：下げた後の最初の窓（切り替え直後の1窓の次）が予算の1.04倍以内か、
  下げる前の遅い窓の9割未満でなければ元の段へ戻し、段下げを保留する。保留は10秒から、効かない段下げのたびに倍（上限160秒）。
  画素数で速くなるのはGPUの画素処理に律速されたフレームだけで、ブラウザがrAFを30fpsに抑える場合（iOSの低電力モード、
  Chromeの省エネモード）やCPU律速では、従来は下限まで下げても速くならなかった。表示間隔の量子化で速さが見えない段下げも戻る。
- 250msを超える間隔（タブ非表示・シェーダのコンパイル・読み込み）は窓を数えずにやり直す。切り替え直後の1窓は判定に使わない。
- 画質の変更でその上限に戻し、ステージの変更で試行の待ち・段下げの保留を10秒に戻す。時間帯の変更では何もしない。
- `?resolution=fixed` で無効（`data-resolution`）。DPRを固定して測る `frame-cost.gpu.ts` が使う。現在値は `data-pixel-ratio`。
- 鏡像・影のマスク・HDRの描画先は描画バッファの大きさに従う（既存の仕組みのまま）。

## 確認

- 単体テスト（`dynamicResolution.test.ts` 9件）：段の作り方、予算内では変えない、遅いと段ごとに下がる、停止を数えない、
  試行と待ちの倍増・上限、成功した試行の維持、画質変更・ステージ変更。
- ブラウザ（`e2e/dynamic-resolution.e2e.ts`、DPR 1.5）：rAFにcanvasの画素数に比例した空回し（1.5で30ms）を挟むと
  1.5→1.25→1（canvasの幅も1200）、外すと1.25へ戻る、画質の変更で上限へ戻る。rAFを1フレームおきにする（30fps上限）と
  1.25へ下げてから1.5へ戻し、保留中は下げない。`?resolution=fixed` では1.5のまま。
- 単体テストには、30fps上限・CPU律速で戻して保留が倍になること、120Hz表示（間隔8.3msの倍数）で12msの場面は変えず
  20msの場面は1.25に留まること、60Hzで表示間隔に隠れる段下げを戻すことを加えた（13件）。
- 実際の重い場面（一時的な観察、[値](observe.json)。Chrome headless・M1 Max・1200×800・DPR 1.5・標準・動作抑制なし）：
  サウナの昼夜・水風呂の昼は1.5のまま60fps。水風呂の夕暮れは1.3秒で1.25に下がり以後60fps。上げの試行は10→20→40→80秒と間が開き、
  1回の試行で平均間隔が17.1〜17.9ms（5秒区間）に落ちるのは約2秒だけ。

## 効かない段下げを戻した後の観察（2026-10-02）

同じ条件で、入室→水風呂→夕暮れ90秒→夜90秒（[値](observe-undo.json)）。水風呂への遷移中の遅いフレームで1.25へ下がり、
その確認窓が夕暮れへの照明の移り変わりと重なって「効かなかった」と判定され、戻された（誤判定）。最初の試作は保留60秒で、
同じ手順で1.5のまま23〜26msのフレームが61.7秒続いた。保留を10秒から倍にする方式にし、同じ誤判定の後も11.1秒で1.25、
13.2秒で1へ下がって60fpsになった。この日は夕暮れ・夜とも1.25でも予算を超えて1まで下がった（09-30の観察では1.25で60fps。
機械の状態による揺れとみる。段の判定自体は従来どおり）。

## 範囲

この機械のChromeでの制御の確認。他の端末（とくにDPR 2〜3のスマートフォン、120Hz表示）での段の選び方・体感は実機で未確認
（30fps上限・120Hzは模擬の確認のみ）。DPR 2〜3でも標準の上限は1.5なので段は同じ（1.5・1.25・1）。
解像度が下がったときの見た目は [resolution-steps](../resolution-steps/README.md)・[resolution-shimmer](../resolution-shimmer/README.md)。
