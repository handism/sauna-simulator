# PCSSの光源ごとの標本数（2026-09-28）

[標本配置の分散低減](../shadow-placement/README.md)を不採用とし、次の候補「光源ごとの標本数（夕暮れで寄与の小さい灯・弱い日光だけ減らす）」を、空を入れた状態（v13、[反射プローブの焼き直し](../reflection-sky/README.md)後）で撮影・計測した。空を入れる前に一度実行した撮影・計測は未集計のまま破棄し、すべて撮り直した。製品の `softShadows.ts` は変更していない。

## 候補

`e2e/shadow-variants.ts` が検証ブラウザ内だけで、一方の光源種別の参照を `getShadow` の複製（`getShadowLite`、定数ループ）へ振り替える。他方の種別は現行の16＋24のまま。

| 名前 | 対象 | 標本数（探索＋フィルタ） |
| --- | --- | --- |
| original | 全光源 | 16＋24 |
| sun-split | 方向光（日光）を複製関数へ振り替えるだけ | 16＋24（分割そのものの費用） |
| sun-half | 方向光 | 8＋12 |
| sun-quarter | 方向光 | 4＋6 |
| spots-half | スポット光（V9・暖色灯） | 8＋12 |

撮影と集計は [PCSSの標本数](../shadow-samples/README.md) と同じ（高画質・1280×800・DPR1・3ステージ×昼夕・既定視点＋1pxずつ8回のドラッグ、基準64＋96、`compare_shadow_samples.py sweep`）。通常の再撮影との差は全条件で0、`sun-split` と現行の差も全条件で0（画像は同一）。

- 夕暮れの sun-quarter は **−12〜−17%**、spots-half は **−28〜−33%**。どちらも全6標本で現行と範囲が重ならない。
- sun-split（関数を2つにするだけ）は誤差の範囲内で、分割そのものの費用は見えない。
- 夕暮れの sun-half は2標本の幅が広く（約±4ms）、減少は確定しない。探索4標本まで減らすと効く。

## 判断

- **夕暮れの日光だけ4＋6標本にする案を製品化の候補とする。** 見た目の差がなく、夕暮れのGPU時間を12〜17%減らす。ただし夕暮れはなお31〜55msで、60fps目標には届かない。
- **暖色灯の半減は採用しない。** 費用の効果は最大だが、半影の粒が目で分かる。
- 製品では昼夕で標本数を切り替える必要がある。三つの方式が考えられ、どれも未実装・未計測：
  1. 標本数をuniformにして可変長ループにする（再コンパイル不要。定数ループより遅くなる可能性があり計測が必要）。
  2. 時間帯ごとの `#define` でシェーダーを作り分ける（切り替え時に再コンパイルの停止が起きる。自動モードは暗転中に切り替わるが、手動の補間中は起こり得る）。
  3. 日光の強度（補間中の値）が閾値以下のときだけ少数標本側を使う分岐（uniformで分岐、両方のループを定数で持つ）。
  昼夕の補間中に標本数が切り替わる瞬間の見え方も確認が必要。

## 限界

- 基準（64＋96）も同じVogel系列の多標本で、収束値ではない。
- GPU時間はこの機械のheadless Chromeでの測定で、表示FPS・CPU・コンポジタの費用やモバイル実機は含まない。候補間の比較にだけ使う。
- 画質は既定視点とその周りの小さな見回しのみ。全周・Cycles同視点は製品化の段階で測る。
