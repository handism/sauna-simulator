# 影の半解像度マスク（2026-10-01、採用）

[光源ごとの影の費用](../light-shadow-cost/README.md)の次の候補「影を画面の低解像度の別パスで評価する」。夕暮れ・夜のGPU時間の約75〜85%はPCSSで、費用は画素数×参照回数に比例していた。不透明な面の影を半分の解像度のパスで1画素1回だけ評価し、本描画はそれを読むだけにした。**夕暮れ・夜のサウナ・外気浴はGPU時間が約4割になり（約35〜41ms→14〜16ms）、この機械の60fps（16.7ms）を下回った。** 水風呂の夕暮れ・夜は0.74〜0.78倍。画像は半影の粒の並びと輪郭の画素だけが変わり、元Cyclesとの誤差は全18視点で±0.01以内。

## 変更

`src/components/3d/shadowMask.ts`（詳細は [3DのCLAUDE.md](../../../src/components/3d/CLAUDE.md)）。

- **マスクのパス**：不透明で影を受ける面（深度プリパスの対象かつ `MeshStandardMaterial`、水中の `SUI_REFRACTION` 材質を除く）に、形状を共有する子メッシュ（レイヤー5、`lights: true` の `ShaderMaterial`）を加えた（78メッシュ）。描画バッファの半分の解像度の32bit floatターゲットに、深度プリパスの子を描いてから、日光と影付きスポット光6灯の影の係数を従来と同じPCSSで評価する。係数は8bitずつ3つを1チャンネルに詰め、残る2枠に頂点法線（八面体符号化）、アルファにビュー深度を書く。
- **本描画**：元の材質に `SUI_SHADOW_MASK` を定義する。近傍4テクセルのうち、深度と法線が自分の面と合うものを双線形で補間する。合うものがない画素（輪郭・溝・半解像度より細い部分）は、影マップを1回だけ引く硬い影にする。
- **水面の鏡像**：鏡像のカメラ・描画範囲の大きさのマスクを別のターゲットに描く（`createPlanarReflection` の `beforeDraw`）。
- HDR出力のない端末・軽量画質（影なし）では使わない。半透明・アルファテスト（葉）・水中の材質・側面の像は従来どおりPCSSを自分で評価する。

### 途中で分かったこと

1. **実行されないPCSSが残るだけで遅い。** 最初の版は、深度が合わない画素だけ従来のPCSSを評価する分岐にした。ほぼ全画面でマスクが使われているのに、GPU時間はHEADとほぼ同じだった（サウナ夕暮れ 41.1／43.1ms）。分岐を消してPCSSを死んだコードにすると13.7msになった。マスクのパスの画素シェーダを空にしても変わらず（39.3ms）、マスク自体はほぼ無料だった。展開された16+24標本×7灯のコードが本描画のシェーダにあるだけで、評価したのと同じだけ遅い。[前回](../light-shadow-cost/README.md)の「1灯ずつ外しても足し算にならない」「ループ展開を止めると遅い」とも合う（レジスタ割り当て・占有率の問題と見られるが、ANGLE Metalの内部は確かめていない）。本描画では `getShadow`・`suiSunShadow` を1回参照の関数に `#define` で置き換え、PCSSの関数は呼ばれず消えるようにした。
2. **影マップが空になる。** threeの静的な影マップは、更新が必要になった後の**最初の** `renderer.render` で、そのカメラのレイヤーにある物体から描かれる。最初の描画がマスクのパス（プリパス用のレイヤーだけ）だと、投射物のない影マップになり、以後そのまま残った。この状態で測った最初の「高速化」は影がないためで無効。更新が必要なフレーム（読み込み・画質変更）は、マスクの前に元のレイヤーで一度描くようにした。その描画中はマスク自身を読まない（読むとWebGLのフィードバックループのエラーになった）。あわせて、threeはカメラのレイヤーにある光源だけを集めるので、光源にもマスクのレイヤーを足した。
3. **詰めた値の丸め。** 復元の `floor( v + 0.5 )` は、全灯が影なしの値 2²⁴−1 を float32 で 2²⁴ に丸め、日光・V9の値が0になった。`round` にした。
4. **溝の漏れ。** 合うテクセルがない画素に「深度が最も近いテクセル」を使うと、天井の板の溝（暗い）に隣の板の明るさが点線状に漏れた（Cycles 02昼の誤差が+0.15）。1回参照の硬い影にしても残った。溝の側面は板とほぼ同じ深度で、深度の許容を通っていたためである。法線（内積0.9以上）でも判定して解消した。

## 結果

条件：Chrome 154.0.8037.58／ANGLE Metal（Apple M1 Max）、headless、`e2e/frame-cost.gpu.ts`、1200×800・DPR1・動作抑制・庭の準備完了後、3ステージ既定視点×昼夕夜。HEADのworktreeと順序を交互にした。

- 変更途中の版で、サウナ夜だけ組ごとに15〜28msの二峰性が出たことがある。最終版では出ていない（6組とも15.9〜16.2ms）。原因は確かめていない。

### 画像

`scene-survey`（216枚）・`cycles-compare`（18枚）・`stage-compare`（12枚）を各版2回ずつ撮った。各版の2回の間の差は、全周の水風呂（`.cooling-glow` の脈動）を除けば読み込み間の孤立した画素だけ（Cycles視点の平均ΔE 0.0003／0.0008、水風呂ステージは一致）。変更前後の差は [cost.json](cost.json) `imageDelta`（CIELAB ΔE76）。

| | 平均ΔE | ΔE>2 | ΔE>5 | 中央部のΔE>5 |
| --- | ---: | ---: | ---: | ---: |
| Cycles視点（18枚） | 0.48 | 7.0% | 0.71% | 0.79% |
| 全周（216枚） | 0.64 | 9.6% | 3.1% | 0.27% |
| 水風呂ステージ（12枚） | 0.10 | 1.1% | 0.16% | 0.30% |

- 差は、半影の粒の並び（標本の回転が半解像度の画素ごとになった）と、輪郭・細い部材の画素に散る。等倍でも見分けにくい。全周の最大はΔE>5が23%の水風呂だが、これは脈動による縁の差で、中央部は0.27%。
- 元Cyclesとの平均ΔE（600×400、[cycles-error.json](cycles-error.json)）の変化は全18視点で−0.004〜+0.009。

## 残件

- 水越しの面（`SUI_REFRACTION`）をマスクに入れると、水風呂の残り（昼34ms・夕夜42〜46ms）が減る見込み。頂点を屈折した像の位置へ動かし、側面の奥では `discard` するので、深度プリパスの `refractedDepthMaterial` と同じ扱いが要る。
- 葉（アルファテスト）・半透明は対象外のまま。
- 標準画質の実際のDPR 1.5、他の端末（Windowsの外付け・内蔵GPU、モバイル）での効果は未測定。「PCSSのコードが残るだけで遅い」は他のGPUのコンパイラでは違う可能性がある。
- 見回し中の粒の流れ（半解像度で標本の回転が粗くなった）の連続再生での見え方は確認していない。

```sh
bun run build   # 変更前はHEADのworktree（node_modulesをリンク）で同じテストを交互に
FRAME_COST_VARIANTS=product bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "frame cost" --reporter=json > after-1.json
FRAME_COST_QUALITY=high FRAME_COST_VARIANTS=product bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "frame cost" --reporter=json > high-after-1.json
bunx playwright test --config playwright.visual.config.ts e2e/scene-survey.visual.ts e2e/cycles-compare.visual.ts e2e/stage-compare.visual.ts
python3 scripts/summarize_frame_cost.py --out docs/3d-qa/shadow-mask/cost.json \
  --runs standard before=before-1.json,... after=after-1.json,... \
  --runs high before=high-before-1.json,... after=high-after-1.json,... \
  --image-delta <変更前の撮影> <変更後の撮影> \
  --image-runs before=<撮影1>,<撮影2> after=<撮影1>,<撮影2>
```
