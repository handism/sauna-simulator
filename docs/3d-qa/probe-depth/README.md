# 補間元プローブの距離による重みと、閉じ込められたプローブの診断（2026-09-24）

**診断のみ。製品の描画コード・配信データ・元blendは変更していない。** 前回の [可視性診断](../probe-visibility/README.md) で見つかった寝椅子付近の不足（面近傍の測定に対して昼0.67倍）について、二値の可視性の代わりに距離による滑らかな重みを試した。安価な代替としてプローブ値を埋め直す案も、ブラウザで同じ視点から撮影して評価した。

## 1. 距離モーメントによる重み（DDGI方式）

`diagnose_probe_depth.py` は各補間元プローブから測定点の方向へcos^50ローブの64本のレイを飛ばす。最初に当たった距離の平均と二乗平均を記録する（外れた場合と距離の上限は2格子対角）。フィルタ済みの八面体深度マップの代わりに使っており、量子化は含まない。`compare_probe_weights.py` がCPU上でChebyshevの可視性 `var/(var+(r-μ)²)`（3乗）、DDGIの裏面の重み `((cos+1)/2)²+0.2`、DDGIの切り詰め（0.2未満を3乗に比例して弱める）、および正則化εを組み合わせる。正則化は `(Σtvc+εΣtc)/(Σtv+ε)` の形で、見える重みが小さい場合は通常の三線形補間へ戻す。評価の基準は前回の面から2cm／5cmでの余弦積分。表の値は14点×昼夕×2オフセット＝56条件での平均 |log2(補間/測定)|（Rec.709輝度）。

| 候補 | 参照点：面から2cm／5cm | 参照点：実行時と同じ半格子 |
| --- | ---: | ---: |
| 現行（三線形） | 0.218 | 0.218 |
| 裏面の重みのみ | 0.180 | 0.180 |
| Chebyshev | 0.191（最大3.20倍） | **0.184**（最大は現行と同じ1.846倍） |
| DDGI（Chebyshev×裏面） | 0.175 | 0.169 |
| 二値の線分可視性（前回） | 0.134 | — |
| 二値＋正則化ε=0.1 | 0.147 | — |

- **半格子の参照点でのChebyshevは、寝椅子付近 `04-400-290` だけを変える**：昼0.670→0.927、夕0.615→0.849（2cm基準。5cm基準もほぼ同じ）。他の13点は1%未満の変化。寝椅子の下の隙間にある2つのプローブ `courtyard [15,0,8]`（補間重み0.251、照度輝度0.035）と `[15,0,7]` は、測定点方向の平均距離が0.10／0.35mと、測定点までの距離0.69／1.11mより近い。このため重みがほぼ0になる。
- 面から2cmの点を参照すると、シダの下の地面 `01-ground-dark` が昼1.735→3.012倍に悪化する。最も重い暗いプローブ（重み0.817）がローブ内の葉に遮られて外れ（平均0.21m＜距離0.37m）、明るいプローブだけが残るため。薄い葉を幾何的な遮蔽として扱う限界であり、面近傍の参照は採らない。
- 二値の線分判定で問題になった草付近 `05-270-300`（2cmで残存重み0.0004を1.301倍へ増幅）は、2cm参照のChebyshevでは0.926倍になり、増幅しない。正則化εは増幅を抑えるが（ε=0.1で0.723倍）、同時に改善も打ち消す（二値の全体0.134→0.147）。
- 裏面の重み（DDGIの一部、追加データ不要）は `05-270-300` を0.72→0.86倍に改善する。一方で `01-320-280` を0.90→0.86倍に悪化させ、多数の点を1〜4%動かす。単独では採用根拠にならない。

## 2. 閉じ込められたプローブの埋め直し（不採用）

実行時のコストがかからない代替として、ベイクと同じ `fill_invalid` で周囲の狭いプローブを近傍から埋め直す案を試した。`survey_probe_enclosure.py` は全4,832プローブから全方向64本のレイを飛ばし、空き距離の平均・最小と、1格子以内で何にも当たらない方向の割合を記録する（Blender 4.5.11、837秒、昼夕で表示対象の形状は同一）。寝椅子の下の `[15,0,8]` は横に開いているため平均0.356格子あり、閾値0.4格子で初めて対象になる（室内1・中庭40・外周47の計88プローブ）。

- 14点では寝椅子付近だけが改善する（昼0.670→0.872、夕0.615→0.813）。他の点の変化は1%未満。
- 同視点撮影（作業用コピーの本番ビルド、配信データだけ差し替え）では、元7枚の平均|ΔL*|が1.45→1.49、夕暮れは0.96→1.00になった。変化した画素（|ΔL*|>1）に限っても、多くの視点でCyclesから遠ざかる：04昼（4.94%）10.36→10.94（符号付き−0.86→+1.69）、01昼 8.23→8.98、04夕はほぼ同じ（5.08→5.04）。改善は室内02のみ（9.92→9.08）。[比較画像](comparison.jpg) の差分は、寝椅子の陰になる石床と手前のデッキに集中する。**埋め直したプローブは下の床も明るくし、光が漏れる。** 寝椅子の上面だけを直すには、画素ごとに補間元を選ぶ（1.の方式）必要がある。
- 変更前の撮影は前回の [probe-sampling/baseline](../probe-sampling/baseline/) とJPEGがバイト単位で一致したため、再保存していない。候補は [refill/](refill/)（`irradiance.bin` のハッシュ `d5f6e22c…`。撮影時のjsonは説明用のキーが1つ多い）。

## 限界と次の判断

1.の結果は14点の点診断。画面全体・GPU負荷は測っていない。製品化するには、中庭と室内の3,068プローブの八面体深度（例：8×8・RG16Fで約785KB、現行の照度データは522KB）の焼き込みが必要になる。シェーダーでも、ハードウェアの三線形補間を8隅の手動補間に置き換える必要がある（テクスチャ取得が約8倍）。葉・ガラスの扱い（遮蔽に数えない材質の指定）も未設計。寝椅子付近1点の改善に対して費用が大きいため、今回は実装しない。サウナ床の昼の過剰（全補間元が見えており、どの候補でも1.31〜1.34倍のまま）は可視性の問題ではない。

## 再実行

```sh
B=/Applications/Blender.app/Contents/MacOS/Blender
$B -b blender/scene/SUI_Retreat.blend --python-exit-code 1 --python scripts/diagnose_probe_depth.py -- --out /tmp/sauna-probe-depth
python3 scripts/compare_probe_weights.py /tmp/sauna-probe-depth/depth.json --out /tmp/sauna-probe-depth/weight-ratios.json
$B -b blender/scene/SUI_Retreat.blend --python-exit-code 1 --python scripts/survey_probe_enclosure.py -- --out /tmp/sauna-probe-enclosure
python3 scripts/refill_enclosed_probes.py /tmp/sauna-probe-enclosure/enclosure.json --threshold 0.4 --write <作業用コピー>/public/models
python3 -m unittest discover -s scripts -p 'test_probe_sampling.py'
```

撮影は作業用コピーで `bun run build` の後に `bunx playwright test --config playwright.visual.config.ts e2e/cycles-compare.visual.ts --reporter=json` を実行し、`scripts/cycles_tone_stats.py <撮影先>` で統計を取る。`--write` に `public/models` は指定できない。

- `depth.json`：補間元ごとの距離モーメント（2cm・5cm・半格子の3参照点）。
- `weight-ratios.json`・`weight-summary.txt`：候補ごとの比と集計。
- `enclosure.json`：全プローブの空き距離（`irradiance.bin` と同じx→y→z順）。
- `refill-points.txt`・`refill-tone-stats.txt`・`refill-pixel-changes.txt`：埋め直し候補の点・画面統計・変化画素の集計（変化画素は変更前後の撮影を600×400でL*比較した一時スクリプトの出力。閾値|ΔL*|>1）。
- `validation.json`：採否・ハッシュ・検証範囲。
