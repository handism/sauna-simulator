# PCSSの標本配置の分散低減（2026-09-28）

[夕暮れの日光の4参照PCF](../sun-pcf/README.md)を不採用とし、距離に応じた半影を保つまま、標本の置き方で基準（64＋96）との誤差と見回し時の変化を下げ、標本数（費用）を減らせるかを調べた。**結論：採用しない。** 製品の `softShadows.ts` は変更していない。

## 候補

`e2e/shadow-variants.ts` が検証ブラウザ内だけでPCSSのシェーダーを差し替える（カーネル・半径・影マップは同じ）。

| 名前 | 内容 | 標本数 |
| --- | --- | --- |
| original | 現行。Vogel円盤を画素ごとのノイズ（`gl_FragCoord`）で回転 | 探索16＋フィルタ24 |
| jitter | 回転に加え、Vogelの半径 `sqrt((i+0.5)/n)` の0.5を画素ごとの別ノイズにする（全画素が同じ同心円に並ぶのを崩す） | 16＋24 |
| adaptive-a-b | フィルタをまずa標本で求め、全部日なた／全部影ならそこで終了。それ以外（半影）だけ別の回転の円盤でb標本を足す | 16＋a（半影は a＋b） |
| blocker-64 / filter-96 | 基準の片方の段だけ多標本にした切り分け | 64＋24 / 16＋96 |

撮影と集計は [PCSSの標本数](../shadow-samples/README.md) と同じ（高画質・1280×800・DPR1・3ステージ×昼夕・既定視点＋1pxずつ8回のドラッグ、`compare_shadow_samples.py sweep`）。全実行で通常の再撮影との差は0。

## 結果

基準との静止誤差の平均ΔE76（括弧内はΔE>2の画素%）。見回し時の変化（誤差のフレーム間の変化）も同じ傾向。全値は [sweep-placement.json](sweep-placement.json)、[sweep-decomposition.json](sweep-decomposition.json)、[sweep-adaptive.json](sweep-adaptive.json)。

| 条件 | original | jitter | adaptive-8-24 | adaptive-8-40 | adaptive-16-32 | blocker-64 | filter-96 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| サウナ 昼 | 0.139 (1.07) | 0.139 (1.08) | 0.150 (1.33) | 0.136 (1.09) | 0.124 (0.76) | 0.118 (0.60) | 0.084 (0.41) |
| サウナ 夕 | 0.024 (0.05) | 0.024 (0.05) | 0.026 (0.06) | 0.024 (0.05) | 0.021 (0.04) | 0.019 (0.01) | 0.014 (0.03) |
| 水風呂 昼 | 0.067 (0.55) | 0.067 (0.56) | 0.072 (0.63) | 0.067 (0.54) | 0.060 (0.42) | 0.052 (0.28) | 0.037 (0.27) |
| 水風呂 夕 | 0.026 (0.14) | 0.026 (0.14) | 0.028 (0.18) | 0.027 (0.16) | 0.023 (0.11) | 0.020 (0.08) | 0.014 (0.06) |
| 外気浴 昼 | 0.190 (1.98) | 0.189 (1.98) | 0.201 (2.16) | 0.187 (1.96) | 0.176 (1.79) | 0.124 (0.50) | 0.135 (1.51) |
| 外気浴 夕 | 0.050 (0.30) | 0.051 (0.31) | 0.059 (0.43) | 0.053 (0.36) | 0.045 (0.22) | 0.042 (0.22) | 0.022 (0.08) |

- **jitter：効果なし**（差は±1%以内）。回転だけで半径方向も十分に散っている。
- **adaptive-8-x：悪化または同等**。8標本が全部日なたでも、真の日なた率0.9の画素では約43%の確率で起こるため、薄い影を1.0に丸める偏りが出る。
- **adaptive-16-32：全6条件で改善**（平均 −7〜−12%、ΔE>2 −10〜−29%、見回し時の変化 −9〜−11%）。adaptive-12-36はその中間。
- 切り分け：フィルタを96にすると誤差は約29〜57%、探索を64にすると約15〜35%減る。誤差は両段の標本数で決まり、置き方で減らせる余地は小さい。外気浴の昼は探索側の寄与が大きい（ΔE>2が1.98→0.50%）。

目視（左から基準・現行・adaptive-16-32、2倍拡大）：[昼のサウナの漆喰壁](crop-sauna-day.jpg)、[昼の外気浴](crop-totonou-day.jpg)。adaptive-16-32でも壁の粒はわずかに細かくなるだけで残る。

## 判断

- 標本の置き方（半径の層化・適応標本）では、同じ費用のまま誤差を下げることも、誤差を保ったまま費用を下げることもできなかった。**採用しない。**
- adaptive-16-32は画質を少し上げる代わりに夕暮れを重くし、60fps目標から遠ざかる。
- 残る粒と費用はどちらも「画素ごとに毎フレーム全標本を評価する」構造から来ている。次の候補は構造を変えるもの：光源ごとの標本数（夕暮れで寄与の小さい暖色灯・弱い日光だけ少なくする）、または影の画面空間での低解像度評価＋ぼかし／時間方向の蓄積。後者は描画パスの追加を伴う。

## 限界

- 基準（64＋96）も同じVogel系列の多標本で、収束値ではない。
- GPU時間は1組（順・逆）のみ。この機械の実行間のばらつき（±10%以上）より差が大きい夕暮れだけを根拠とし、昼の差は確定しない。
- ちらつきは1pxずつ8回の静止フレーム列で、表示フレームレートや知覚の評価ではない。モバイル実機は未検証。

  bun run test:browser:visual e2e/shadow-samples.visual.ts --reporter=json > /tmp/placement.json
python3 scripts/compare_shadow_samples.py sweep /tmp/placement.json /tmp/placement
# 切り分け：SHADOW_CANDIDATES=blocker-64,filter-96 ／ 適応：SHADOW_CANDIDATES=adaptive-12-36,adaptive-16-32
SHADOW_COST_VARIANTS=original,adaptive-16-32,adaptive-12-36 \
