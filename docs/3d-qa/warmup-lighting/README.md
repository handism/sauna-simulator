# 分割準備中の時間帯変更（2026-10-07）

製品の `?warmup=split` に対する `e2e/scene-warmup.e2e.ts` の回帰検証。描画コード・配信モデルは変更せず、時間帯変更の2ケースを追加した。

## 方法

```sh
# ローカルpreviewのlistenが可能な環境で実行。buildを含む。
bun run test:browser e2e/scene-warmup.e2e.ts --reporter=json > /tmp/sauna-warmup-regression.json
```

`readPixels` に150msの待ちを入れ、キャッシュが温まっていても各ステップでブラウザへ処理を返させる。新しい2ケースは動作抑制あり、開始時の時間帯は昼。設定の各変更後に `data-warming` が対象の準備段階を保っていることを検査し、準備が終わってから選んだテストにならないようにする。

| 対象 | 準備中の選択順 | 完了後・水風呂への移動後 |
| --- | --- | --- |
| 本体 | 夜→夕暮れ | `lighting=evening`、`timeOfDay=1.000` |
| 庭 | 夕暮れ→夜 | `lighting=night`、`timeOfDay=2.000` |

両ケースで同じcanvas、本体／庭GLBそれぞれ1回だけの取得、分割方式での準備完了、本体／庭の描かれなかったグループ0件、ミュート状態の維持、ページエラーなしも検査する。`warmup-lighting` 添付にブラウザ版・設定順・取得URL・完了後の属性を残す。

## 結果

Google Chrome 154.0.8037.98、1280×800・DPR1。追加2件を単独実行して成功後、温め回帰6件すべてが再試行なしで成功（約114秒）。[検証記録](validation.json)に最終レポートのハッシュ、ソース・配信物・テスト入力のハッシュ、6件の結果と時間帯2件の添付内容を保存した。

既存4件は画質変更、庭の準備中のリサイズ／ステージ変更、2D切り替え／コンテキスト喪失、30秒期限と手動再試行。期限ケースは読み戻しを1秒遅らせる。型検査、48ファイル315単体テスト、Lint、整形、本番ビルド、差分チェックも成功。

## 範囲

確認したのは手動設定の反映と継続動作。最初に表示されたフレームの画素一致、庭準備中の保持画像、自動時間帯の移り変わり、見回し、非HDR、WebKit・Safari・モバイル実機、音の実聴は対象外。待ちを加えた属性値を読み込み速度やGPU性能の数値として使わない。ページエラーの検査であり、consoleログ全件の無エラーを主張しない。

前回の標準・夜の最大2画素差と全周比較は未解決のまま。今回の成功だけでは分割準備を既定にしない。
