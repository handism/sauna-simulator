# 林のカードの見回し中のちらつき（2026-10-02、採用）

[動的解像度の段と見回し中のちらつき](../resolution-shimmer/README.md)の残件「葉のちらつき自体（1.5でも残る）」。
**ちらつきの約半分は遠景の林のカード（`leafCluster.ts`）で、近景の葉・Fine canopy・シダはほぼ寄与しなかった。**
遠いカードだけ alpha to coverage の閾値の遷移を広げ、面の残差を1.5で0.72〜0.81倍、全段で0.72〜0.85倍にした。林の平均の明るさは変えない。

## 方法

- 撮影・指標は [resolution-shimmer](../resolution-shimmer/README.md) と同じ（`e2e/resolution-shimmer.visual.ts`、Chrome headless・M1 Max・1200×800・DPR 1.5・標準画質・動作抑制、
  3ステージ既定視点×昼・夕暮れ、1フレーム1 CSS px のドラッグ13フレーム、回転で重ねたL*の残差を12×12画素の面で平均）。切り分けと候補の比較は段1.5だけを撮った。
- 切り分けは一時的な変更（コミットしない）：`prepareModel` で材質名が正規表現に合うメッシュを非表示にし、葉のグループを1つずつ消して撮った。
  非表示は影・深度プリパス・影マスクの子メッシュも消す。消した後ろの面（空・林の奥）の分は残差に残る。
- 林の明るさ：基準とカードを消した画像でL*が2以上違う画素（林のカードが写る画素、画面の3〜8%）の平均L*を、各候補で基準からカードなしへ何割動いたか（0なら同じ明るさ、1なら全く透ける）で見た。
- 候補はURLパラメータで切り替える一時ビルド1つで撮り、採用案は定数にした最終ビルドで3段とも撮り直した（1.5の値は一時ビルドの同じ設定と一致）。

- 残り（約0.4〜0.5）を当初は柱・縁・屋根の線などの幾何の縁としたが誤り。葉を消すと後ろの枝・幹が空を背に見えるようになる分を含み、葉と樹皮をまとめて消すと0.17〜0.43倍になる（[crown-shimmer](../crown-shimmer/README.md)）。
- 前回の残差の分布（林・庭の葉に集中）は、ほぼ全部が林のカードだった。カードは遠く、20枚の葉の型の1枚が1画素前後になる。

## 候補（段1.5、6系列の平均と範囲）

カード由来の残差＝基準−カードなし。「残存」はその何割が残ったか。

| 候補 | カード由来の残存 | 林の明るさの移動（0＝不変） | 林の画素の平均\|ΔL*\| |
|---|---|---|---|
| ミップの平均被覆をそのままalpha to coverageへ（閾値なし） | 0.34（0.32〜0.37） | 0.47（0.31〜0.60） | 15.0 |
| 遷移の半幅0.1 | 0.67（0.58〜0.73） | −0.12（−0.14〜−0.08） | 7.5 |
| **遷移の半幅0.2（採用）** | **0.57（0.50〜0.63）** | **−0.01（−0.08〜0.05）** | 8.4 |
| 遷移の半幅0.35 | 0.47（0.41〜0.52） | 0.18（0.06〜0.28） | 10.6 |
| 遷移の半幅0.5 | 0.40（0.36〜0.44） | 0.34（0.20〜0.45） | 12.8 |
| 異方性フィルタ8× | 1.07（1.04〜1.11） | 0.32（0.20〜0.42） | 13.7 |
| 異方性フィルタ4×＋半幅0.2 | 0.74（0.64〜0.80） | 0.07（−0.03〜0.15） | 11.8 |

- **平均被覆をそのまま使う案は林を大きく透かす**：重なったカードが同じalphaのとき、alpha to coverageは同じサンプルを覆う（WebGL2ではサンプルマスクを選べない）。
  奥行き方向に重なる冠の被覆が足し合わさらず、平均の明るさが空の方へ約半分動いた。閾値で切る従来の方式は重なりを正しく合成する。
- 遷移を閾値の両側へ対称に広げると、広げるほどちらつきは減るが、0.35以上では透け始める。0.2で明るさの偏りがほぼ0になった。
- 異方性フィルタは斜めのカードで細かいミップを読むため、閾値の前の平均で被覆が痩せ（係数の再調整は等方ミップ前提）、ちらつきも減らなかった。
- 0.2では斜めに見えるカードの葉が長軸方向に少しにじむ（等方ミップのぼけが半透明に見える）。等倍の目視では遠景の冠が柔らかくなる程度で、不自然な模様は出ない。

## 変更

- `leafCluster.ts`：`suiLeafCoverage( alpha, uv )` を照明パスの `alphatest_fragment` と置き換える。1画素あたりのテクセル数（level 0のUV微分の長い方）が1→2で、
  閾値0.5の遷移の半幅を `fwidth( alpha )` から `LEAF_FAR_RAMP`（0.2）へ広げる（`smoothstep( 0.5 − w, 0.5 + w, alpha )`）。近いカードは従来の `smoothstep( 0.5, 0.5 + fwidth, alpha )` とほぼ同じ（下側へも1画素分広がる）。
  それまでの `onBeforeCompile` と合成する。
- `depthPrepass.ts`：カードの深度の複製は同じ関数で被覆が1になる画素だけ深度を書く（従来の `a ≥ alphaTest + fwidth( a )` と同じ考え方）。遠いカードで被覆1の画素が減る。
- `shadowMask.ts`：カードの影マスクは同じ関数で被覆が0でない画素に書く（照明パスが葉を残す画素）。`suiAlphaTest` uniform は不要になった。
- 影マップの描画（three標準の深度材質）は従来の閾値0.5のまま。

| 変更後÷変更前 | 面の残差 | 面の99パーセンタイル | 画素の残差 |
|---|---|---|---|
| 1.5 | 0.72〜0.81 | 0.59〜0.74 | 0.85〜0.89 |
| 1.25 | 0.75〜0.83 | 0.65〜0.76 | 0.85〜0.89 |
| 1 | 0.79〜0.85 | 0.68〜0.83 | 0.86〜0.90 |

- 段ごとの比（1.25・1の1.5に対する比）は1.2・1.5倍前後のままで、低い段ほど葉の明滅が増える関係は変わらない。
- 変更後の1・1.25の面の残差（例：外気浴昼 0.227・0.180）は、変更前の1.25・1.5（0.217・0.177）に近い。

## GPUの費用

`e2e/frame-cost.gpu.ts`（製品のみ、標準画質・DPR 1.5・繰り返し2回、`?resolution=fixed`）をHEADのworktreeと交互に2組。1フレームの費用は繰り返し描画のフレーム間隔（ms）。

| 視点 | 変更前 | 変更後 | 比 |
|---|---|---|---|
| サウナ 昼／夕暮れ／夜 | 11.8／14.8／15.7 | 11.9／15.1／15.9 | 1.01／1.02／1.02 |
| 水風呂 昼／夕暮れ／夜 | 15.1／18.2／18.7 | 15.2／18.4／19.1 | 1.01／1.01／1.02 |
| 外気浴 昼／夕暮れ／夜 | 8.6／12.1／12.8 | 8.9／12.4／13.2 | 1.04／1.02／1.03 |

- +0.1〜0.4ms。遠いカードで被覆1の画素が減り、深度プリパスが隠せない奥の面の照明が増える分と見ている（内訳は測っていない）。60fpsの予算をまたいだ視点はない（水風呂の夕暮れ・夜はもともと超えている）。
- 最初の計測は集計スクリプト（CPU負荷）と重なったので捨てて測り直した。

値は [values.json](values.json)。面の残差の分布（`tiles-*.png`、左から1.5・1.25・1）はローカルのみ。

## 範囲

L* の静止フレーム列の比較で、知覚的なちらつきの合否ではない。1フレーム1 CSS px のゆっくりした見回し、DPR 1.5のこの機械だけ。Cycles画像との比較はしていない（冠の模様は変わるが平均の明るさは保つ）。
アルファの遷移は画面の画素基準なので、DPRや動的解像度の段が変わると遷移が始まる距離も変わる。
