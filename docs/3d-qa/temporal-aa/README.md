# 時間方向の蓄積（TAA）（2026-10-03、ずらしなしを採用）

[見回し中のちらつきの残りの切り分け](../crown-shimmer/README.md)で候補に挙げた、時間方向に標本を重ねる方法の試作。製品コードの変更はない（`?taa=1` の一時ビルドで測った）。
**見回し中の面の残差は、静止画を変えない「ずらしなし」で0.54〜0.58倍、サブピクセルのずらしを加えると0.35〜0.47倍になった。** フレーム費用は約+1ms（1.05〜1.11倍）。利用者と相談して、静止画を変えない「ずらしなし」を製品化した（下の「製品版」）。

## 試作の仕組み

- 各ステージのカメラは位置が固定で回転だけ（`lookControls.ts`）なので、前のフレームの画素は奥行きなしの射影変換 `P_prev·V_prev·V_cur⁻¹·P_cur⁻¹`（遠クリップ面の点）で正確に今のフレームへ写る。
  動きベクトルや深度は使わない。カメラ位置が変わったら（ステージ変更）・描画バッファの大きさが変わったら（動的解像度の段・画質）履歴を捨てる。
- `hdrOutput.ts` がMSAAを解決した線形HDRの画像を、半精度の履歴2枚と交互に混ぜ（今のフレーム0.1・履歴0.9）、その結果をトーンマッピングする。
  色は `c/(1+max)` で圧縮したYCoCgで扱い、履歴は周囲3×3の平均±標準偏差の箱に制限する（今のフレームの画素を必ず含む）。履歴はCatmull-Rom（双線形5回）で読み、動きがない画素は `texelFetch`。
- 「ずらし」案は、影マスクと本描画の投影行列だけにHalton(2,3)の8点のサブピクセルのずれを足す（水面の鏡像は投影行列が変わると毎フレーム描き直すので、ずらさない）。

## 試作中に見つけた落とし穴

- 箱を平均±標準偏差だけで作ると、今の画素がその外にある画素（明るい中の暗い葉など）では静止していても履歴が毎フレーム平均の方へ引かれ、ぼけに収束した（静止画の勾配0.88〜0.91倍）。
  箱を今の画素まで広げて、静止画は基準と一致した（サウナΔE76平均0.02）。
- 画素中心の双線形の読み出しでも、フィルタの座標精度で隣の画素がわずかに混ざる。静止時は `texelFetch` にする（判定は最も近い画素中心からの距離。`floor(p − 0.5)` で判定すると中心のわずか手前で外れる）。
- **既存の不具合**：最終パスはHDRターゲットのアルファをそのままcanvasへ出し、レンダラーは `alpha: true` なので、アルファが1未満の画素ではページの背景が透けて合成される。
  サウナ昼の既定視点で1766画素（0.08%、庇の下の葉の縁など）。撮影では背景を消しているため、試作（アルファ1）との差として見つかった。製品版と同時に、最終パスのアルファを1にして直した。

## 製品化の前に挙げた要件（試作時点）

- 軽量画質・HDR出力なしの端末では無効。ステージ変更・画質変更・動的解像度の段で履歴を捨てる（試作は位置と大きさで判定）。
- 静止画を比べる既存の撮影テスト（Cycles比較・全周・撮影の再現性）は、ずらしなしなら静止画が変わらない（アルファの透けを直す分を除く）。ずらし案では全部の基準画像が変わり、収束までのフレーム数にも依存する。
- 単体テスト（再投影行列・ずらし列・リセット条件）とブラウザテスト（静止時に基準と一致、見回しでの残差）。

## 製品版（`temporalAA.ts`、2026-10-03採用）

- ずらしなし。標準・高精細のみ（`quality.ts` の `temporal`）、HDR出力のない端末と `?temporal=off` では無効（`data-temporal`）。
- 履歴を捨てる条件：カメラ位置・描画バッファの大きさの変化、1フレームに0.25radを超える回転（`JUMP_ANGLE`。採用時は0.05rad、下の「速い見回し」で変更）、矢印キーの1押し（0.08rad。撮影の視点の飛びもこれ）。ステージ変更でも明示的に捨てる。
- 試作から足したもの：
  - 今のフレームも `texelFetch` で読む（双線形で読むと最終パスの補間と二重になり、静止画が1段階ずれた）。
  - 履歴が半精度の丸めの範囲で今の値と同じ画素は、今の値をそのまま出す。履歴を0.9で混ぜると、差の0.1倍が丸めで消えたところで止まり（最大約5段の半精度の刻み、相対0.25%程度）、静止画が1段階ずれたまま残った（画素の1.3〜1.9%）。
    許容は圧縮した色の最大成分の0.6%。これで `?temporal=off` との差は1段階が約120画素と、シーン自体の非数の2画素（2160000画素中）になった。
  - 既存のタッチ操作のテスト（動かした直後の画像がそのまま止まることを画素一致で確かめる）は、この修正の前は失敗した。
- 結果（`?temporal=off` の同じビルドに対する比、全段）：

| 段 | 面の残差 | 面の99パーセンタイル | 画素の残差 |
|---|---|---|---|
| 1.5 | 0.57〜0.63 | 0.54〜0.65 | 0.56〜0.59 |
| 1.25 | 0.57〜0.59 | 0.54〜0.56 | 0.57〜0.61 |
| 1 | 0.52〜0.56 | 0.51〜0.55 | 0.55〜0.62 |

- 低い段ほどよく効き、1の1.5に対する面の残差は1.60倍（中央値）から1.47倍になった。
- 費用（DPR 1.5・標準、交互に2回）：+1.1〜1.4ms（1.06〜1.14倍）。外気浴の昼10.2ms・水風呂の夕暮れ19.7ms・夜20.6ms。
- `temporal-aa.e2e.ts` が静止画の一致・見回し中の違い・軽量での無効を検査する。

## 静止中はパスを省く（2026-10-03）

- 製品版の残件「費用の削減」。カメラが60フレーム（`STILL_FRAMES`）続けて止まったら、パスを描かずMSAA解決の画像をそのままトーンマッピングし、履歴を捨てる（止まっている間に蒸気・水面が動くので、次の見回しは表示中の画像から始める）。
- 止まった直後に省かないのは、ゆっくりしたドラッグ（ポインタの更新がフレームより疎い、120Hz表示など）で混ぜた像と1フレームの像が交互に出て、かえってちらつくため。60フレームの間に履歴は今の画像へ収束し（0.9^60 ≈ 0.2%）、シェーダの許容の内側に入るので、省いた瞬間の段差は見えない。
- 費用（DPR 1.5・標準、静止した既定視点、繰り返し描画2回のフレーム間隔）：

| 比較 | 差 | 比 |
|---|---|---|
| HEAD（毎フレーム混ぜる）→ 変更後、交互に3組 | −0.37〜−0.55ms | 0.954〜0.981 |
| 変更後のビルドで `?temporal=off` → オン、交互に2組 | −0.13〜+0.16ms | 0.990〜1.013 |

- 静止中の費用は `?temporal=off` と区別できなくなった。見回し中の費用は変わらない（同じパス）。この日の測定ではパス自体が約0.4msで、採用時の+1.1〜1.4ms（別の日、TAAを入れる前のビルドとの比較）より小さかった。
- `temporal-aa.e2e.ts`（静止画の一致・見回し中の違い）、`scene-touch.e2e.ts` は変更なしで通る。見回しのちらつきの撮影（`resolution-shimmer.visual.ts`）は、各フレームを動かしてから2フレームで撮るので60フレームの省略に掛からず、再実行していない。
- `frame-cost.gpu.ts` に `FRAME_COST_QUERY`（URLに足すクエリ、例 `&temporal=off`）を足した。

## 速い見回し（2026-10-03）

- 採用時の残件「速い見回しでの効果」。指のスワイプは60Hzで1フレーム約0.07rad回るので、採用時の `JUMP_ANGLE` 0.05radでは毎フレーム履歴が捨てられ、蓄積なしと同じだった（測るまでもなく構造上）。
- `resolution-shimmer.visual.ts` に `SHIMMER_PX`（1ステップのCSS px）・`SHIMMER_FRAMES`（1ステップのフレーム数）・`SHIMMER_RATIOS`・`SHIMMER_QUERY` を、`summarize_resolution_shimmer.py` に `--baseline`（別の実行に対する比）を足し、`JUMP_ANGLE` を0.25radにしたビルドで段1.5・1ステップ1フレームを撮った（同じビルドの `&temporal=off` と比較）。

| 見回し | 1フレームの回転 | 画素の残差 | 面の残差 | 面の99パーセンタイル | 12フレーム後の勾配 |
|---|---|---|---|---|---|
| ゆっくり（1 px） | 0.004rad | 0.57〜0.58 | 0.59〜0.62 | 0.56〜0.64 | 0.89〜0.92 |
| スワイプ（18 px） | 0.072rad | 0.57〜0.58 | 0.69〜0.72 | 0.69〜0.77 | 0.88〜0.90 |

- 速くても画素の残差は同じだけ減り、面の残差の効果はやや下がる（0.6→0.7倍）。動いた分だけ履歴がCatmull-Romの再標本化で毎フレーム少しぼけ、箱で切られる画素も増えるため。外気浴の昼の拡大を並べて見たが、残像・二重像は見えなかった（目視のみ）。
- そこで `JUMP_ANGLE` を0.25rad（1フレームに約62 CSS px）にした。この範囲を超えるのは、ポインタの更新が止まった後の飛び程度。矢印キーは1押しで0.08rad飛ぶ「段」なので、回転量では区別できなくなった代わりに `lookControls.ts` が押下ごとに `resetTemporal()` を呼ぶ（撮影テストの視点の移動も矢印キーなので、次のフレームから1フレームの画像のまま）。
- 速いほど1フレームのずれが大きく、Catmull-Romのぼけは前のフレームの画素位置の端数に依存する。60Hzより遅い表示・速いフリックでは確かめていない。
- `scene-touch.e2e.ts` は1フレームに50 CSS px（0.2rad）動かし、動かした直後の画像がそのまま止まることを確かめていた。0.05radでは履歴が捨てられ直後に確定していたが、0.25radでは混ぜた像が収束するまで変わり続けて失敗した。止めてから70フレーム待ち（`STILL_FRAMES` の後は1フレームの画像そのもの）基準を撮るようにした。

## さらに速いフリック・遅い表示（2026-10-03）

- 60 px×12ステップは画面からはみ出すので、`resolution-shimmer.visual.ts` のドラッグを移動範囲の中央から始めるようにした（既定の1 pxでは開始位置が6 px左になるだけ）。

## 履歴の箱を十字の5点にする（2026-10-03、採用）
