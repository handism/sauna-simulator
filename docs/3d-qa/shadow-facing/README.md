# 光に背を向けた画素の影計算を省く（2026-09-28）

[標本数の検証](../shadow-samples/README.md)の残件「光が寄与しない画素の影計算の省略」と「日なたの粒の原因」に対応した。製品の変更は `src/components/3d/softShadows.ts` の影の参照だけで、光源・影マップ・モデル・標本数は変えていない。

## 変更

- three 0.186 の `lights_fragment_begin` は、光源ごとに `( directLight.visible && receiveShadow ) ? getShadow(...) : 1.0` で影を掛ける。この条件に `SUI_SHADOW_FACING`（`dot( geometryNormal, directLight.direction ) > 0.0`）を加え、光に背を向けた画素ではPCSSを評価しない。
- 省略は厳密である。このシーンの材質はすべて `MeshStandardMaterial`／`MeshPhysicalMaterial` で、GLBの拡張は `KHR_materials_emissive_strength`・`KHR_materials_specular` だけ（clearcoat・sheenなし）。直接光は拡散・鏡面とも `saturate( dot( N, L ) ) × 色` に比例する。水底の濡れた鏡面（`waterBottom.ts`）も同じ法線の `saturate( dot )` を掛ける。葉は透過しない。clearcoatは法線が違うため、`USE_CLEARCOAT` の材質と標準材質以外では条件を常に真にする。
- PCSSの受け側平面バイアスは `getShadow` の中で `dFdx`／`dFdy` を取っていた。分岐の中の微分は、2×2画素の一部だけが分岐に入ると未定義になる。最初の試作（分岐条件だけ追加）では、梁・デッキ板・葉の輪郭で1%前後の画素が変わった（最大62/255、日なた側の縁が暗くなる）。そのため微分は `suiShadowSlope()` で分岐の前に全画素で取り、`getShadow` はその値を使う。

## 日なたの粒の原因

検証ブラウザ内で、最後に評価する光源（日光）の遮蔽物探索とフィルターの結果を色分けして撮影した（完全な影／部分的な影／遮蔽物ありで完全に日なた／遮蔽物なし）。

- 昼のサウナの視点では、中庭の地面・デッキ・漆喰壁の広い範囲が「部分的な影」になる。庭の木々（`sauna-garden.glb`）を読み込まないと地面・デッキの大半は「完全に日なた」に変わるので、これらは葉の本物の半影である。漆喰壁は庭がなくても部分的な影のままで、真上に格子状のパーゴラがあり、日光の円盤（0.085rad）でぼけた格子の影が壁全体に落ちている。
- 受け側平面の量子化（最近傍参照でテクセル中心の深度を読むことによるずれ）を疑い、傾きに比例したバイアス（(|傾きx|＋|傾きy|)×半テクセル）を試したが、部分的な影の範囲はほぼ変わらなかった。採用していない。
- 結論：日なたの粒は自己遮蔽の不具合ではなく、葉・格子の広い半影を16＋24標本で見積もるばらつき。標本数を減らすには、画面に固定した回転ノイズ（`pcssNoise`）より分散の小さい標本配置が必要。

## 検証

型検査、35ファイル199単体テスト（`softShadows.test.ts` に1件追加：分岐条件と微分の位置）、Lint、整形、本番ビルド、ブラウザ回帰14件成功（3.3分）。3Dチャンク721.37→722.73KB。検証用の差し替えスペック（1灯ずつ外す測定・色分け撮影）はリポジトリに含めていない。全周撮影・Cycles同視点・継続利用・帯域制限・Python検証は、既定視点6条件で差が0.025%以下のため再実行していない。モバイル実機（Apple以外のGPUの分岐の扱いを含む）・実聴・GPU総メモリは未検証。
