# 2026-10-26のまとめた回帰と入室直後の停止

10/22・10/25の見た目の修正は静止画の目視だけで、最近は対象を絞ったブラウザ回帰しか実行していなかったため、`a6beac3` で通常回帰の全件・全周撮影の四季と天気・高画質の全周をまとめて実行した。Chrome 155.0.8059.85、同じMac。

## 通常回帰（`bun run test:browser`）

- `a6beac3`：80件中7件が失敗（`scene-warmup` 4件、`frame-rate`、`scene-lifecycle` の繰り返し、`audio-nodes` の3D）。再実行で `frame-rate` は成功し、6件は再現した。`47692ff`（最近5コミットの前）のworktreeでも `audio-nodes`・`scene-lifecycle` は失敗した（`scene-warmup` はこのときは成功、続く計測では同じだけ遅かった）。
- 失敗の行番号が今のファイルと合わず（165行のファイルで193行目など）、Playwrightの変換キャッシュが古い版を走らせていた。`PWTEST_CACHE_DIR` を新しくすると `scene-warmup` は6件すべてが同じ理由（入室後5秒以内に `.sauna-3d-canvas` が見つからない）で失敗した。
- 原因は入室直後のメインスレッドの停止。3DのJS・モデルは1.5秒で届くが、その後の約4.8秒のLong Taskの間、テスト側の確認も進まない。CPUプロファイルでは約3.7秒が `gardenDetails.ts` の地面の高さ（真下のレイを地形の全三角形へ総当たり、数千回）、約0.7秒が `settleTerraceProps()` の支えの面へのレイだった。旧版でも同じなので最近の変更の退行ではない。
- 修正：`downwardRay.ts` の `createDownwardRay()` が三角形を世界座標の足跡で水平の格子（0.5m）へ一度だけ振り分け、点の格子の三角形だけを `Mesh.raycast` と同じ手順（境界球・箱、ローカル座標のレイ、材質の面の向き、メッシュ順・三角形順の最も近い交点）で調べる。`downwardRay.test.ts` が回転・拡大・重なり・インデックスの有無・BackSide・drawRangeの4000点でRaycasterとビット単位の一致（外れも含む）を検査する。変形・スキン・複数材質のメッシュは従来のRaycasterに任せる。
- 結果（同じビルド手順・`?frameRate=full`・標準、各2回）：Long Task 4.76→1.04秒、`data-load-ms` 5.15→1.41秒。分割準備（`?warmup=split`）ではcanvasの出現が入室後6.3→3.2秒。
- 修正後の通常回帰は80件すべて成功（21.3分、新しい変換キャッシュ）。
