# サウナの着座位置（2026-10-18）

上段の奥寄りから、下段ベンチの中央より少しストーブ寄りへ移動した。GLBの形状やストーブ位置は変更せず、`scripts/web_scene.py` の `stageViews.sauna` に体験用の視点を追加した。`views` は従来のCycles比較用として維持し、`?camera=review` では着座位置の上書きも `STAGE_PITCH` も適用しない。温めとステージ再入室は同じ `placeCamera`、空間音響のリスナーも同じカメラ位置を使う。

## 配置の根拠

元blendを読み取り専用で開き、ベンチの境界を確認した（Blender座標をglTFへ変換）。下段の板はx −6.01〜−1.19m、z −3.028〜−2.512m、座面上端y 0.565m。新しい目の位置 `[-3.2, 1.65, -2.78]` はこの座面上にあり、座面から目まで1.085m。旧位置は `[-4.9, 2.12, -3.65]`。ストーブ中心への水平距離は約4.35mから約2.46mになった。

向きの基準点は `[-0.95, 1.4, -0.65]`、垂直画角65°、既存の初期俯角−0.18radを適用。ストーブは画面中央から少し左へ置き、縦長でも石の面を見せ、右側に窓越しの庭を残す。

## 再実行

```sh
python3 scripts/web_scene.py
bun run test:browser:visual e2e/sauna-seat.visual.ts --reporter=json > /tmp/sauna-seat-visual.json
bun run test:browser e2e/scene-viewport.e2e.ts e2e/audio-nodes.e2e.ts --grep 'narrow controls|3D scene' --timeout=180000 --reporter=json > /tmp/sauna-seat-regression.json
```

撮影は標準画質・DPR1・動作抑制のChrome。変更前は同じビルドのシーン定義から `stageViews` だけを検証ブラウザで除く。横長1280×800、縦長390×844、低い横長844×390の昼夕夜を両位置で撮影し、変更後はロウリュ3枚・水平8方向・ステージ一巡後1枚も撮る。比較中も滞在時間・温湿度は進むため、UIの画素一致を要求する比較ではない。画像はローカルのみ保存する。

## 範囲

実機・実Safari・高画質・全季節天気・連続見回し・音の実聴・性能の検証は含めない。低い横長画面では右側の操作パネルがストーブの一部に重なるため、全体を見る場合は既存の「景色」操作を利用する。

## 確認結果

Chrome 155の撮影テスト2件が成功（skip・flaky・console/page errorなし、30枚）。最終位置の昼夕夜・ロウリュの一覧、水平8方向の一覧、昼の横長・縦長の原寸を目視確認した。縦長でもストーブの石が左右端で切れず、操作パネルの上に見える。水平8方向で壁・ベンチへのカメラのめり込みは見られなかった。静止画の限定した確認であり、すべての俯仰角や連続見回しの保証ではない。撮影条件・PNGと入力のSHA-256は `capture.json`。

初回の通常回帰では、音響の6周＋3D再生成が7セット目の最後で90秒の全体上限に達した。狭い画面の回帰は成功。個々の待機期限・チェック・周回数を維持し、CLIで全体上限を180秒へ延ばして再実行し、2件とも成功（skip・flakyなし）。音響リスナーは6周・3D再生成後も新しい着座位置と一致した。`regression-timeout.json` と `regression.json` に両方の結果を残した。

型検査・422単体テスト・Lint・整形・ビルド・`git diff --check` 成功。3Dチャンク873.05kBで、既存の850kB警告は継続。
