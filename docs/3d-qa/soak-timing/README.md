# 継続利用の資源比較と描画速度の記録（2026-09-28）

対象は `e2e/scene-stability.soak.ts` と `playwright.soak.config.ts`。製品コード・配信モデルは変更しない。

## 背景と変更

庭の分割読み込み後の検証では、標準・高画質の夕暮れで180フレームの計測が15秒以内に終わらず、
継続利用テストが途中で止まった。分割前でも同じ箇所で失敗し、取得できた標本のリソース数は一致していた
（[前回の記録](../../3d-sauna-progress.md)）。速度の問題により、後半の再生成・操作・資源比較が未検証になっていた。

今回、180フレームの標本数を維持し、各標本の待機上限を15秒から30秒、全体の上限を420秒から600秒にする。
実時間5分以上・最低6周回、全ステージの準備描画、蒸気の終了待ち、各ステージ／画質でのテクスチャ数・
形状数の厳密な一致、ミュート保持、同一canvasの維持、最後の2Dでの操作は従来どおり検証する。
30秒以内に標本が得られない場合や資源数が異なる場合は、引き続き失敗する。

各標本に次を記録する。

- `waitMs`：標本の待機開始から読み取りまでの実時間。
- `frameWindowMs`：製品の平均フレーム間隔×180。平均値が小数点2桁なので最大約0.9msの丸め誤差がある。
- `exceedsPreviousWindow`：180フレームの所要時間が15秒相当を超えたか。
- `slowSamples`：上記を超えた標本数（添付の先頭）。

蒸気の終了待ち中にも180フレームの計測は進むため、所要時間と待機時間は異なる。
`exceedsPreviousWindow` は旧テストで必ず失敗したことを示すものではない。
検証成功は資源数と操作継続の成功であり、FPSの合格ではない。PCの60fps目標は別途評価が必要。
製品の速度を改善する変更でもない。

## 再実行

```sh
caffeinate -i bun run test:browser:soak --reporter=json > /tmp/sauna-soak-window.json
```

macOS以外では `caffeinate -i` を外す。レポートの `stability-samples` 添付（base64 JSON）に全標本がある。
Viteのビルド出力が先頭に入るため、JSONとして読む場合は最初の `{` から読む。

## 検証範囲

同じデスクトップChrome内のレンダラー資源数の比較。GPU総メモリ、音声ノード数、モバイル実機性能、
リーク不存在を証明するものではない。通常のブラウザ回帰・全周画像・帯域制限テスト・GPU時間は、
製品変更がないため今回は再実行しない。
