# 深度プリパス後の光源ごとの影の費用（2026-10-01、診断）

[水中の材質の深度プリパス](../underwater-prepass/README.md)の残件の先頭。1画素あたりの計算回数が1回に近づいた後で、夕暮れ・夜の影（PCSS）の費用を光源ごとに測り直した。製品の描画・配信物は変更なし。

**結論：影は夕暮れ・夜のフレームの約75〜85%を占めるが、費用は光源ごとに足し算にならない。** 1灯ずつ外した節約の合計は、多くの視点で全灯分の半分程度にとどまり、外すとかえって遅くなる灯もある。「どの灯を軽くするか」で詰める方針は根拠にならない。ループの展開を止めてシェーダを小さくする案（`rolled`）は夕暮れ・夜で9〜16ms遅くなり、シェーダの大きさが原因という仮説は外れた。

## 方法

`e2e/frame-cost.gpu.ts` に変種を加えた（`frame-cost.ts`、書き換えは検証ブラウザ内だけ）。

- `noshadow-<灯>`：その灯の影の参照だけを `false ? …` に置き換える（灯は影なしで照らし続ける。受け側の傾きの微分 `suiShadowSlope` は残る）。`sun`（唯一の平行光源、夕暮れは4＋6標本、昼・夜は16＋24）、`spot0`＝V9、`spot1`＝寝椅子灯（lounge dusk fill）、`spot2`〜`4`＝通路灯1/4/7、`spot5`＝モミジ灯（threeは影を落とすスポット光を先に並べる。`lighting.ts` の順）、`all`＝全灯。置き換えが0件なら失敗にする。
- `rolled`：PCSSの標本ループの回数に、未設定で常に0のuniformを足す。計算は同じで、コンパイラがループを展開できない。
- `warmup`：製品と同じだが集計しない。起動直後の最初のページは全視点で2〜4倍遅かった（1回目の報告。`cost.json` の `ablation` に残し、光源ごとの集計には使っていない）。

条件：Chrome 154.0.8037.58／ANGLE Metal（Apple M1 Max）、headless、標準画質・1200×800・DPR1・動作抑制・庭の準備完了後、3ステージ既定視点×昼夕夜。変種の節約量は、同じ報告の直前と直後の製品の平均からの差（2回目の報告は最初と最後の製品）。光源ごとは4報告（順序を変えた。製品を3変種ごとに挟むのは3〜5回目）、`rolled` は製品と交互に4回。

## 結果

節約量の中央値（ms、正は速くなる）。製品は同じ報告群の製品の中央値。全標本は [cost.json](cost.json) `lightCosts`。

- **全灯の影を外すと** 夕暮れ・夜は8〜13ms（サウナ夕 38.6→約11ms、水風呂夜 64.9→約13ms）。4報告の範囲は狭い（例：水風呂夕 44.7〜48.4ms）。昼も水風呂は41→13ms（日光とV9が働く）。
- **足し算にならない。** サウナ・水風呂の夕暮れ・夜は単独の合計が全灯の55〜65%。外気浴夕暮れは逆に合計64msが全灯28msを大きく上回り、通路灯・モミジ灯のどれか1灯を外すだけで9〜19ms減る（通路灯1は4報告中3報告で18〜19ms、残る1報告は5ms）。
- **外すと遅くなる灯がある。** 寝椅子灯はサウナ夕・夜で−2〜−3ms（どの視点でも節約は1ms未満）。昼に強度0で評価されない通路灯3灯（`directLight.visible` の分岐）を外すと、水風呂昼で0.3〜0.6ms遅くなる。影の参照を消すとコンパイル結果（レジスタ割り当て・命令の並び）が変わり、ほかの灯の費用まで動くと見られる。
- **`rolled` は遅い。** 展開を止めると夕暮れ・夜で+9.5〜16ms、サウナ昼でも+15ms（4回すべて同じ向き）。昼の水風呂・外気浴はほぼ変わらない。展開済みのループはむしろ速く、命令数・シェーダの大きさが律速ではない。
- 足し算にならない理由は切り分けていない。候補は、複数の影マップを1画素で読み合うことによるテクスチャキャッシュの競合（全灯を外すと影マップを1枚も読まない）と、コンパイル結果の変動。

## 次に試す候補（未実施）

- 影マップの読み出し量を減らす：暖色灯5灯は静止した光源・形状で影が視点によらないため、影マップの解像度・形式（16bit深度）を下げたときの費用。1灯の影マップを小さくして節約が足し算に近づくかで、キャッシュ競合の仮説も確かめられる。
- 影の評価を画面の低解像度・別パスへ移す（深度プリパスの深度を使う影のマスク）。描画パスの追加と、水越し・半透明の面の扱いが必要。
- 他の端末（Windowsの外付け・内蔵GPU、モバイル）では非加法性が違う可能性があり、光源ごとの結論は他の端末に持ち出さない。

## 検証

型検査、Lint、整形、Python 155テスト（`test_summarize_frame_cost.py` 2件追加）、GPU計測6回（計69件成功、1回目はウォームアップ前の外れを含むため光源ごとの集計から除外）。製品コードの変更はなく、単体テスト・ブラウザ回帰・撮影は再実行していない。

## 再実行

```sh
bun run build
FRAME_COST_VARIANTS=warmup,product,noshadow-sun,noshadow-spot0,noshadow-spot1,product,noshadow-spot2,noshadow-spot3,noshadow-spot4,product,noshadow-spot5,noshadow-all,product \
  bunx playwright test --config playwright.gpu.config.ts e2e/frame-cost.gpu.ts -g "frame cost" --reporter=json > light-1.json
# 順序を変えて繰り返す。rolled は warmup,product,rolled,product,rolled,…,product
python3 scripts/summarize_frame_cost.py --out docs/3d-qa/light-shadow-cost/cost.json --light-costs light-1.json ... rolled-1.json
```
