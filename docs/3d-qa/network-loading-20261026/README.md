# 読み込みの期限を受信の途絶に変え、プローブを時間帯ごとに分けて取得（2026-10-26）

## 変更前の状態

[前回の記録](../garden-split/README.md)の後、本体GLBは2.50MB（本番のgzip転送1.74MB）になり、室内・飛び石の局所照度も加わった。本番（GitHub Pages、`.glb`・`.bin` もgzipで配信）で準備完了までに取得していたのは約3.5MB（3D用JS 0.27MB・本体GLB 1.74MB・照度／反射プローブ 1.41MB・その他0.06MB、いずれもgzip後）。読み込み全体に開始から一律30秒の期限があったため、転送だけで見て約0.9 Mbps未満では3Dに入れなかった。

試したが採らなかったもの：

- GLB内のJPEG 6枚（計0.94MB、gzipで縮まない）をWebPに再圧縮：同程度の品質（q80〜88）でほぼ同じ大きさか大きい。不可逆の再圧縮で得がない。
- プローブ（float16）のバイト分割・係数ごとの並べ替え・差分化：可逆でgzip後12〜17%減にとどまる。

## 変更

1. **期限を受信の途絶に**（`src/components/3d/loadDeadline.ts` の `LOAD_STALL_MS` = 30秒）：`createModelFetch` が本文を受け取るたびに `SaunaScene` の期限と、`onProgress` 経由で `SceneMode` の期限を延ばす。遅い回線でも届き続ける限り読み込み、30秒何も届かなければ従来どおり2Dへ戻る。遅延JavaScriptの取得中は進捗がないため開始から30秒のまま。取得後の解析・コンパイルは最後の受信から30秒以内。
2. **プローブを時間帯ごとに**（`probeScenes.ts`、`vite.config.ts` の `probe-scenes`）：配信用の `irradiance.bin`・`reflection.bin` から昼・夕・夜のファイル（各265,464 bytes、gzipで約0.23MB）を切り出し、準備完了までは今の時間帯の分（入室直後の自動なら昼の2ファイル、約0.46MB）だけを取得する。残り4ファイルは準備完了の後、庭の前に取得する。時間帯の変化は通過するシーンのプローブが揃うまで止める。元の1ファイルは焼き込み・診断スクリプトが読むので残す。

本番で準備完了までに取得する量は約3.5MB → 約2.5MB（gzip後）。

## 帯域制限での読み込み（`bun run test:browser:network`）

ローカルの `vite preview`（`.glb` は無圧縮で2.50MB転送）・CDPの帯域／遅延制限・キャッシュ無効、Chrome headless 1280×800。6件すべて成功。全値は [network.json](network.json)。

| プロファイル | 結果 | 準備完了 `data-load-ms` | 庭の追加 `data-garden-ms` |
| --- | --- | ---: | ---: |
| 12 Mbps・80ms | 準備完了 | 3.87秒 | 10.30秒 |
| 4 Mbps・150ms | 準備完了 | 8.87秒 | 25.26秒 |
| 1.6 Mbps・150ms | 準備完了 | 19.58秒 | 57.94秒 |
| 0.8 Mbps・150ms | **準備完了**（従来は30秒で2Dへ） | 37.43秒 | 112.37秒 |
| 0.8 Mbps・本体GLBを保留（受信なし） | 他のファイルの最後の受信から約30秒で2Dへ（押下から42.6秒）、解除後の再試行で準備完了 | — | — |
| 0.8 Mbps・手動取り消し | 約5.9秒で取り消し、再試行で準備完了 | — | — |

- 準備完了までに要求したプローブは全プロファイルで `irradiance-day.bin`・`reflection-day.bin` だけ。残りは本体GLBの受信後で、全6ファイルが揃う（`data-probe-scenes="day,evening,night"`）。
- 1.6 Mbpsの準備完了は前回記録の24.5秒から19.6秒（その間に本体GLBは2.73→2.50MBに変わっているので、差のすべてが今回の分ではない）。
- 庭は残りのプローブの後に始まるため、低速では前回より数秒遅れる（1.6 Mbpsで約5秒分）。

## 限界

- ローカルのプレビューとCDPの帯域制限。モバイル実機・CPU制限・パケット損失・本番CDNは測っていない。
- 低速回線では庭の木々が届くまで長い（0.8 Mbpsで約1分15秒、木々のない景色が続く）。読み込み中の状態表示に進み具合（割合）は出していない。
- 手動で時間帯を変えたとき、残りのプローブが届くまで（1.6 Mbpsで約5秒）照明が切り替わらない。
- 残りのプローブの取得に失敗すると、その訪問の間は取得済みの時間帯に留まる（自動では夕暮れに進まない）。
