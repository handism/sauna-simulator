# 時間方向の蓄積を追加した後の継続利用（2026-10-03）

製品コードは `9484b0d`。TAAの導入・静止時の省略・速い見回しへの対応・5点の箱への変更後に、
繰り返し利用時の資源数を確認した。製品コード・配信モデルは変更していない。

## 方法

```sh
bun run test:browser:soak --reporter=json > /tmp/sauna-soak-temporal.json
```

従来の3画質・昼夕夜・ロウリュ・ステージ一巡・2D/3D再生成に加え、各標本の前にUIを隠し、
8 CSS pxずつ12ステップ往復ドラッグした（各ステップで2回のrAF待ち）。続いて70フレーム静止してUIを戻し、
資源数を比較する。軽量では `data-temporal=off`、標準・高画質では `on` を要求する。
高画質での全ステージのウォームアップ、蒸気の終了待ち、180フレームの計測窓と資源数の一致条件は維持した。
TAAは見回し後に再開し、静止でパスを省く経路を通るが、パスの実行回数を直接計測した試験ではない。

`samples.json` は成功レポートの `stability-samples` 添付そのもの、`summary.json` は条件ごとの集計・実行結果・入力SHA-256。
初回はサンドボックス内でプレビューサーバーが起動できず、試験開始前に終了した。許可後にサンドボックス外で実行した
下記1回が評価対象（Playwrightの自動再試行なし）。

## 結果

Chrome 154.0.8037.97／macOS／headless／localhost／1280×800／DPR1。
**321.6秒・8周回・40標本で成功**。スキップ・自動再試行なし、ページエラー0件。
180フレームの窓が15秒相当を超えた標本は0。最後に2Dへ戻り、水風呂へ進めることも確認した。

| 画質・時間帯 | 周回 | 標本 | 形状数 | テクスチャ数 | TAA | 平均フレーム間隔 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 軽量・夕 | 3 | 15 | 128 | 17 | 無効 | 16.67〜18.89ms |
| 標準・夜 | 3 | 15 | 128 | 34 | 有効 | 16.67ms |
| 高画質・昼 | 2 | 10 | 128 | 34 | 有効 | 16.67ms |

- 形状数・テクスチャ数は全周回・3D再生成の前後で一定。描画数・三角形数も同じ画質／ステージ内で一致。
  庭は全標本で準備完了、描画DPRは1。
- [前回](../soak-optimized/README.md)の形状127から128、標準・高画質のテクスチャ32から34に増えた。
  TAAの全画面三角形1個と履歴2枚という実装と一致する。軽量で履歴テクスチャは解放されるが、
  全画面三角形は保持する（高画質でウォームアップした後の値）。
- 7周目の最初のサウナ標本（軽量・夕）に最大416.6msの停止があり、平均18.89ms。他の39標本は平均16.67ms、
  最大16.8msだった。前回も同じ7周目・軽量・夕・サウナで416.7msが記録されているため、
  単発で再現しないとは扱わない。今回も原因は特定していない。TAAはこの標本では無効。

## 範囲と残件

デスクトップChrome・DPR1での資源数と操作継続の確認。全画質×全時間帯の組み合わせではない。
フレーム間隔は従来どおりステージ・画質変更後の180フレーム窓で、見回し中だけの性能測定ではない。
描画資源数の一定性はGPU総メモリ、音声ノード数、リーク不存在を証明しない。
スマートフォン実機・DPR 2〜3・120Hz表示、通常速度での残像の知覚と、約417msの停止の原因調査は残る。
