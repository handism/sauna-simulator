# 初回の描画準備を分割する（2026-10-06、検証候補）

[前回](../shader-cost/README.md)の残件「残りの初回停止を、描画を複数フレームに分けて短くできるか」を検証した。製品コード・配信GLBは変更していない。

## 方法

`diagnose_compile_batches.mjs` が現在のソースを一時ディレクトリへ複製してビルドする。読み込み時の最初の本描画の前に、重いプログラム（頂点・断片の合計16万字超）を使う新しい描画状態を1個／3個ずつ許可する。残りの重い描画だけを保留し、次回同じシーンを描いて続ける。主描画・鏡像の本物の描画先・MSAAを使い、鏡像も各回再生成する。

各回の最後にキャンバス1画素の `readPixels()` で先行する描画の完了を待ち、rAFと20msのタイマーでブラウザへ処理を返す。前回確認したように、この環境の `finish()` だけではMetalの準備の完了を待たない。最後に抑止を解除し、影・鏡像・TAAを更新して通常の全体描画へ戻す。これはWebGL呼び出しを抑止する実験であり、製品向けの実装ではない。

- macOS・Apple GPU、Playwright Chrome for Testing／WebKit、headless。
- 標準画質・1200×800・DPR 1.5・動作抑制・昼・固定解像度・全フレーム描画。
- 各ブラウザで通常→1個→3個→3個→1個→通常。全プログラムの断片出力に毎回異なる名前の、初期値0のuniformを足す（出力へ0を加算）。Metalキャッシュを削除せず初回相当のプログラムを作る。製品のシェーダーそのものの初回時間ではない。
- 描画状態のキーはプログラム、描画先の形式・標本数、ブレンド、深度／色書き込み、alpha-to-coverage。29／31などの数はこの検証が許可したキー数で、ドライバーのパイプライン総数の実測ではない。
- WebGL状態の同期問い合わせ・読み戻し・繰り返し描画の費用を含む。FPSや通常利用の読み込み時間と混同しない。
- タイマーの最長間隔はページ初期化から庭準備完了後500msまで（入室前も含む）。分割ステップの最長時間とは別の指標。

## 結果と判断

Chrome for Testing 153.0.8010.12の通常描画は `data-load-ms` 9.81〜9.86秒、タイマーの最長間隔8.58〜8.60秒。1個ずつでは読み込み12.25〜12.30秒、29回の準備の最長1.32〜1.36秒。3個ずつでは読み込み10.81〜10.82秒、11回の準備の最長1.84〜1.88秒。

Playwright WebKit 26.6でも同じ傾向だった。通常は読み込み9.91〜10.14秒・タイマー最長8.70〜8.90秒。1個ずつは読み込み11.54〜12.11秒・準備最長1.37〜1.56秒、3個ずつは読み込み10.58〜11.23秒・準備最長1.90〜2.11秒。WebKitはSafariそのものではない。

**1個ずつの2回目には、準備ステップの外で9.65秒のタイマー間隔も記録された。** 時刻とフェーズを保存していないため、入室前・準備後などのどこで起きたか、原因は特定できない。準備ステップを短く分けられることと、ページ全体の停止がなくなることは分けて判断する。

最初の準備ステップには軽いプログラムや影など、今回分割しない処理も入る。そのため1個ずつでも1秒以上の待ちが残る。読み戻しと再描画で合計時間も延びる。**製品への採用は保留**とする。

両ブラウザの3ステージの既定視点は各6回、合計36枚が、各ブラウザの最初の通常描画とRGB全画素一致。撮影時だけDOMのUIを非表示にして比較した（初期試行ではcanvasのスクリーンショットにもUIが重なり、タイマーの文字が差になったため、最終撮影から除外）。全周・見回し・夕暮れ／夜の画質確認ではない。

詳細は [Chrome](cft.json)、[WebKit](webkit.json)、[集計](summary.json)。

## 次の作業

- タイマーとrAFの間隔に時刻・入室／準備／準備完了／庭のフェーズを記録し、ステップ外の停止を切り分ける。
- 重い材質以外の最初の準備を調べる。読み戻しを非同期のフェンスへ置き換えられるかも別に検証する。
- 製品化する場合は、部分描画を見せないこと、30秒期限、準備中の画質・ステージ変更、キャンセル・コンテキスト喪失、影／鏡像の復旧を設計してから回帰する。

## 再実行

```sh
node scripts/diagnose_compile_batches.mjs docs/3d-qa/compile-batches/cft.json cft 0,1,3 2
node scripts/diagnose_compile_batches.mjs docs/3d-qa/compile-batches/webkit.json webkit 0,1,3 2
python3 scripts/summarize_compile_batches.py docs/3d-qa/compile-batches/cft.json docs/3d-qa/compile-batches/webkit.json --out docs/3d-qa/compile-batches/summary.json
```

プレビューのポート4194とブラウザの起動が必要。計測は同時に走らせない。ソース・配信物・スクリプト・PNGのハッシュ、実行順序、全条件の完了を集計時に検査する。PNGはローカルのみ、JSONとこの記録だけをGit管理する。一時ビルドはレポートの `scratch` に残す。
