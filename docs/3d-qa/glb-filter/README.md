# GLBの位置・法線・UVを許容誤差つきで圧縮（2026-09-27）

前回の [帯域制限検証](../network-loading/README.md) で、3D用の取得17.62MBのうちGLB（16.37MB）が93%を占め、30秒の期限内に完了するには約4.7 Mbps以上が必要と分かった。GLBの容量を、形状・描画数を変えずに減らした。

## 内訳（変更前）

画像6枚は0.94MBで、残り15.25MBが形状。POSITION 6.70MB・NORMAL 5.66MB・INDICES 1.68MB・UV 1.18MB。メッシュ別では葉・シダ・枝が約8割（`Fine canopy leaves` 4.75MB、V6の葉カード 2.89MB、シダ 1.61MB、V5の枝 1.42MB、V11のモミジ3体 1.31MB）。すべてfloat32のまま、meshoptのフィルターなしで圧縮していた。散らばった葉の座標はfloat32のままでは差分符号化がほとんど効かない。

## 候補（形状部分のバイト数）

配信中のGLBを可逆に復号し（再圧縮すると配信中のGLBとバイト一致することを確認）、同じ入力で測った。

| 候補 | 形状 | 備考 |
| --- | ---: | --- |
| 現行（可逆、bitstream v0） | 15,251,579 | |
| 頂点順の最適化（`reorderMesh`）のみ | 15,767,393 | 逆効果（葉は元から連続した四角形） |
| 可逆、bitstream v1 | 14,312,407 | GLB全体 14,818,176 |
| 法線をoct 8／10／12bit（v0） | 11.16M／11.67M／11.98M | 出力が正規化整数になりアクセサ型・ストライドが変わる |
| 位置・法線・UVをEXPONENTIAL（下記の許容誤差、v0） | 9,439,179 | |
| **同上、bitstream v1（採用）** | **8,731,329** | GLB全体 **9,842,672** |
| 許容誤差を2倍（0.2mm／0.25°、v0） | 8,970,739 | 追加の削減は約5% |

法線のoctは同じ誤差でさらに約1.1MB小さいが、NORMALがint8/int16の正規化整数（ストライド4/8）になる。`refraction.ts` の `sliceUnderwater` などは属性を型付き配列のまま作り直すため、floatのまま出力されるEXPONENTIALフィルターを選んだ。

## 方式

`scripts/compress_web_glb.mjs`：

- `KHR_meshopt_compression`（bitstream v1、meshoptimizer 1.1.1）。three 0.186の `GLTFLoader` とデコーダーは対応済みで、製品コードの変更はない。
- POSITION・NORMAL・TEXCOORD_0/1 だけEXPONENTIALフィルター（位置・UVは成分ごと、法線はベクトルごとに指数を共有）。アクセサごとに8〜23bitを順に試し、**全頂点**が許容誤差に収まる最小のビット数を使う。フィルターなしより大きくなる場合は可逆のまま。
  - 位置：ワールド座標で0.1mm（ノードの拡大率の最大値を掛けた誤差ベクトルの長さ）。舗石はデッキから3mm持ち上げているので、その1/30。
  - 法線：0.1°。
  - UV：1/8192（1024pxの画像で1/8テクセル）。
- インデックス・頂点カラー・画像は復号後にバイト一致を検査する。位置のmin/maxは復号後の値で書き直す。
- 結果（[compression-report.json](../../3d-export/compression-report.json)）：362領域のうち246がフィルターあり、116が可逆。最大誤差は位置0.0996mm・法線0.095°・UV 1.22×10⁻⁴。位置は14〜21bit（葉の多くは19〜20bit）、法線は10bit。
- 三角形数・メッシュ数・材質・ノード変換・画像・材質extrasは不変。GPUメモリ（float32）と描画数も不変。

`--lossless` でフィルターなし（v1）の出力も作れる。

## 帯域制限での読み込み

`bun run test:browser:network` に「4 Mbps・遅延150msで準備完了」を追加し、3回実行した（4件×3回すべて成功、自動再試行なし、ページエラー0件）。全値は [network.json](network.json)。

| プロファイル | 変更前（[前回](../network-loading/README.md)） | 変更後（3回） |
| --- | --- | --- |
| 12 Mbps・80ms | `data-load-ms` 13.10〜13.11秒 | 8.73〜8.78秒 |
| 4 Mbps・150ms | 期限切れ（GLB 12.60MB＝77%受信で取り消し、今回実測1回） | 24.57〜24.63秒で準備完了 |
| 1.6 Mbps・150ms 期限切れ | 30.19〜30.21秒で2D継続 | 30.13〜30.19秒で2D継続（GLB 3.71MB受信） |
| 1.6 Mbps 手動取り消し | 約3.3秒 | 約3.3秒 |

3D用の取得は17.62→**11.10MB**（GLB 9.84MB、プローブ2件1.06MB、3D専用JS 0.19MB）。遅延・解析を除いて30秒以内に取得を終える目安は約4.7→**約3.0 Mbps**。制限解除後の再試行は変更前と同じく約0.5秒。

## 限界

- ローカルのプレビューとCDPの帯域制限。モバイル実機での復号時間（フィルターの分だけ増える）・CPU制限・本番CDNは測っていない。
- 画像比較は20視点の静止画。全周144視点・継続利用・GPU時間は再実行していない（形状数・描画数・アクセサ型は不変）。
- 3 Mbps未満では引き続き30秒以内に完了しない。GLBの分割・段階的読み込みは未着手。
- Blenderでの再書き出しは行っていない（入力は配信中のGLBを復号したもの）。再書き出し時は `export_web_glb.py` が同じスクリプトを呼ぶ。
