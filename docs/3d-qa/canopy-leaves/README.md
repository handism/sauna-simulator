# 頭上の葉の形と大きさ

2026-10-20。水風呂・外気浴で見上げたときの頭上の葉が「同じ大きさの菱形が並んで見える」という指摘への対応。1回目は本体GLBの `V5 light filtering canopy`（材質 `V5 forest leaf 0〜3`）。2回目（下記「庭の葉と林のカード」）で、水風呂から背後を見上げたときの壁の上の庭の `Fine canopy leaves` と、林のカード（`leafCluster.ts`）の菱形マスクも葉の形にした。両GLBで2三角形の菱形が並ぶ葉はこの3つだけ（シダは `fernShape.ts` で加工済み）。モミジは元から5裂の輪郭。

## 変更

- `canopyLeafShape.ts` が読み込み時に960枚の葉を加工する。書き出しの葉は全枚数が同じ面積（√面積15.7cm、約33×15cm）の菱形の2三角形だった。
- 各葉を長い対角線の中点と元の面の向き（巻き方向）のまま、先の尖った卵形（中央脈＋4断面×左右、14頂点・16三角形）へ置き換える。位置から決まる乱数で、面積0.36〜1.64倍（一様、平均は元と同じ）・縦横比0.85〜1.2・面内の向き±0.5rad・付け根の端・中央の浅い折り（幅の0.08〜0.18倍）・先端の垂れを変える。
- 最初の候補の折り（幅の0.2〜0.4倍）は、なめらかな法線で日なたの葉がさや状に膨らんで見えたため浅くした（画像はローカルのみ）。
- 共有頂点・UV・モーフを持つ形状は変更しない。GLB・照度／反射プローブは元形状のままなので、間接光・遮蔽は近似。影・深度プリパス・影マスクは加工後の形状を共有し、追加の材質・テクスチャ・描画パスはない。

## 形状の確認

`geometry.json` は配信GLBをMeshopt展開して加工した結果。

- 3,840→13,440頂点、1,920→15,360三角形（+13,440、モミジ1種の約1.6万三角形と同程度）。
- √葉面積は全枚数15.7cm → 9.5〜20.3cm（5〜95%：10.3〜19.8cm）。
- 表面積は23.61→24.26m²（折りの分）、水平投影は23.04→23.38m²（+1.5%）で、木漏れ日の影の量はほぼ同じ。
- 非単位の法線0、元の面と逆向きの法線0。加工時間はbunで約14ms。

```sh

  bunx playwright test --config playwright.visual.config.ts canopy-leaves --reporter=json > /tmp/canopy-leaves.json
```

## 庭の葉と林のカード（2回目）

水風呂から背後を向いて見上げると、壁の上に庭GLBの `Fine canopy leaves`（材質 `Forest leaf tone 0〜3`、建物の奥 z −4.5〜−19m、77,760枚）が同じような菱形で並んで見えるという指摘への対応。

- 枚数が多いので、`canopyLeafShape.ts` に軽い輪郭 `SMALL_LEAF`（2断面・中央脈なし・折りなし、6頂点・4三角形）を加えた。V5と同じ乱数で面積・縦横比・向き・付け根の端・先端の垂れを変える。V5の `OVATE_LEAF`（14頂点・16三角形）を当てると124万三角形・bunで約470msになるため使わない。V5の加工結果は変更前と全頂点・法線・インデックスが一致する。
- 加工は検査・雛形・法線計算を配列のまま行うよう書き直した（同じ処理で約280ms→bunで約77ms）。
- `garden-geometry.json`：311,040→466,560頂点、155,520→311,040三角形（+155,520）。√葉面積は5.1〜15.4cm（中央10.0cm）→3.1〜19.1cm（中央9.4cm）。水平投影688.79→689.99m²（+0.17%）。非単位の法線0。
- 林のカードのマスク（`leafCluster.ts`）は、20枚の同じ大きさの菱形から、同じ卵形の輪郭・面積0.5〜1.5倍・任意の向きの20枚へ変えた。回転後の外接範囲でカード内に収め（縁から1テクセル空ける）、しきい値以上の被覆を菱形の0.4355に合わせて0.4385とした（面積係数0.9）。テクスチャの大きさ・ミップの補正・描画は同じで、毎フレームの負荷は変わらない。

### 負荷

`cost.json`：`frame-cost.gpu.ts` で標準・DPR1・1200×800・固定解像度・描画3回反復、HEADのworktreeと交互に3組。フレーム間隔÷3の平均。

- 既定視点（3ステージ×昼夕夜）：全9条件で+1.0〜3.3%（例：水風呂の夜21.58→21.80ms、外気浴の夕15.89→16.41ms）。3組とも同じ向き。
- 背後の見上げ（`FRAME_COST_KEYS=ArrowLeft*39,ArrowUp*12`）：サウナ+1%、水風呂の夕夜+6〜7%、外気浴+7〜11%（夜7.80→8.68ms）。水風呂の昼は表示間隔の上限（5.56ms＝16.7÷3）に張り付き差が出ない。
- 庭の読み込みの `gardenMs` は前後とも約4.5〜4.8秒で、加工の差は揺れに埋もれた。
- 増分は三角形の分（影・深度プリパス・主描画で共有する形状）。三角形を増やさない4頂点の非対称な凧形は試していない。
