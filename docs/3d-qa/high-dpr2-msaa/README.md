# 高精細・DPR 2でのメインの描画先の2倍MSAA（2026-10-05、確認・不採用）

[メインの描画先のMSAA](../main-msaa/README.md)の残件「高精細・DPR 2での2倍」。標準画質（DPR 1.5）では葉の縁の段がはっきり分かって不採用にしたが、画素が細かい高精細（画素比2）なら段が目立たず、速さとメモリだけ得られるかを確かめた。製品コードの変更はない。

## 結論

**変えない。** 2倍は8〜13%（1.7〜2.6ms）速いが、差は標準・DPR 1.5のときの約8割（0.77〜0.84倍）にしか縮まらない。庭の見える視点の昼の平均ΔEは0.73〜1.35（DPR 1.5では0.87〜1.75）。差は画素単位の市松模様だけではない。CSSの画素（2×2）に平均しても平均ΔEは0.7倍程度にしか下がらず、ΔE>2の画素の割合はほぼ変わらない。等倍では葉の塊が少しざらつき、枝の輪郭がわずかに硬くなる（[中庭・昼の等倍](crop-cycles-01-day.png)、[外気浴・昼の2倍拡大](crop-zoom-cycles-07-day.png)、左が4倍・右が2倍。拡大すると背景の林に2標本の alpha to coverage の市松模様が見える。画像はローカルのみ）。高精細は見た目を優先するために選ぶ設定で、このマシンでは2倍にしてもほとんどの視点で60fpsに届かない（届かない分は動的解像度が画素比を下げる）。

## 方法

- ビルド：4倍は `b7fcb78`、2倍は同じ版で `hdrOutput.ts` の標本数だけ2にしたもの。2つの本番ビルドを退避し、回ごとに `dist/` を差し替えた。
- 画像：`cycles-compare.visual.ts`（Cycles 6視点×昼夕夜、1200×800）と `stage-compare.visual.ts`（水風呂12視点、1280×800）を `CAPTURE_QUALITY=high CAPTURE_DPR=2 CAPTURE_PNG=1 CAPTURE_QUERY='&resolution=fixed'` で、4倍→2倍→2倍→4倍の順に撮った（2400×1600・2560×1600）。2倍の2回は全画素一致。4倍はCycles 01・04・05だけ従来どおり読み込み間でわずかに揺れる（平均ΔE 0.0004以下・ΔE>2は0.005%以下、下の差より3桁以上小さい）。
- 費用：`frame-cost.gpu.ts`（`FRAME_COST_QUALITY=high FRAME_COST_DPR=2 FRAME_COST_REPEAT=2`・`?resolution=fixed`・1200×800、`data-pixel-ratio` 2を確認）で、4倍と2倍を順を入れ替えながら4組（各回 `warmup,product`）。3ステージ既定視点×昼夕夜のフレーム間隔の平均（÷2）。

## メモリ（推定、未計測）

色（半精度RGBA、8バイト）と深度（4バイト）のマルチサンプルのレンダーバッファが半分になり、1200×800・DPR 2（2400×1600）で約88MiB減るはず。`gpu-memory.e2e.ts` は画素比1で測るため確かめていない。メモリが足りない端末で高精細を選ぶ場合の受け皿としては意味があるが、今回は見た目を優先した。
