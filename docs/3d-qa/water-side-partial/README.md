# 水の側面から透過する視線の部分反射（2026-09-26）

[側面の全反射を鏡映した像で描いた](../water-side-images/README.md)後の「次」は、(a) 側面から透過する視線の部分反射と、(b) 到達点の鏡面（水から出る光）の近似のどちらかを、水風呂ステージの視点の基準で比べて選ぶことだった。

## 選択

- (b) は[過去の測定](../water-exit-sampling/README.md)でタイルのCombinedの0.5〜1.2%（L*で1未満）しかなく、1画素8〜16本の標本と粒状の雑音を伴う。
- (a) は、透過する領域（側面にほぼ垂直な視線、入射角41.4〜48.6°）でFresnel反射率が7〜100%あるのに、ブラウザが内壁だけを描いていた部分。前回の比較画像で内壁がCyclesより濃く、全反射の境界が硬く見えていた。
- 見た目の差の大きい (a) を先に入れた。(b) は引き続き未着手。

## 方式

- 側面の裏に見える面は、元の水形状の全側面で**6mm裏の内壁1層だけ**（次の面は約30cm奥の内壁の裏。水形状を除いたレイキャストで確認）。
- 視線を波の法線で屈折させて箱を追う既存の処理（`suiSidePath`、TSの参照は `sidePath`）で、**最初に当たる側面では必ず反射する経路**とし、その側面でのFresnel反射率 R（非偏光・水→空気、臨界角を超えると1）を求める。2面目は従来どおり全反射か透過の二値。
- 鏡映した像の複製は、最初の側面に当たる画素ではRに関係なく描く（不透明、`renderOrder` 1）。
- 本物の面：水の中は従来どおり。最初の側面の裏5cm以内（`SIDE_WALL_LAYER`）の面は重み 1−R、それより奥・全反射の画素は `discard`（`trueWeight`）。
- 重みはアルファに出し、内壁を像の上に `SrcAlpha / OneMinusSrcAlpha`（ターゲットのアルファは保持）で重ねる。そのため内壁は像より**後に**描く必要がある。
  - 最初の試作では、該当する元メッシュ（水中のタイル全体・青銅・内壁）ごと `renderOrder` 2 にした。見た目は正しかったが、GPU時間が水風呂で+23〜28%、サウナでも+6〜14%増えた。ブレンドを外しても同じで、順序を戻すと変更前と同じだったため、**描画順が原因**（床のタイルを最後に描くと、その下の物体を深度で早期に捨てられない）。
  - そこで、裏の層に角を持つ水中の三角形だけを、属性を共有する別メッシュ（ブレンドする材質の複製、`renderOrder` 2）に移し、元メッシュからは除いた。元メッシュは従来の順序のまま。
- 材質の複製で見つけた既存の不具合：`material.clone()` は `customProgramCacheKey` も `onBeforeCompile` も引き継がない。鏡映像の複製は、ほかのモジュール（コースティクス・画像ランプ・ノイズ色）がキーで区別しているプログラムを取り違えることがあった。修正だけの前後の差分では、反射したタイルにコースティクスの模様が現れた（前回の版では青銅のプログラムを共有していたとみられる）。複製のキーを元のキー＋接尾辞にして修正した（`|side-image`・`|behind-sides`）。

## 限界・残件

- 2面目の側面は全反射か透過の二値のまま（角の近くで1面目で反射した後に透過する視線の部分反射は省略）。
- 透過した視線の側面での屈折（内壁の見える位置のずれ）は省略。空気の隙間は6mmなので、ずれは小さい。
- 像が描かれない画素（複製がない・深度で負ける）では、内壁が背後の色に重なる。今回の視点では見当たらなかったが、網羅的には確認していない。
- 到達点の鏡面（水から出る光）の近似は未着手。
- 比較は静止した波（動作抑制）・標準画質・Chrome headless。動く波、軽量／高精細画質、モバイル実機は確認していない。
