# 実ブラウザ検証（e2e）

- 実ブラウザ回帰検証は `bun run test:browser`。本番ビルドを生成し、専用の127.0.0.1:4175でプレビュー、インストール済みGoogle Chromeをheadless起動する。`e2e/*.e2e.ts` はVitestと分離し、型検査・Lintの対象に含める。5回の2D/3D切り替え、ステージ一巡、`WEBGL_lose_context`による喪失後の2D継続と再試行、取得保留中の解除、実時間30秒のタイムアウト、キーボードショートカット（クリック後のボタン上の`Space`、遷移中の無視）と全画面切り替えを確認する。`test-results/` はGit管理外。GPU総メモリ・長時間・実機タッチ・音の実聴を検証するものではない。
- 継続利用の検証は `bun run test:browser:soak`。専用の `playwright.soak.config.ts` で `e2e/*.soak.ts` のみ実行し、通常のブラウザ回帰検証から分離する。実時間5分以上、3画質・昼夕夜・ロウリュ・ステージ一巡・2D/3D再生成を繰り返し、同じステージ／画質のテクスチャ・ジオメトリ数を比較する。全計測値は `stability-samples` 添付JSONへ保存し、`--reporter=json` で取得可能。大量のtrace記録による負荷を避けるため、この設定ではtraceを無効にする。GPU総メモリ・音声ノード数・実機性能やリーク不存在を証明する検証ではない。
- リソース比較の前には、各周回と3D再生成後に高画質で3ステージを一巡し、指定画質へ戻す。Three.jsは初めて描いた形状だけをGPUへ登録するため、水の側面像や鏡像専用の光源形状の初回確保をリークと誤認しないよう、表示履歴を揃える。蒸気も表示を終えてから比較する。数の一致条件と180フレームの標本数は維持する。遅い描画でも全周回の資源比較を終えるため待機期限30秒・全体600秒とし、添付JSONには実際の待機時間と180フレームの所要時間（平均間隔×180）、従来の15秒相当を超えた標本数を記録する。蒸気の終了待ち中にも計測は進むため、所要時間と待機時間は異なる。成功は資源数と操作継続の検証であり、FPSの性能目標達成を意味しない。
- 低速回線の読み込みは `bun run test:browser:network`（`playwright.network.config.ts`、`e2e/*.network.ts` のみ）。2D入室後にCDPで帯域・遅延を制限（キャッシュ・Service Worker無効）し、12 Mbps・4 Mbps・1.6 Mbpsでの準備完了（1.6 Mbpsは庭を分けた本体でのみ間に合う）と、その後の庭（`sauna-garden.glb`）の取得が本体の完了後に始まり帯域制限を受けて追加されること、0.8 Mbpsでの30秒期限切れと手動の2D切り替えによるGLB取り消し（庭は取得しない）、制限解除後の再試行を確認する。1件150秒まで。取得ごとのバイト数・時間は `network-loading` 添付JSON。プロファイルは実験用で実回線の名前ではなく、CPU制限・実機・パケット損失・本番CDNは測らない。
- 全周の目視確認用画像は `bun run test:browser:visual --reporter=json > /tmp/sauna-visual-check.json`。専用configで `e2e/*.visual.ts` のみ実行し、3ステージ×昼・夕・夜×8方向×上下・水平の216枚を `test-results/visual/` に保存する。標準画質・動作抑制・1280×800・DPR1のChrome。`python3 scripts/summarize_visual_survey.py /tmp/sauna-visual-check.json docs/3d-qa/survey`（Pillow必要）で9枚の一覧画像とモデルハッシュ付きJSONを生成する。テストの成功は撮影・操作の成功であり、画質の合格判定ではない。画質所見は進捗記録へ残す。
- 同じ実行で `e2e/cycles-compare.visual.ts` が元Cyclesのカメラ（`e2e/fixtures/cycles-cameras.json`、`scripts/blender_camera_reference.py` で元blendから生成）の位置・向き・垂直画角で撮影する。`sauna.scene.json` の取得をテスト内で差し替えるだけで、アプリにテスト用APIはない。`python3 scripts/summarize_cycles_compare.py /tmp/sauna-visual-check.json <出力先>` が `blender/renders/` と対にした比較画像を作る。照明・露出・材質は一致させていない（霧はどちらにもなく、空は同じ元blendのWorldを `sky.ts` で再現）。
- Cycles比較は `scene-capture.ts` の `rendererCaptureStyle` を screenshot の `style` に渡し、ステージのDOM演出と固定操作UIを撮影中だけ除外する。canvasのlocator screenshotにも上に重なるDOMは写るため、UI非表示・動作抑制だけでは水風呂の `.cooling-glow` の脈動を除けない。全周撮影は実際の画面演出を残す。`capture-stability.visual.ts` は03/04・昼夕について脈動の0/500msの位相では画像が異なること、演出除外後は同一ページ内の位相間でPNGが一致することを検証する。2回のページ読み込み間はテクスチャ面の孤立した十数画素が変わることがあり（影なしでも発生、原因未特定）、ブラウザで復号した変化画素0.01%以下を条件とし、割合と最大差を記録する（同一Chrome/GPU環境内の再現性）。
- `caustics.e2e.ts` は水中の疑似コースティクス（`src/components/3d/caustics.ts`）のGLSLを素のWebGL2で評価し、Blender基準値（`e2e/fixtures/blender-caustic.json`）と強度・Voronoi・ノイズを1e−4以内で照合する。`noise-color.e2e.ts` と同じく移植の検証で、画面の見た目の検証ではない。
- `sky.e2e.ts` は空（`src/components/3d/sky.ts`）のGLSLを素のWebGL2で、Cyclesのパノラマから取った方向（`e2e/fixtures/blender-sky.json`）で評価し、昼・夕・夜の放射輝度（1e−4＋0.1%以内）・Voronoi F1の距離と色・雲のノイズ（1e−4以内）を照合する。月の円盤（角直径0.0093rad）は参照パノラマの画素（約0.012rad）より小さく、画素中心が円盤に入ったときだけ検査される。flatな可変値は微分が0なので、画素フィルターなしの元のグラフになる。空の入口 `sui_sky` にglTF軸で渡し、軸の変換も確かめる。日光の円盤の縁・星の半径・星の密度のしきい値上の点は除く。fixtureと `sky.json` のblendのハッシュ一致も検査する。
- GPU時間は `bun run test:browser:gpu`（`playwright.gpu.config.ts`、`e2e/*.gpu.ts` のみ）。`EXT_disjoint_timer_query_webgl2` で各アニメーションフレームのコールバック全体（鏡像・影・主パス・トーンマッピング）を計測し、既定の視点とCyclesカメラ03で、サウナ・水風呂×昼夕夜の8秒間の10/50/90百分位と描画数を `gpu-time` 添付JSONへ保存する。拡張がない環境ではskip。同じ機械・ブラウザでの変更前後の相対比較用（変更前はHEADのworktreeで同じテストを実行）で、他の端末のフレーム予算ではない。`gpu-timer.ts` はWebGLのdraw呼び出しがないコールバックを除く（2026-09-28修正）。以前の集計はUIの空コールバックを含む可能性があり、新しい測定値と直接比較しない。
- 影の費用の切り分けは `bun run test:browser:gpu e2e/shadow-cost.gpu.ts --reporter=json`。高画質・1280×800・DPR1・動作抑制・庭の準備完了後、3ステージ×昼夕を通常PCSS（16+24標本）／半分（8+12）／硬い影（1参照）で測り、逆順でも繰り返す。`shaderSource` の差し替えは検証ブラウザ内だけで、製品の光源・影マップ・描画コードは変えない。共通の `gpu-timer.ts` でWebGL描画のあるコールバックだけを各条件4秒測り、1秒のクエリ回収待ち後に `shadow-cost` 添付JSONへ記録する。CPU負荷を伴う別の検証と同時に実行しない。硬い影は費用の下限を探る診断で、画質を保った最適化や60fps達成の検証ではない。差し替えは `shadow-variants.ts`（標本数で指定し、製品の定数は `softShadows.ts` から読む。置換はPCSSの関数内だけ）。
- 影の標本数の画質は `bun run test:browser:visual e2e/shadow-samples.visual.ts --reporter=json`（視覚撮影の一式にも含まれ、約4分）。同じ差し替えで基準64+96／通常16+24／半分8+12／通常の再撮影を、高画質で3ステージ×昼夕の既定視点と1pxずつ8回のドラッグ（1px＝0.004rad）のPNGで撮る。`python3 scripts/compare_shadow_samples.py sweep <report.json> <出力先>` が基準との誤差とそのフレーム間の変化（画面座標に固定された標本の回転による粒の流れ）を出す。記録は `docs/3d-qa/shadow-samples/`（8+12は不採用）。`SHADOW_CANDIDATES=a,b` で半分の代わりに `shadow-variants.ts` の他の候補（半径の層化・適応標本・段ごとの切り分け）を撮り、`shadow-cost.gpu.ts` は `SHADOW_COST_VARIANTS=a,b` でその順と逆順に計測する。記録は `docs/3d-qa/shadow-placement/`（いずれも不採用）。
- `stage-compare.visual.ts` は水風呂ステージの既定視点を全周撮影と同じ操作で4方向（見出し0/2/4の水平・1の見下ろし）×昼夕夜、`rendererCaptureStyle` で画面演出を除いて撮る（全周撮影は `.cooling-glow` の脈動を残すため、実行間で画面の縁が最大40 L*変わり比較に使えない）。`scripts/blender_stage_reference.py` のCycles画像と対にする。
- 夕暮れの日光の影だけの比較は `bun run test:browser:gpu e2e/sun-shadow.gpu.ts --reporter=json`。方向光だけ通常PCSS／硬い影／影なし／通常再撮影の順に、3ステージ既定視点＋Cycles6視点を高画質・1200×800・DPR1で撮る。GPU時間は既定視点のみ。`scripts/summarize_sun_shadow.py <report.json> docs/3d-qa/sun-shadow` が元解像度の差、600×400のCycles誤差、比較画像、全標本を保存する。製品変更なしの候補評価。見回し・全周・昼夕補間・逆順の性能追試は別途必要。
- 同診断に `SUN_SHADOW_REVIEW=1` を付けると、通常／硬い影／4参照PCF／通常再撮影で夕暮れの108視点（既定3・Cycles6・8方向×3俯仰×3ステージ・1px見回し9枚×3ステージ）を比較し、続けてPCF→硬い影→通常の逆順で既定視点のGPU時間を再測定する。高画質のみ、昼夕補間は対象外。`scripts/summarize_sun_pcf.py <report.json> docs/3d-qa/sun-pcf` で差・再現性・見回しの誤差変化・GPU時間を集計。4参照PCFは壁の半影が帯状になるため不採用。通常の全周撮影とは角度が異なり、45°刻み・既定俯仰から±0.45radの操作（入力の上限±0.85rad）を使う。
- 製品化した夕暮れの日光4＋6標本の追加確認は `SUN_SHADOW_PRODUCT=1 bun run test:browser:gpu e2e/sun-shadow.gpu.ts --reporter=json`。製品／変更前（日光も常時16＋24）／製品再撮影を各108視点で比較する。`SUN_SHADOW_QUALITY=standard` で標準画質（省略は高画質）。以前の硬い影・PCF比較とは別条件。`scripts/summarize_sun_product.py <report.json> <out>` が差・再現性・見回し時の誤差変化と **v13-sky** のCycles参照を集計する。`SUN_SHADOW_LIGHTING=night` を付けると夜に、変更前の代わりに月を常に4＋6標本にした `lite` を比べ、Cycles参照は `web-night` になる（記録は `docs/3d-qa/moon-shadow/`、不採用）。影の費用の `shadow-cost.gpu.ts` は `SHADOW_COST_LIGHTINGS=night` で時間帯を変えられる（省略時は昼・夕）。
- `e2e/sun-transition.visual.ts` は標準・高画質の製品／変更前／再撮影を、動作抑制なしで比較する。検証ブラウザ内のrAF時刻だけを固定し、100msずつ進める。製品の `lighting.update`・水の時刻はそのまま使い、撮影中の余分なフレームではdelta=0になる。昼→夕の5.3〜6.2秒と夕→昼の0〜0.3秒を撮影し、`directionalLights[0].color` の実uniform値で閾値の両側を通ったことを検査する。ページ・コンソールエラー0件を要求する。`summarize_sun_product.py` は条件間の時刻・日光値の一致も検査し、再撮影の差と製品−変更前のLab誤差のフレーム間変化を分けて記録する。100ms刻みの制御撮影であり、通常速度の動画・実FPS・知覚的ちらつきの合否ではない。
- `e2e/auto-lighting.visual.ts` は自動の時間帯（入室からの実時間、`lighting.ts` の `timeOfDay`）を確かめる。検証ブラウザ内で `Date.now` だけを指定値に止め（描画ループ・タイマー・rAFは実時間）、0〜45分の8時点の `data-time-of-day` と3ステージ×8方位の撮影、ステージ変更・2D→3D再生成での時刻の維持、手動選択の優先を検査する。記録は `docs/3d-qa/auto-lighting/`。自動の時刻は移り変わり中（12〜15分・27〜30分）に毎フレーム動くので、画素一致を比べるテストは入室直後（昼で静止）か手動の時間帯で撮る。
- 自動照明の実時間の録画は `bun run test:browser:motion --reporter=json > /tmp/sauna-auto-motion.json`（`playwright.motion.config.ts`、`e2e/*.motion.ts`）。標準画質・動作抑制なしで、水風呂の12〜15分と外気浴の27〜30分を各195秒観察する。入室時刻との差へオフセットを一度だけ加えて開始前の保持時間を省くが、以後のDate.now・rAF・タイマーは実時間で進む。50〜70秒・110〜130秒に実際のマウス入力で左右を見回す。時刻の単調増加・到達値・同一canvasの維持・2D復帰・エラーなしを検査し、約1秒ごとの値と入力ハッシュを添付する。録画には `bunx playwright install ffmpeg` が必要。`python3 scripts/summarize_auto_motion.py /tmp/sauna-auto-motion.json docs/3d-qa/auto-motion` で動画の全デコード、入力の一致検査、ローカル動画と抽出フレーム一覧・JSONの保存を行う。録画には追加負荷があり、符号化fpsは描画fpsではない。抽出フレームの確認を連続再生によるちらつきの合格としない。通常回帰・静止画・継続利用検証とは別に実行する。
- `e2e/water-bump-motion.visual.ts` は水底反射の斑（`waterBottom.ts` のバンプ）の動きを見る。検証ブラウザ内でrAFの時刻だけを固定して1/60秒ずつ進め、水風呂の夕暮れ・夜×見下ろし・見出し2で各72フレームを標準画質の無劣化PNGで撮る（撮影用の余分なフレームはdelta 0）。変更前はHEADのworktreeで同じテストを撮り、`python3 scripts/analyze_water_bump_motion.py <変更前> <変更後> --out <記録先>` で比べる。記録は `docs/3d-qa/water-bump-motion/`。描画速度を再現しない制御撮影で、知覚的なちらつきの合否ではない。
- `e2e/water-gloss-capture.visual.ts` は水風呂の夕暮れ・見下ろし・見出し2で、HDR出力の全画面パスをAgXの代わりに線形値×0.5（露出なし）にして撮り（`shaderSource` の書き換えは検証ブラウザ内だけ）、寝椅子灯の `suiWetSpecular` と側面の像を外した `off`、`on` の再撮影と比べる。`on` − `off` がタイル光沢。1変種1ページ読み込み。`python3 scripts/summarize_water_gloss_capture.py` で集計し、記録は `docs/3d-qa/water-gloss-capture/`。書き換える文字列が見つからなければ失敗する。
- フレームの費用の切り分けは `bun run test:browser:gpu e2e/frame-cost.gpu.ts --reporter=json`（`frame-cost.ts` の書き換えは検証ブラウザ内だけ）。標準画質（`FRAME_COST_QUALITY=high` で高画質）・1200×800・DPR1で3ステージ既定視点×昼夕夜のフレーム全体のGPU時間を、製品／画素シェーダを定数にした `trivial`／実行されない `discard` を足した `discard`・1灯ずつ影の参照を外す `noshadow-sun`／`noshadow-spot0`〜`5`（V9・寝椅子灯・通路灯1/4/7・モミジ灯）／`noshadow-all`・PCSSのループ展開を止める `rolled`・円盤の点を回転で求める `rotate`・影マップを16bit深度にする `depth16`・集計しない `warmup`（起動直後の最初のページは2〜4倍遅い）（`FRAME_COST_VARIANTS=a,b` で順を指定、既定は製品・定数・定数・製品）で測り、加算合成を強制した1画素あたりの計算回数を `overdraw` 添付に出す。ANGLE Metalではタイマーを描画先や描画ごとに区切っても各区間がフレーム全体に近い値になるため、区間の内訳は測らない。変更前後は `FRAME_COST_VARIANTS=product` をHEADのworktreeと交互に実行し、`scripts/summarize_frame_cost.py` で集計する。影の変種は製品を3変種ごとに挟み、`--light-costs` で直前・直後の製品との差を取る（費用は光源ごとに足し算にならない）。影のマスク（`shadowMask.ts`）を読む材質では `noshadow-*` がマスクの読み出しを外す（マスクのパスは残る）。画像が変わる変更は `--image-delta <変更前> <変更後>` でCIELABのΔE76（平均・2／5超の割合・中央部・最悪の5枚）を記録する。記録は `docs/3d-qa/depth-prepass/`・`docs/3d-qa/underwater-prepass/`・`docs/3d-qa/light-shadow-cost/`・`docs/3d-qa/shadow-mask/`。画像の前後比較は読み込み間の差（Cycles視点・全周のサウナ／外気浴でも起こる）があるため、各版を2回以上撮って `--image-runs` で判定する。
